## Findings and changes

1. The prelude dock always rendered a second countdown, while opening a teaser detail left its card countdown visible. `use-premiere-clock-owner` now observes source visibility; card/detail/stage own the visible countdown in turn. The dock supplies time when the source is outside the viewport and no matching detail is open. Its exit remains available. Detail-open cards use a non-numeric label. Calendar and detail retain their existing shared countdown presenters/clock.
2. In 40d2e1cb, `enterViewerMode` set viewerMode then asynchronously flushed writes/refreshed the full route/requested a public snapshot. The cold-entry effect independently saw viewerMode and requested another snapshot before the flush. Thus stale-first presentation, duplicate server responses and a full route refresh could overlap a newly started premiere. Entry now claims the cold-request guard synchronously, flushes then requests one sanitized public snapshot, and enables automatic premiere after that request settles. The studio route refresh is deferred until return to editing. PublicPoster stays in the same React position. This removes the identified conflicting paths; genuine authenticated production reproduction remains outside fixture evidence.
3. The release screen put the complete multiline publicTitle into one h2. It now uses the calendar's shared first-line/subtopic parser with bounded indentation metadata. Main heading, lighter subtopics and description have distinct hierarchy. Korean words stay together, long headings use a smaller tier, and outlined mobile stories use the full reading width above internal scrolling. Announcement reads the newly public main heading once.
4. Random order/deadline remain; four restrained depth/lateral departures replace rotations and long throws. A source-card face translates toward the destination heading while the screen arrives at .975→1 scale over 1.1 seconds with monotonic easing. Typography is no longer stretched from the card's height/width ratios to a viewport. The existing shared FLIP implementation is reused.
5. Existing hype intensity/calm plus the shared synchronized clock drive bounded aperiodic numeric position. At T−10…2, ring/ticks, labels and hope controls retreat as digits grow (48% desktop, 65% agenda maximum). Faded controls become inert and focus moves to the visible exit; postponement/release restores them. Waiting-at-zero retains its spinner/status. Reduced motion, gfx decoration limits and existing flash budget remain.

References/adaptation: [Apple fluid interfaces](https://developer.apple.com/videos/play/wwdc2018/803/) for continuity; [Apple motion](https://developer.apple.com/design/human-interface-guidelines/motion) for purposeful low-amplitude motion; [Apple UI typography](https://developer.apple.com/videos/play/wwdc2020/10175/) for hierarchy; [Material transitions](https://m2.material.io/develop/android/theming/motion) for shared-element/depth continuity.
