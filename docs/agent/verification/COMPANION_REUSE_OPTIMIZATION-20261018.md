## OBS 검증 기준

OBS는 브라우저 JS와 별개로 합성·캡처·GPU·인코딩을 사용한다. [OBS 공식 성능 안내](https://obsproject.com/kb/encoding-performance-troubleshooting)도 이 자원 경합을 다룬다. 브라우저 CPU 스로틀은 실제 OBS 송출의 대체 검증이 아니다. 실제 방송 PC 검증은 사용자 요청대로 계속 유보한다.

가능한 개발 환경에서 이후 비교할 프로토콜:

1. 같은 해상도/DPR/월·이벤트 수/브라우저 버전으로 빅타민OFF→ON, 집/음식8개/라디오/도감 각각 분리 기록.
2. 브라우저 단독과 로컬OBS 녹화/합성 동시 실행을 구분. 창 캡처와 OBS 브라우저 소스도 다른 환경으로 취급.
3. OBS통계의 렌더링 지연/인코딩 지연/네트워크 드롭을 분리. 앱 프레임 간격·JS·메모리와 시각을 맞춰 비교.
4. 스크롤·월 전환·집 접기/펴기·편집 팝오버·미리보기 왕복·음식8개·급격한 던지기·라디오 전환을 반복, 30분 후 메모리가 계속 증가하는지 확인.
