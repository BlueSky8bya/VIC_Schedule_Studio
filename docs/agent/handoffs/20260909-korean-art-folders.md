## 고정 증거와 복구

이관 직전 art-src 파일 1,281개와 manifest/codex를 `C:/projects/VIC-art-korean-backup-20260909T055336967Z`에 백업했다. 백업 파일 해시를 대조했다. 새 폴더명 설정을 포함한 이관 파일 1,282개는 이동 직후 전부 기존 해시와 일치했다. 이후 카탈로그·현재 안내·NOTICE만 다시 생성/갱신하며 보호 대상 307개는 원문 바이트를 유지한다.

반려 묶음 README 두 개는 옛 이관 링크를 현재 경로로 연결했다. 각 원문을 같은 폴더의 `원문-README.md`로 바이트 보존하고, 새 receipt의 documentationUpdates에 원본 위치·원본/현재 해시·이유를 추가했다. 기존 plan과 planSha256은 유지했다. 검사는 등록된 README만 허용하고 원문 사본·수정본 해시를 모두 확인한다. request/review JSON, PNG, sidecar를 이 예외로 바꿀 수 없다. 보존 원문의 옛 링크는 역사 증거이며 현재 탐색 링크 검사에서는 제외한다.

기존 request.md/json·review.json·PNG·sidecar·과거 이관 receipt 및 manifest/codex는 수정하지 않는다. 예전 요청서의 경로는 현재 프롬프트 진입점의 납품·입력 링크와 경로 해석기를 사용한다. 새 요청은 한글 회차명과 한글 하위 폴더를 쓴다. 이관된 옛 요청에 --refresh-prepared를 적용하지 않는다.

폴더 이관은 모든 목적지·원본 해시·한글 매핑을 사전 확인한 뒤 깊은 폴더부터 이름을 바꾼다. 중단되면 파일을 지우지 않고 recovery-required와 완료된 이름 변경 목록을 백업 위치의 folder-migration.json에 기록한다. 복구 시 해당 진행 기록의 역순과 백업을 대조하고 현재 파일을 먼저 보호한다. 전체 덮어쓰기나 blind retry는 하지 않는다.

## 연결과 검증

카탈로그·참고 수집/출처 검사·과거 이관 검사·요청/정규화/검토/승격이 한글 경로를 사용한다. 제품의 새 클립보드 프롬프트만 경로를 현행화하며, 고정 원문의 그림 규격과 원문 해시는 바꾸지 않는다. 공개 이미지 URL, 권한·서버 데이터 경계, KST 계산은 이 변경의 대상이 아니다.

최종 검증: 불가사리 통합까지 전체 **786 tests / 69 files**, typecheck, lint, diff check, harness 74문서 통과. 엔티티 193개·생성 문서 966개, art Markdown 976개와 현재 로컬 링크 1,884개 확인. 공개 파일을 포함한 이전 보호 목록 343개 해시, 옛 이관 105+244개 해시, 참고 이미지·출처 103쌍, 고정 입력 4개 및 request·manifest·codex 해시가 일치한다. 현재 영어 하위 폴더는 0개다.

제품 build는 운영 자격증명이 없는 `C:/projects/VIC-work-order-check-20260909`에서 통과했다. app/components/lib/public의 제품 파일 291개와 package/lock/tsconfig가 현재 작업실과 바이트 일치한다. 이후 변경은 로컬 이관 검사·테스트·문서뿐이다. 새 브라우저/기기 검사는 수행하지 않았고, 화면 구조·권한·서버 데이터·KST 계산을 변경하지 않았다.

생성·실제 normalize/promote·소유자 승인·커밋·배포는 수행하지 않았다. 기존 C의 검토 화면과 legacy 분류·후속 커밋 선택은 여전히 별개로 남는다.
