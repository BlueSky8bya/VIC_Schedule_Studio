# A. 규칙 보존을 증명한다 (최우선)

네가 이렇게 말했다 — *"현재 하네스는 크기·링크·상태를 검사하며, 규칙의 의미가 모두 보존됐는지는
증명하지 못합니다."* 그 증명을 만드는 것이 A다.

## A-1. 옛 규칙 → 새 규칙 ID 전수 대응표

- 원본: `docs/agent/archive/20260909-CLAUDE-before-memory-split.md` (589줄).
- 옛 규칙 **한 줄도 빠짐없이** 아래 셋 중 하나로 분류한다.
  - `→ UI-14` 처럼 **새 규칙 ID로 이관**
  - `→ 코드` (수치를 코드가 소유. 파일:심볼을 적는다)
  - `→ 의도적 삭제` (**반드시 이유를 적는다.** 철회된 지시·완료된 이력 등)
- 결과를 `docs/agent/RULE_MIGRATION.md`로 남긴다.
- 이 표가 없으면 "보존됐다"는 말은 검증 불가한 주장이다.

## A-2. 사라진 **측정 계약**을 되살린다

이게 A에서 제일 중요하다. 이 저장소의 문화는 "주장하지 말고 재라"인데,
분할하면서 **재는 조건이 빠지고 서술만 남은** 규칙이 있다.

확인된 사례 하나(우리가 실측했다):

> 옛 `CLAUDE.md`: 눈 편한 테마 — *배경 ON에서 토글하면 달력 영역 픽셀의 **≥ 50%**가 바뀌고
> (파랑 채널 ≈ −8), `<html>`·`.gs-season`·그 캔버스의 computed filter/opacity/blend는 **양쪽이 동일**하다.*
>
> 현재 `UI-05`: 서술만 있고 **숫자가 없다.** `UI_RULES`·`ENGINE_RULES`·`AGENTS.md` 어디에도 "50%"가 없다.

- A-1의 대응표를 만들면서 **숫자·임계값·측정 절차가 있던 규칙을 전부 찾아라.**
- 그것들을 규칙 줄에 되돌린다. 길면 규칙 줄은 짧게 두고 `검수 조건` 항목을 따로 두어도 된다.
- 네가 지적한 것도 같이 처리한다 — **확정 수치와 자유 구현값의 구분.**
  오늘 표식의 크기·페이드, 카메라 상수처럼 **소유자가 확정한 시각 기준**은
  "바꾸려면 소유자 판단이 필요하다"를 규칙에 명시한다.

## A-3. 규칙 줄에 **한글 원어를 병기**한다

- 이유는 실측 증거가 있다: 이 저장소를 아는 에이전트가 `금생수`·`아바타 자리`·`눈 편한`으로
  검색해 **다섯 규칙 모두 못 찾았다.** 소유자는 한글로 피드백하고 한글로 검색한다.
- 찾을 수 없는 규칙은 다시 깨진다. 규칙 본문을 영문으로 두더라도
  **소유자가 쓰는 한글 용어를 같은 줄에** 넣어라(금생수·오행 · 아바타 자리 · 눈 편한 테마 ·
  오늘 · 업 도움 · 차분한 편집실 등).

## A-4. ADR의 철회된 절을 표시한다

- 네가 찾은 것: `ADR-0016` 29번 줄 — *"차분 스위치 하나로 전부 이전 모습"*.
  그 스위치는 2026-09-04에 제거됐고 항상 ON이다. 현재 UI 규칙과 충돌한다.
- **다른 ADR도 전수로 훑어라.** 철회·대체된 절에 표시를 달되 **삭제하지 않는다**
  (Accepted ADR은 조용히 뒤집지 않는다 — supersede 표시).

## A-5. 하네스가 대응표를 지키게 한다

- 새 규칙 ID가 생기거나 사라지면 `RULE_MIGRATION.md`가 낡는다. 검사로 막아라.
- 이 저장소는 낡은 문서로 세 번 다쳤다. 계약 테스트가 유일하게 통한 방법이다.

# D. 커밋을 나눈다 (A 끝난 직후)

네가 제안한 5단위 그대로 간다. 174건 한 덩어리는 되돌릴 수 없다.

1. 원문 보존 · 규칙 분할 · 메모리 하네스 (**A의 결과물 포함**)
2. 아트 요청 · 정규화 · 검토 · 반영 파이프라인 + 테스트
3. 엔티티 카탈로그 · 참고 관리 코드 + 테스트
4. 실제 이미지 · sidecar 이관, 이관 기록, 생성된 카탈로그
5. 최종 진입점 · 하네스 연결 · 현재 상태 정리

조건:
- **먼저 현재 변경 전체를 보관한다**(추적·미추적 모두). 되돌릴 수 있는 상태를 만든 뒤 시작한다.
- 각 커밋이 **자체로 검사를 통과**해야 한다. 하네스가 카탈로그를 import하는 등 의존성이 있으므로
  파일 통째가 아니라 **변경 부분**을 나눈다.
- 커밋 메시지에 **무엇을 검증했고 무엇을 안 했는지** 적는다.
- 푸시는 하지 말고 커밋까지만. 소유자가 보고 결정한다.

# B. 엔티티 폴더 194개를 먼저 만든다

네 추천 그대로다 — *"194개 엔티티의 기본 진입점과 자료 폴더는 먼저 만들고,
세부 변형·계절 폴더는 필요한 만큼."*

- 소유자 목적이 이것이다: **탐색기로 전체 대상을 훑고 참고를 미리 넣는 것.**
  곤충 39종 참고를 모으려면 폴더가 먼저 있어야 한다.
- `목록.md`의 **모든** 엔티티에 링크를 단다. 지금은 "필요할 때 생성"인 것에 링크가 없어
  소유자가 거기로 갈 방법이 없다.
- **범주·전체 일괄 생성 옵션**을 넣는다(`--all`, `--category bug`).
  지금은 여러 ID를 나열할 수는 있으나 일괄 옵션이 없다.
- 변형 × 계절 하위 폴더는 **필요할 때** 만든다(이중 폴더 유지는 네 판단대로 사람 탐색용으로 둔다).

# C. 네가 스스로 짚은 나머지 둘

## C-1. `검토/`를 열면 그림이 보이게

- 지금은 README 링크뿐이다. 소유자가 원한 것은 **열자마자 한 눈에 보는 것**이었다.
- 중복 저장은 피하자는 네 판단에 동의한다. 그러면 `검토/`에
  **대조 시트와 실제 표시 크기 시트를 두는 것**으로 충분한지 판단해 제안해라.
  (심볼릭 링크는 Windows에서 쓰지 마라.)

## C-2. `생성본/`을 승인 흐름에 연결한다

- 네 말: *"승인 후 원본을 `생성본/변형/계절/`에 보관하는 단계는 없다. 완성됐다는 설명은 과장이었다."*
- `promote`가 public에 복사할 때 **원본도 `생성본/`에 보관**되게 연결한다.
- 지금 `생성본/`이 과거 보관소 겸 승격 목적지로 **두 의미**를 갖고 있다. 하나로 정리하고,
  어느 쪽으로 정리했는지 `art-src/AGENTS.md`에 한 줄로 적어라.
