# PLAN-037 — 공개 후 읽기 창

2026-10-14 KST · L2 · 사용자 대개편 및 기존 커밋/푸시/배포 승인 범위.

## 문제와 방향

공개 후 화면은120px 날짜 열+38px 간격, 최대82px 제목,28px 안쪽 카드,68px 장식 헤더와 바깥48px 패딩이 겹친다. 태그/본문이 아래로 밀리고 종일 문구가 별도 줄을 차지한다. 스크롤 존재만으로 첫 화면의 정보 부족을 해결할 수 없다.

- 완료 화면의 V 포즈 keepsake와 반복 외곽 헤더를 제거한다. 대기 중 호스트/응원단/단일 시계는 유지한다.
- 각 공개 일정마다 날짜(item.dateKey/KST)·실제 시각(종일이면 생략)·모든 태그·상세 버튼을 소형 상단 정보줄로 묶는다. 복수 일정에도 귀속을 유지한다. 태그는 우측/상단에 줄바꿈되는 작은 색상 라벨로 배치하고 잘라내거나 +N으로 감추지 않는다.
- 단일 일정의 중첩 카드/큰 날짜 레일을 없애 가로 폭을 내용에 돌려준다. 제목/부제/본문의3단계 위계와 들여쓰기를 유지한다. 긴 제목/많은 부제에는 읽을 수 있는 범위의 조밀한 간격·크기, 짧은 내용에는 적절한 제목 강조를 적용한다.
- 읽기 창의 불필요한 상하 예약 여백을 줄이고 실제 화면 높이를 쓴다. 일반적인 긴 제목+여러 부제+태그 다수를 PC/390px/짧은 가로 첫 화면에서 검사한다. 극단적인 본문과 확대 글자는 내용을 누락하지 않고 기존 화면 한 곳에서 끝까지 읽게 한다. 자동 종료 없음.
- PLAN-033의 완료 후 하단 중앙 종료 배치는 이번 내용 중심 재배치에 맞춰 상단 우측 고정으로 대체한다. 대기→읽기에서 같은 위치를 유지하며, 긴 본문이 덮지 않는 겹침 순서와 버튼 실제 클릭을 검사한다.

## 근거

[NN/g visual hierarchy](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)의 크기·대비·그룹 구분을 이 화면에 적용한다. 과도한 큰 요소와 중복 박스를 줄이고 관련 정보 사이 거리는 좁힌다. [Apple Layout](https://developer.apple.com/design/human-interface-guidelines/layout)의 정렬/들여쓰기/적응형 여백 참고. 이는 사용자 연구를 새로 수행해 몰입/효율을 입증했다는 뜻이 아니다.

## 경계와 변경

공유 `PremiereStage`의 released 분기와 기존 CSS만 개편한다. 상세 동작은 기존 `onRead`, 제목은 기존 `splitEventTitleOutline`, 태그는 기존 resolver/테마 토큰. 재잠금/다음 카운트다운의 영구 `data-pm-retreat`·inert·관측자 유지. 스크롤·포커스 강제 초기화 없음. 공개 DTO/서버/DB/권한/unlock/KST/1840px export 기하 무수정. 토리 미적용 시안·기존 개인 파일 보존.
