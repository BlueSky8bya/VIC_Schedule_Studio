# PLAN-20261017-075 — 함께 지내며 달라지는 빅타민 성향

Status: In Progress
Date: 2026-10-17 (KST)
Scope: L2, 공유 로컬 행동·설정·저장

## 결정

사용자는 실제 상호작용에 따라 성격이 점진적으로 변하길 원한다. 종·수동 성격·걸음은 사용자가 고른 기준으로 보존하고, 별도의 느린 친화성/놀이성/자신감 경험값을 행동 동기에 제한적으로 합성한다. 기존 초 단위 mood·care needs와 구분하며 수동 설정을 자동 변경하지 않는다.

1. 인정된 쓰다듬기, 실제 사용자 음식 섭취 성공, 취소되지 않은 수동 이동 완료, 직접 짧은 탭만 경험으로 인정한다. 자동 착지·휴식·장난·생각·성공/실패는 장기 성향을 자기 강화하지 않는다. 일반 이동은 긍정적 교감이며 벌점이 아니다.
2. 경험은 작은 EMA로 반영한다. 활성 시간에만 보충되는 제한된 경험 credit을 같은 작은 상태에 저장해 반복 입력·새로고침으로 급변하지 않게 한다. 성향 자체의 시간 감소·부재 감점·접속 이력은 없다. 반대 방향 경험으로 회복 가능하다.
3. 친화성은 실제 포인터 접근/관찰·놀이 권유, 놀이성은 활동/놀이 가중치, 자신감은 새 장소 탐색/접근 거리와 관찰 리듬에 반영한다. 각 보정은 bounded하며 종·수동 성격/걸음 차이와 꺼 둔 이동/장난/교감, 배고픔·피로·직접 조작·창/presence·최초공개·감소 동작/gfx가 우선한다.
4. 공유 설정의 기존 빅타민>성격 탭에 기존 switch로 ‘함께 지내며 배우기’(기본ON, 마스터 기본OFF 유지)와 작은 ‘배운 습관 초기화’를 둔다. OFF는 학습·효과만 멈추고 기억을 보존한다. 초기화는 경험만 지우며 care/수동 설정을 보존하고 현재/다른 탭의 stale 복원을 막는다. 집·생각 문구·풍선·새 대시보드는 추가하지 않는다.
5. 기존 care 저장 경로/5초 예산·cleanup flush를 재사용한다. 인정된 경험만 최소18초 활성 credit 예산으로 즉시 flush해 새로고침으로 credit을 재사용하지 못하게 한다. 일반 입력/프레임은 force 저장하지 않는다. schema v1 needs는 읽고 v2의 명시적 needs+숫자 경험 allowlist로 저장한다. 로컬 숫자 외 원본 입력/이벤트/궤적/시간/일정·음식·계정 ID/본문/날짜는 보관·전송하지 않는다. 실패한 저장은 기존 메모리/재시도 제한을 유지한다.
6. 공유 renderer/brain/profile를 두 화면·미리보기·비로그인에서 재사용한다. 모바일 제외/92px/1840 포스터·승인 아트·소파·입·스크롤 기하는 보존한다. 새 타이머·프레임별 학습/경로 탐색·DOM scan·모델/네트워크/DB/의존성은 없다. 공개 DTO·권한·unlock·KST 의미 변경 없음.

초기화 동기화에는 로컬 숫자 `generation` 하나만 둔다. 옛 성향 값의 fingerprint로 차단하는 초안은 ‘초기화 후 같은 경험을 다시 배운 값’까지 거부하는 충돌이 발견되어 폐기했다. generation은 익명 reset 순서이며 날짜·신원·원본 행동 기록이 아니다. 초기화/삭제 뒤 옛 snapshot의 credit이 조금 바뀌어도 복원되지 않게 하고, 새 세대의 같은 교감은 정상 학습한다. 저장 값은 성향3개·credit·이 counter의 명시적5숫자 allowlist다.

## 근거와 한계

- [Blumberg 외, SIGGRAPH2002](https://characters.media.mit.edu/Papers/siggraph2002.pdf), §3.2–3.3/§4: 사람의 유도/보상과 가까운 경험 결과를 연결하는 가상 강아지. VIC의 경험 축/EMA/예산은 제품 적용 추론이다.
- [Gebhard, ALMA2005](https://alma.dfki.de/papers/aamas05.pdf), §3: 짧은 감정·기분·긴 성격 층 구분. 논문 성격은 사전 지정이며 사용자 경험으로 성격을 학습했다는 근거로 인용하지 않는다.
- [Rankin 외, 2009](https://pmc.ncbi.nlm.nih.gov/articles/PMC2754195/): 습관화의 반복 자극/회복 특성. 입력 폭주를 같은 경험으로 반복 강화하지 않는 설계 참고이며 가상 펫의 계수나 UX 효과를 입증하지 않는다.

계수·보정 상한·시간은 프로젝트 디자인 선택이다. 사용자의 성격을 추정하거나 실제 의식·언어 모델·생물학적 뇌를 구현하지 않는다. 실제 OBS/장기 주관적 몰입 승인은 자동 검사와 구분한다.

## 단계와 검증

1. 독립 학습 출처/UX/저장·프레임 예산/연구 조사 완료. 구현은 순수 경험 함수와 기존 store/profile/gesture 경계로 분리한다.
2. 느린 누적·반대 경험 회복·동일 입력 제한·부재 변화0·상한·중립/OFF 동등성·전체 종/성격/걸음·권한 우선, v1 migration/불량값/quota/민감 canary·reset/다른 탭을 단위 검증한다.
3. 생산 빌드 fixture에서 두 화면의 실제 쓰다듬기/딱밤/수동 이동/식사, 설정 OFF/reset/새로고침/왕복 및 자율 동작의 무학습을 확인한다. 모든 mutation 차단·실DB 쓰기0. 소파/스크롤/창/모바일 제외 회귀를 수행한다.
4. 독립 리뷰·type/lint/unit/build·문서 검사 후 기존 승인 범위의 commit/push·운영 SHA/리소스를 확인한다. 완료 결과는 별도 검증 기록에 두고 현재 작업 row를 제거한다. 기존 전체 unit8/harness2 실패는 변경 전 증거와 분리한다.
