## Shared design and boundaries

- One PC implementation across viewer/studio/preview/anonymous. Mobile companion stays excluded; use existing settings tokens, capabilities and reduced/graphics motion gates.
- Explain actual source effects rather than treating the display .35/.65 categories as behavioral thresholds. Preference affects food choice, safety/energy/input gates still apply, and direct home/meal intent remains authoritative.
- Expand13 stable food IDs to36, including vegetables; weighted rarity is local and transparent. First consumption/witness records are separate from learning credit, idempotent, bounded allowlisted enum sets. Never infer historical discoveries from old scores.
- Preserve existing v3 care/13 food memories and seed; initialize new scores safely. Separate versioned local collection memory stores discoveries, one pending gift, up to6 permanent accessories and one explicitly equipped item. Learning reset preserves discoveries/belongings.
- Gifts require real positive interaction, sufficient actual affection and active shared time. No payment/currency/absence punishment, account linkage or new API/DB/model requests. Opening unlocks; equipping is explicit, ownership never disappears with lower affection.
- Use existing scheduler/persistence/decoded-frame adoption for observations and finite gift presentation. No extra permanent timer/RAF, per-frame React/storage or all-pose preload. Accessories reuse offline per-pose registration and transform chain; generated views support front/quarter/side/back instead of an upright pasted picture.
- Art: preserve native outputs, references and provenance in the Korean source run; raster requests use built-in imagegen. Generated/technically checked/user approved are distinct. No user asset replacement, hidden identity or private production notes in commits.
