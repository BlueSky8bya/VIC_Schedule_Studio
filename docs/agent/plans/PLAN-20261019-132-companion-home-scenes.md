## 3. TV·전등·방 상태 제안

하나의 순수 `home-room-state` 투영기를 제안한다. 기존 공유 환경, 실제 집/접지/수면, 사람 입력·행동 소유권을 받아 TV·전등·커튼·임시 셔터를 함께 결정한다. main의 기존 decision/paint/환경 경계에서 거친 상태 변화만 React에 전달한다. 새 interval·per-frame React·상시 DOM 탐색은 추가하지 않는다.

- TV는 무음 기본, 외부 stream/iframe/API 없이 로컬 공개 소재 5채널. 초기 채널을 한 번 고르고, 실제 시청 beat를 마쳤을 때만 관심을 평가한다. 흥미가 있으면 계속 보는 다음 beat, 지루하면 한 번 채널 변경 또는 OFF/다른 생활. 매 frame 추첨하거나 OFF 뒤 자동으로 즉시 다시 켜지 않는다.
- 채널별 선호는 아래 초기 작가 가중치와 실제 완료 시청 경험을 구분한다. 로컬 bounded 기록만 사용하며 음식/장난감 취향·발견 이력과 섞지 않는다. 재미없었다는 한 번의 판정으로 영구 불호를 만들지 않는다.
- 전등은 `auto/on/off` 같은 명시적 모드로 사용자 선택을 우선한다. 자율 외출은 실제 이탈 완료 후 OFF, 밤 귀가는 실제 집 착지 후 ON. 잡힌 중간 프레임·모달·숨김이 귀가/외출 사건이 되지 않는다.
- 당김줄은 실제 44px 이상 손잡이, native pointer capture·최신 입력 flush·키보드 대안을 갖춘다. 그림/줄만 움직이고 측정 표적·발판 자체는 움직이지 않는다. 폼폼이 직접 당긴다면 현재 실제 접점에 닿은 유한 동작의 완료만 ACK한다.
- 집돌이의 낮 암전 TV는 수면과 별개 목적이다. `sleep OFF`를 뒤집지 않고 깨어 있는 TV 취미로 표현한다.
- TV 빛과 전등/창빛은 독립 pointer-free 층. UI 테마나 캘린더·설정 전체를 검게 만들지 않는다. 빠른 점멸·스트로브·무한 TV 동작 루프를 쓰지 않는다.

## 4. 편집실 로컬 16반응 제안

기존 `studio-shell.tsx:7278–7286`는 이미 busy/overlay/월·환경만 전달한다. 추가 bridge도 고정 enum/boolean과 완료 신호만 받는다. 공개 일반 일정의 현 상태는 `companionEditorEventId`와 같은 공개·비떡밥 경계에서 파생하고, 새 일정은 내용 없이 공개 작성 허용 boolean만 전달한다. 제목·본문·태그명·ID·날짜 문자열·임시 draft·비공개 DTO·작업 내용을 읽거나 AI/서버에 전달하지 않는다. 비공개/떡밥 편집은 맥락 반응을 발행하지 않고 busy 억제만 유지한다.

| 실제 로컬 신호 | 반응 목표 | 입력·상태 경계 |
|---|---|---|
| 1. 공개 일반 편집창 열림 | 집에서 고개 돌려 보기 | 편집창을 열어주거나 포커스를 옮기지 않음 |
| 2. 새 공개 작성 시작 | 짧은 꾸벅 | 저장 성공/실제 작성 완료라고 주장하지 않음 |
| 3. 미저장 변경 false→true | 한 번 집중 눈빛 | 값/키 입력마다 반복하지 않음 |
| 4. 입력 종료/필드 blur | 짧은 끄덕임 | 입력·IME 조합 중 재롱 없음, 값 읽기 없음 |
| 5. 태그 창 열림 | 조용한 관심 | 모달 소유권 중 새로운 이동 없음 |
| 6. 태그 수정 완료·창 닫힘 | 작은 만족 몸짓 | 실제 dirty→완료만, 태그 내용/개수 없음 |
| 7. 일정 drag 시작 | 안전한 위치로 양보·정지 | 기존 workspaceBusy가 우선 |
| 8. 일정 drag 실제 반영 | 짧은 응원 | 서버 저장 성공과 로컬 배치 완료를 혼동하지 않음 |
| 9. 기간/span 조정 완료 | 몸을 쭉 펴는 재롱 | 기간/일정 ID를 전달하지 않음 |
| 10. 저장 진행 | 얌전히 기다림 | 저장·버튼·진행 표시를 가리지 않음 |
| 11. 저장 성공 전환 | 짧은 축하 | 같은 묶음 drag/sync 축하와 중복하지 않음 |
| 12. 저장 실패 전환 | 차분히 곁에 있기 | 오류를 희화화하거나 자동 재시도하지 않음 |
| 13. 동기화 시작→완료 | 기다림→꾸벅 | `syncingIds.length>0`만, IDs는 전달하지 않음 |
| 14. undo/redo 실제 완료 | 갸웃 후 안심 | 키를 대신 누르거나 기록을 바꾸지 않음 |
| 15. 월 이동·새 레이아웃 완료 | 이동 방향 바라보기 | 현재 공유 환경/월 경계, 새 시계 없음 |
| 16. 패널 자리 변경 완료 | 현재 앵커 따라 시선 돌리기 | 기존 FLIP/실제 geometry 완료 후만 |

동일 작업에서 가장 최근의 유효한 고정 cue 하나만 유지하는 방향을 권장한다. 숨김·다른 모달·공연·사람 입력 뒤 오래된 응원 전체를 재생하지 않는다. 편집하는 동안에는 일반 이동을 허용하기보다 기존 공개 detail guest 또는 안전한 집의 짧은 pointer-free 표현만 검토한다. viewer/익명/역할 미리보기에는 실제 편집 권한이나 편집 명령을 추가하지 않는다.

## 5. 계절·방문 시간·의외성 12장면 제안

‘성격 조합’은 선택 성격 하나 + 기존 동물 모드/걸음/실제 학습 성향을 뜻한다. 동시에 여러 성격을 저장하는 새 필드나, 관측하지 않은 경험을 추가하지 않는다.

| 장면 | 실제 진입 근거 | 유한 장면 제안/중단 |
|---|---|---|
| 1. 봄 새벽의 탐험가 | viewed-season 봄 + 공유 dawn + 호기심의 실제 귀가 | 창 열기→자연 화면→창밖을 한 번 킁킁. 사용자 입력이면 양보 |
| 2. 한여름 집돌이 극장 | 여름/강한 공유 sunlight + 깨어 있는 집돌이 | 커튼 shade/closed→불 OFF→TV. 수면 이력은 만들지 않음 |
| 3. 가을 비 오는 둥글이 | 가을 + 실제 resolved rain + 균형형 | 창비를 잠깐 보고 잔잔한 화면/소파 휴식, 억지 외출 없음 |
| 4. 겨울밤의 잠꾸러기 | 겨울 night + 실제 졸음/수면 허용 | 달별 화면→TV·불 OFF→집 착지 확인 후 셔터 |
| 5. 익숙한 저녁 귀가 | 실제 완료 귀가가 같은 coarse KST band에 반복 관측됨 | 다음 저녁 실제 귀가 때 전등 ON·소파 환영, 부재 시간 빚 없음 |
| 6. 아침을 즐기는 먹보 | 실제 아침 귀가 반복 + 선택 먹보 | 짧은 요리 화면. 음식은 실제 배출/섭취 경로가 별도 증명되어야 함 |
| 7. 평소보다 이른 방문 | 학습된 band와 다른 실제 visible encounter | 한 번 반가운 bow, ‘오래 기다렸다’는 허구 시간 표현 없음 |
| 8. 늦은 시간의 애교 | night의 실제 교감/귀가 | 조용히 불을 켜고 기대기. 사용자 음소거를 뒤집지 않음 |
| 9. 호기심 고양이의 달별 | curious + cat + 실제 시청 완료 | 별 화면에 귀/시선 반응→다른 채널 한 번, 점프 OFF면 제자리 표현 |
| 10. 깔끔하지만 흥이 많은 날 | tidy + 실제 학습 play 성향 + 마지막 물건 실제 반납 ACK | 음악 채널에 짧은 bow. 정리 ACK 전에는 축하하지 않음 |
| 11. 사고뭉치의 조용한 반전 | mischievous + 낮은 현재 에너지 + 실제 귀가 | 채널을 한 번 넘기려다 달별 화면에 머물기. 강제 난동/점멸 없음 |
| 12. 처음 겪은 수줍음 | 실제 난처한 사건 + 임시 shy 상태 + 집 경로 증명 | 집으로 돌아가 가리기→사용자 교감으로 다시 열기. 선택 성격 자체는 바꾸지 않음 |

방문 시간 학습은 새 위치 추적이나 접속 분석이 아니다. 구현한다면 기존 실제 encounter/귀가 완료에서 공유 KST band의 소수 카운터만 로컬로 누적하는 제안이다. 같은 진입 중복은 억제하고 카운터는 포화·감쇠·리셋 가능해야 한다. 정확한 시각, 출석 일지, 계정/별명, 세션 식별자, 일정 내용은 저장하지 않는다. `learnFromYou OFF`에는 학습 읽기/쓰기·감쇠를 멈추고 기본 성격만 사용한다. away/hidden 시간의 경험·catch-up은 0이다.

의외성은 기존 결정 경계에서만 한 번 선택하고, 한 개의 끝나지 않은 장면과 bounded cooldown으로 제한한다. idle/look를 반복해 의미 예산을 채운 척하지 않는다. 의미 없는 긴 대기를 줄이는 것은 제안 목표이며 **모든 상황에서 10초 이내 의미 행동이 지속된다는 보장은 하지 않는다**. 실제 입력·식사·운반·경로 실패·quiet/숨김은 계속 우선한다.

## 6. 배치·몸·조작과 자동 셔터의 필수 조건

1. **기존 방에 단순 덧붙이지 않기.** 기본 CSS의 상자 뒷줄과 앞줄 쓰레기통 사이 세로 틈은 약 6px 수준이다. 샤워 패드를 그 틈에 실제 44px 제어/92px 몸 받침으로 끼울 수 있다고 주장하지 않는다. TV를 소파 오른쪽 바닥 버튼으로 추가하면 `geometry.ts:336–404`가 body-safe 구간을 더 잘라 음식/상자 접근도 손상시킬 수 있다.
2. 기본 200px 방, 기존 소파 디자인/실제120px 최소·150px 상한, 창 가시성, 현재 상자/음식 출구·쓰레기통 접점을 기준으로 우측 수납과 샤워 bay를 함께 재배치한다. 새 그림 크기만 정하고 나중에 모델 거리 한계를 넓히는 방식은 사용하지 않는다. ≤250px의 기존226px 예외를 새 무조건 높이 증가 근거로 삼지 않는다.
3. 새 조작은 실제 화면44px 이상, 상호 hit 비중첩·포커스·중앙/edge 접근을 검증한다. 기존 `--vc-object-min-hit`와 shell-zoom 보정을 공용한다. TV/전등 그림은 pointer-free, 조작 표적은 별도 고정 DOM. 모든 house button을 geometry에서 무차별 제외해 경로를 꾸미지 않는다.
4. 샤워는 실제 보이는 패드와 기존92px 몸의 안전 중심 구간·입출구 경로가 필요하다. 칫솔은 도구로 움직이고 팔은 만들지 않는다. 겉보기 바닥/물/거품은 자동 발판이 아니며, 실제 씻기 완료만 학습/발견 후보가 된다. 음식/장난감 44px 표적을 덮거나 클릭을 가로채지 않는다.
5. 자동 숨기기는 `요청→실제 귀가/접지→운반/낙하/사람 입력 종료→유한 셔터→가림` handshake다. 물건이 carried/held인 중간, 잠드는 척하는 표정만으로 집을 접지 않는다. `jump OFF`에는 걸어서 가능한 귀가만 쓰며 불가하면 안전한 제자리 가림/대기를 검토한다.
6. 사용자 저장 expanded와 자동 privacy owner를 분리한다. 자동 셔터는 `vic.panelSections`의 사용자 선택을 덮지 않는다. 사람이 열기/잡기/모달을 시작하면 자동 요청을 취소하고, 다시 열 때 실제 집 앵커를 재실측한 뒤 주민/물건을 재개한다.
7. 셔터 동안 집안 음식/장난감의 ID·분수 앵커·완료 경험을 보존하고 body/small tier를 같은 소스 프레임으로 freeze한다. 현재 toy의 source 소실 release를 자동 접기와 혼동하지 않도록 가시성 가림과 실제 집 삭제를 구분해야 한다. 물건 삭제·바깥 낙하·발판 순간이동으로 숨기지 않는다.

## 7. 입력·성능·보안·G22와 검증 계획

- 우선권: 기존 사람 직접 입력/소유 작업, 실제 식사·운반·공연·편집/저장 경계를 보존한다. 새 TV 시청·줄 당김·샤워는 이 소유권을 취소하거나 성격 예산만 먼저 리셋하지 않는다. 사람이 직접 OFF한 TV/전등을 즉시 자율 ON으로 되돌리지 않는다.
- `enabled OFF`·모바일 제외 유지. `roam OFF`에는 새 자율 이동/당김/시청 행동을 시작하지 않지만 직접 허용된 가구 조작은 즉시 피드백한다. `sleep OFF`에는 TV 취미와 수면을 분리한다.
- `activeWhileVisible`과 실제 가시성 정책 공용. 보이는 다른 창 작업 중 활동은 허용 정책 안에서만, hidden·모달·차단에서는 정지한다. 복귀 시 밀린 방송·응원·학습을 재생하지 않는다. 실제 OBS 하드웨어 검증은 별도이며 source-only 검토로 보장하지 않는다.
- reduced/OFF/soft는 정적 상태/밝기 피드백, 필요 시 즉시 상태 전환. 물리 표적은 hover/press로 움직이지 않는다. 오디오 master·기존 mix/미디어 활성화 정책을 보존하며 두 기기가 동시에 소리를 경쟁하지 않게 한다. TV가 외부 미디어·새 자동재생 우회가 되지 않는다.
- 기존 KST/solar band·viewed-month 계절·공유 날씨만 읽는다. 새 시간대 표, 고정 UTC 시각, 새 interval, 전역 observer, 상시 DOM scan, per-frame React, 백그라운드 catch-up을 추가하지 않는다. 필요한 source rect는 기존 유한 geometry read/compute/write batch에 통합한다.
- 서버/API/DB/권한·공개 DTO·teaser/private gate 변경 없음. 역할은 owner/developer/viewer 그대로. 새 context는 고정 enum/boolean whitelist, 디바이스 로컬이며 일정·태그·ID·사용자 정체성·정밀 방문 기록을 읽거나 AI에 전달하지 않는다. 역할 미리보기는 실제 권한을 만들지 않는다.
- G22는 직접 새 제어만 고정 의미 타깃으로 처리한다: 예 `companion-tv-power#on/off`, `companion-tv-channel#next`, `companion-lamp#on/off`, `companion-wash#start/cancel`, `companion-work-react#on/off`. 실제 채택 시 명칭/동일 키보드·포인터/단일 capture/writer→timeline→least-used 표시를 함께 검사한다. 이는 제안 타깃이며 현재 등록되었다는 뜻이 아니다.
- 자율 TV/전등/커튼/귀가/셔터/응원·채널 취향·방문 band·학습값은 사람 활동으로 기록하지 않는다. food/toy/song/channel ID·발견·개인 취향·작업내용을 analytics payload에 추가하지 않는다. 기존 analytics fixture guard 유지.

향후 구현 전에는 방의 실제 배치와 소재 등록부터 동결한다. 그 후 순수 room-state/성격9종/동시 소유권/시간대·학습OFF·리셋·away0 단위, 실제 renderer·food/toy source/귀가/접힘 lifecycle 회귀, G22 capture-through-display, type/lint/full units/build/harness, 생산 빌드의 viewer/studio/preview·compact·.9/.8 shell-zoom 실물 검증을 수행한다. 현재는 이 새 제품 검사·새 행동·미술/사용자 승인·지속시간 보장이 미실행/미확정이다. 문서·출처 검사 결과는 아래와 별개다.
