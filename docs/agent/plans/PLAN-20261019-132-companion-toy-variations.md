2026-10-19 KST. 상태: 소스·현재 소품 그림 조사와 제안. **이 보충 조사에서는 런타임 구현·설정 변경·이미지 생성0.** 132의 별도 이미지6시안과 이 문서의 놀이 제안을 구분한다. [성격·생활 조사](PLAN-20261019-132-companion-personality-life.md), [집 생활·TV 시안 조사](PLAN-20261019-132-companion-home-scenes.md)의 보충 자료다. 둥글이는 신규 균형 성격의 추천 이름이며 현재 enum에는 없다.

## 1. 현재와 제안의 경계

현재 카탈로그에는 실제 24종이 있고 종류별 표시 상자 크기가 다르다. 아래 크기는 **현재 `COMPANION_TOY_VISUALS`의 CSS 그림 상자**이며 불투명 그림 자체의 실측 크기와 다르다. 실제 입력 영역은 공통 44px이고 동시 실물 한도는 4개다. [카탈로그·크기](../../../lib/ui/viewer-companion/toy-catalog.ts), [장난감 모델](../../../lib/ui/viewer-companion/toys.ts#L12).

현재 렌더러는 장난감별 한 이미지와 위치·각도·상태를 사용한다. 집기·운반·놓기·투척·중력·실제 상자 도착은 공통 모델이며, **24종에 각기 다른 전용 놀이 물리가 전부 구현된 상태가 아니다.** 요요 줄 제약, 바람개비 회전축, 팽이 회전 접촉, 자동차·기차 바퀴 회전, 블록·고리의 개별 쌓기, 주사위의 변화하는 면 결과는 그림에 자동으로 따라오는 기능이 아니다. [모델과 효과](../../../lib/ui/viewer-companion/toys.ts), [실제 그림·운반 처리](../../../components/poster/viewer-companion/companion-toys.tsx).

조사 중 125의 24종 비교표로 소품의 구성을 실제 열람했다. 그 시트의 옛 크기 표기를 현재 크기로 사용하지 않고 현재 카탈로그를 기준으로 아래 표를 작성했다. 이는 소품 구성 확인이며 전문 미술 승인이나 새 동작의 자연스러움 인증은 아니다.

- **A — 통째 그림 활용:** 새 그림 없이 현재 소품 전체의 위치·회전·짧은 기울임으로 시작할 수 있는 제안. 전용 접촉점·물리·순서·소리 코드는 새로 필요할 수 있다. 현재 구현 완료라는 뜻이 아니다.
- **B — 부품·새 그림 필요:** 통째 그림으로 가벼운 관찰·운반은 가능하지만, 제안한 본격 조작에는 부품 분리·다른 각도·연속 키 같은 추가 소재가 필요하다. 단일 이미지를 억지로 회전·늘려 해당 기능으로 위장하지 않는다.

## 3. 기존 자원을 연결하는 기억에 남는 추천 12개

모두 **추가 제안**이다. TV를 포함하는 항목은 132의 TV 시안·후속 코드가 있어야 하며 현재 TV 기능으로 표현하지 않는다. 새 반사 그림·채널별 빅타민 그림을 대량 생성하는 방향은 제외했다.

1. **화면에서 본 공을 실물로 찾기.** 제안 TV의 장난감 채널에서 공을 본 뒤 → 현재 화면에 실제 공이 있으면 찾아 한 번 굴려 본다 → 다시 TV 쪽을 보고 공을 회수한다. 공이 없으면 상자를 한 번 살필 뿐 강제 추첨·미발견 해금은 하지 않는다.
2. **요리 방송 뒤 밥통 앞 기대.** 제안 요리 채널의 한 시청 구간을 마치면 → 먹보가 실제 밥통 가까이 가 잠깐 기대한다 → 사용자가 음식을 꺼내면 실제 음식에 반응하고, 아니면 기다림을 끝낸다. TV를 봤다는 이유로 음식 생성·섭취·도감을 성공 처리하지 않는다.
3. **쓰다듬기로 받는 앙코르.** 실제 공연 완료 뒤 사용자가 쓰다듬으면 → 재롱둥이가 다른 짧은 장면을 한 번 더 보여 준다 → 인사 후 멈춘다. 앙코르 자체가 또 사람 교감 보상이나 무한 학습 신호가 되지 않는다.
4. **오리 인형을 관객으로 삼기.** 실제 오리 인형과 빈자리가 있으면 → 재롱둥이가 오리를 놓고 앞에서 인사 연습을 한다 → 공연을 마치고 그 오리를 실제 상자에 돌려놓는다. 인형의 새 표정·대사 그림 없이 방향과 대상만으로 맥락을 만든다.
5. **도감에서 본 장난감과 실제 물건 연결.** 사용자가 이미 발견한 장난감 항목을 열고 닫으면 → 현재 화면에 같은 종류의 실물이 있을 때만 그것을 살핀다 → 한 번 놀거나 실제 상자에 넣고 끝낸다. 현재 신호는 행동·상황 회상 중심이므로 장난감 연결은 새 bounded 신호 코드가 필요하다. 미발견 미리보기·가짜 놀이 경험은 만들지 않는다.
6. **공연을 위해 자기 무대 만들기.** 재롱둥이가 놀려는 실제 안전한 자리에 물건 하나가 있으면 → 그 물건을 상자나 실제 집 보관점으로 먼저 옮긴다 → 빈자리에서 짧은 공연을 한다. 깔끔이처럼 방 전체를 치우는 성격과 ‘공연할 자리만 확보’하는 목적을 구별한다.
7. **사용자가 마지막으로 골라 준 장난감.** 사용자가 실제 장난감을 잡았다 놓으면 → 애교쟁이나 둥글이가 그 물건을 다음 놀이 후보로 한 번 우선 고려한다 → 실제 놀이 후 상자에 돌려놓는다. 사용자 손에서 빼앗지 않고, 새 설정 버튼·서버 입력 기록 없이 현재 세션의 제한된 실제 대상만 사용한다.
8. **편집하는 동안 조용히 기다린 뒤 이어 하기.** 사용자가 일정 편집·드래그를 시작하면 → 진행 중 물리 동작을 안전하게 끝내고 작업 소유권에 양보한다 → 편집이 끝난 뒤 같은 실물이 아직 있고 경로가 유효하면 중단한 놀이·정리를 잇는다. 작성 중 제목·본문은 읽지 않는다.
9. **자기가 튕긴 장난감 되찾기.** 실제로 튕긴 장난감이 쓰레기통 옆 같은 엉뚱한 곳에 멈추면 → 사고뭉치가 돌아보고 같은 ID의 실물을 찾는다 → 실제 상자까지 데려오며 사건을 끝낸다. 새 복제본·자동 삭제·순간 회수로 대신하지 않는다.
10. **깃털에 간지러워 몸 털기.** 실제 놀이 중 깃털이 현재 얼굴 가까운 영역을 스치면 → 기존 몸 털기·고개 반응을 한 번 연결한다 → 깃털의 실제 위치를 다시 확인해 회수한다. 접촉하지 않았는데 반응·도장을 주지 않고 새 재채기 그림을 필수로 요구하지 않는다.
11. **넘어진 물건에는 다음번에 조심하기.** 실제로 특정 장난감에 걸려 구른 기록이 있을 때 → 다음 가까운 접근에서 짧게 살피거나 유효한 여유 구간을 고른다 → 놀이·정리를 실제로 마치면 경계를 완화한다. 한 번의 사고를 영구 불호로 만들지 않고 학습 OFF면 이 기억을 쌓지 않는다.
12. **다시 생긴 믿음을 작은 놀이로 확인하기.** 거친 경험 뒤 실제 안심 교감이 쌓이면 → 애교쟁이가 안전한 간격에서 익숙한 장난감으로 짧은 놀이를 먼저 제안한다 → 사용자가 응하면 교감하고, 바쁘면 장난감을 실제 상자에 넣고 물러난다. 자동 행동을 사람이 쓰다듬은 경험으로 기록하지 않는다.

## 4. 공통 수용 기준과 비구현 범위

- 10초 반응 기준은 후보 생성이 아니라 **실제 보이는 성격다운 행동의 시작·표시**로 관측한다. 낙하·착지·실제 운반·식사·사용자 입력 소유권을 끊어 시간을 맞추지 않는다. 첫 0–3초와 8초 예산의 안전 예외는 [성격 보고서](PLAN-20261019-132-companion-personality-life.md)의 공통 계약을 따른다.
- 보이는 화면에서 `activeWhileVisible`을 켠 경우 blur만으로 잠들거나 멈추지 않는 계약을 유지한다. 실제 hidden·모달·편집 소유권·명시 OFF는 각각 존중한다. [가시성 계약](../../../lib/ui/viewer-companion/presence.ts#L5).
- 장난감 개별 연출은 같은 유한 시계·실제 접촉·44px 입력 영역·음식 8개와 장난감 4개 한도·안전한 발판을 공유한다. 떨어진 물건을 화면 밖에서 자동 삭제하지 않는다.
- 음식은 실제 먹기 또는 실제 집 보관·현재 배부름에 맞는 실제 쓰레기통 운반으로 끝낸다. 장난감 정리 완료는 실제 상자 도착으로만 인정한다. 일반 놀이와 정리 성공을 섞지 않는다.
- 사용자가 물건을 잡거나 명시 귀가·편집을 시작하면 양보한다. 수면·식사·음향·학습 OFF, 선택한 속도·동물 습관, 정확한 역할 권한과 KST 규칙을 장난감 성격이 바꾸지 않는다.
- 새 발견·맛·놀이 경험은 실제 관찰·효과·식사 증거를 확인한다. 자동 장면·장난감 ID·취향을 사람의 활동 타임라인/최소 사용 기능 메타데이터로 보내지 않는다. 새 수동 조작을 만들 때만 기존 G-22 계약을 감사한다.
- 이번 변경은 이 신규 문서 하나다. 제품·테스트·자산·다른 보고서는 수정하지 않는다. 표의 24종과 추천 12개, 상대 링크는 문서 검사 대상으로 두며 최종 harness·링크 검사는 루트가 수행한다. native·구현·OBS 성능 PASS를 주장하지 않는다.
