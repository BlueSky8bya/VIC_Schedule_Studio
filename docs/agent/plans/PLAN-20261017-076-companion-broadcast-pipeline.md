# PLAN-20261017-076 — 방송 병행 빅타민 표시 파이프라인

Status: In Progress
Date: 2026-10-17 (KST)
Scope: L2, 공유 클라이언트 표시·프레임 예산·기본 설정

## 소유자 결정

OBS 송출과 함께 실행할 때 가능한 끊김 원인을 줄이고 다음 배포부터 빅타민 기본값을 ON으로 바꾼다. 이후 ON/OFF는 사용자 선택이다. 이전 계획의 기본OFF 조항만 대체하며 모바일 제외·92px·감소 동작/gfx·직접 조작·창/최초공개 우선순위는 보존한다. 설정이 없는 브라우저는 ON, 유효하게 저장된 ON/OFF는 그대로 읽는다. 초기 렌더가 저장된 OFF를 읽기 전에 펫/이미지를 잠깐 불러오는 경로도 막는다. 전역 설정 epoch나 다른 사용자 취향을 초기화하지 않는다.

## 구현 범위

1.075에서 재현한 Image decode→별도 CSS 배경 요청/첫 paint 간격을 실제 decode한 이미지의 단일 표시 경로로 제거한다. 등록·clip wrapper/전체 몸체·입/소파 좌표는 유지한다. 준비 전에는 현재 이미지를 유지하며 임의 대기나 검사 완화로 숨기지 않는다. decoded cache/동시 작업·표시 이미지 소유권을 제한한다.
2. 공유 runtime의 중복 프레임 작업·기하 조회·포인터 입력·저장/React 갱신을 조사한다. 계측/코드 근거가 있는 경로만 수정한다. 해상도·행동 다양성·보행/스크롤 cadence를 낮춰 성능을 주장하지 않는다. 포스터1840 기하는 고정한다.
3. 보이는 비활성 창에서는 현재 행동을 마친 뒤 쉬기→하품→CSS 수면으로 연결하며 자율 JS/needs/geometry는 멈춘다. 실제 DOM/직접 입력·집/창 기하 갱신에 필요한 유한 작업은 구분한다. 숨긴 탭 복귀에 catch-up/워프를 만들지 않는다.
4. 시청자·비로그인·미리보기·편집실은 하나의 구현을 쓴다. 공개 DTO/서버 권한/unlock/KST/실제 일정·하트/학습 데이터 경계 변경은 없다. DB/외부 AI/새 의존성·아트 생성은 추가하지 않는다.
5. 회귀에서 확인된 실제 viewport 축소 복구 결함도 수정한다. 가로 또는 세로 크기가 바뀌어 예전 수직 발판선이 새 화면 밖이 되면 기존 geometry callback에서 가까운 안전 발판으로 복구한다. 일반 스크롤·직접 놓기는 기존 수직 낙하 의미를 유지한다. 오래된 창 강제 이동/클릭 쓰다듬기/편집실 접힘 제외/20행 sprite 검사만 최신 승인과 실제32행에 맞춰 정정하고 최초 실패는 보존한다.

## 검증과 출하

- 순수 sprite cache/소유권/실패·설정 기본ON/명시OFF 보존 검사. 실제 생산 fixture에서 cold/지연 packet 중 현재 몸체 지속, 실제 픽셀·요청 수, 두 화면 스크롤/긴 frame/소파/드래그/창/수면·복귀, 모바일 제외, 학습 회귀를 확인한다. 소스만 확인한 것을 OBS 실기기로 측정했다고 부르지 않는다.
- 독립 코드/성능 검토 후 typecheck/lint/unit/build·문서/harness. 과거 fixture만 사용하고 쓰기 mutation을 차단한다. 기존 전체 unit8/harness2 실패는 변경 전 증거와 구분한다.
- 현재 승인 범위에서 commit/push, 운영 SHA/공개 응답/검증 리소스 확인. 결과는 별도 검증 기록에 남기고 완료 row를 제거한다.

## 근거와 위험
