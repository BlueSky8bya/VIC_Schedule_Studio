# PLAN-20261014-027 — 최초공개 프리미어 무대 (확정안)

Status: **Accepted** (2026-10-14 소유자: "정해 주면 따른다") · 구현 전 · Task Risk: **L2**
대체: [PLAN-025 클로드안](PLAN-20261014-025-teaser-premiere-stage.md), [PLAN-026 코덱스안](PLAN-20261014-026-teaser-premiere-codex.md) — 둘은 근거 자료로만 남는다.
결합 원칙: **연출 = 025, 상태·동기화·실패 복구·검증 = 026.** 026의 KV·registry는 M0 실측이 요구할 때만.

## 0. 한 줄

공개 180초 전부터 화면 크롬이 하나씩 퇴장하고, 90초에 일정이 지각변동으로 빠지고, 70초에 떡밥이 영화관 스크린으로 떠오른다. 60초부터 계절 태풍이 몰아치다 10초에 태풍의 눈처럼 멎고, 0초에 빅뱅. 서버가 공개를 확인한 내용이 스크린에서 해독되고, 스크린이 제 날짜 칸으로 착지하며 달력이 다시 조립된다. 모든 시청자 탭이 **하나의 상태 경로 + 서버 보정 시계 + 지휘자 하나**로 움직인다.

## 2. 타임라인 (T = 서버 확인 공개 시각, r = T − 보정 시각)

단계는 타이머 사슬이 아니라 매 틱 `planPremiere(state, now)`로 **다시 도출**한다. 변경·복귀 때 지난 안무를 몰아 재생하지 않는다.

| r | 단계 | 화면 |
|---|---|---|
| >180 | idle | 지금과 같음 |
| 180→150 | prelude-1 | 위에 띠 "🔮 곧 최초공개 · 일정표 보기". 데뷔 박스가 보라 별 하나를 스크린 자리로 던지고 풍선처럼 떠나감 |
| 150→120 | prelude-2 | 태그 필터 칩이 카드 패처럼 날아감(모바일은 범례 줄 통째) |
| 120→90 | prelude-3 | 머리줄 접힘, 하단 버튼 비눗방울처럼 톡톡, 사이드 패널 미끄러짐, 계절 배경 dim→정지→퇴장. **일정은 아직 읽을 수 있음** |
| 90→70 | quake | 다른 일정 퇴장: PC는 떡밥 칸부터 거리순으로 칸이 흔들리다 떨어짐, 모바일은 떡밥 줄 기준 위아래로 갈라짐. 비네트 어둠 0→0.8 |
| 70→60 | screen | 떡밥 카드(또는 열린 팝오버)가 FLIP으로 중앙 스크린. 기존 `hypeEmerge`(66→58)로 시계→링 연결 |
| 60→11.8 | build | 기존 `hypeIntensity`로 **계절 태풍**: 꽃잎·물방울·낙엽·눈이 스크린 둘레를 소용돌이, 점점 빠르고 많아짐. 테두리 금 맥박 |
| 11.8→0 | eye | 기존 `hypeCalm`: 입자가 공중에서 멈춘 뒤 가라앉음, 조명 꺼짐, 숫자 + 초마다 메아리 파문 + 심장박동 |

## 3. 다중·연쇄 (D8·D9·D16)

- 무리(같은 ms) = 스크린 묶음, 카운트다운 하나, 빅뱅 하나. 일부만 `released`면 도착한 것부터 해독, 나머지는 `???` 유지.
- 연쇄(≤15초): 한 무대. 각 스크린에 자기 카운트 칩, 큰 숫자는 다음 T. 먼저 공개된 스크린은 줄어 **필름 띠**에 꽂히고 다음이 가운데로. 빅뱅 간격 <1.5초면 효과 합침. eye 단계는 첫 T−10부터 마지막 T까지 유지.
- 90초 상한에 걸리면: 남은 연쇄는 카드 + 띠로 계속 공개(데이터는 절대 지연 안 함), 무대는 귀환.
- 끝난 연쇄가 2개 이상이면 귀환 직전 필름 띠 2초 "오늘 공개된 일정".

## 4. 상태 경로·시계

### 4.1 `/api/public/[calendarSlug]/teaser-state` (GET, 익명 동일, 고정 캐시 키)

- 질의: 공개 뷰에서 `hidden` 이거나 `teaser_reveal_at ≥ now() − 24h` 인 행. 쿼리 하나, DB `now()`를 같은 문장에서 `sampledAtDbMs`로 반환.
- 응답: `{schemaVersion, sampledAtDbMs, entries: [{id, dateKey, revealAt, state, event?}]}` — `event`는 `released`일 때만, 기존 `PublicScheduleEvent` **명시 필드 생성**(스프레드 금지). `masked`는 지금 stub과 같은 필드만.
- `gone` 판정: 클라이언트가 알던 id가 **성공 응답**에 없으면 gone. 오류·타임아웃은 모름(기존 `reconcileTeaserReveal` 계약 유지). `sampledAtDbMs`가 이전보다 작은 응답은 버림.
- 헤더: 가장 가까운 떡밥이 5분 이내면 `s-maxage=1`, 아니면 `s-maxage=15`, `max-age=0`. 다음 T를 넘어 캐시되지 않도록 TTL을 `T − sampled`로 자름.
- import는 `public-loader`만(경계 규칙). 쓰기 액션의 revalidate 3줄에 이 경로 포함.
- D3 저장 변경: [event-actions.ts:230](../../../lib/schedules/event-actions.ts) 떡밥 해제 시 `teaser_reveal_at = now()` 보존. 이 열을 읽는 곳(편집실 UI·검색·활동 로그) 감사 후 반영.

### 4.2 `/api/public/clock` (GET, no-store, DB 없음)

`{serverMs}`만. 진입·180초·70초·탭 복귀 때 3표본. 오프셋 변화 ±250ms 이내는 1초에 걸쳐 따라가고, 그 이상은 즉시 재도출 + 해당 무대 축하권 무효.

### 4.3 지휘자 `useTeaserPremiere`

- 하나만 존재. 상태 경로 폴링, 시계, 단계, 공개 저장소(`revealedEvents`) 반영, 관람·효과권, 정리를 소유. 카드·팝오버·스크린은 구독자.
- 기존 카드별 100ms 루프·2초 재시도·`revealTeaserAction` 시청자 호출·mount-sync는 지휘자로 흡수(`revealTeaserAction`은 편집실 경로 필요 시만 유지).
- 관람 기록 = `(id, revealAt)` 단위, **화면에 실제 보였고 탭이 visible인 채 T를 통과**했을 때만 빅뱅.
- 숨김 탭: 폴링·루프 정지, 복귀 시 시계 → 상태 → 단계 순 재동기화.

## 5. 접근성·안전 (D12·D14)

- 퇴장 영역: 퇴장 시작과 함께 `inert` + `aria-hidden`, 귀환 완료 시 해제. 포커스가 퇴장 영역 안이면 "일정표 보기"로 옮김, 종료 시 원래 요소(없으면 달 제목)로 복원.
- 집중 단계만 모달 포커스 범위, prelude는 포커스 가두지 않음. 뒤로 가기는 기존 `pushInnerOverlay` 순서.
- `aria-live=polite`: 진입·60초·10초·공개(완성 제목 1회)·변경. 매초 낭독 없음, 난수 글자 `aria-hidden`.
- 효과 예산기: 고휘도 출처(카드 링, 팝오버 맥박, 스크린 테두리, 빅뱅)는 `requestFlash()`로만 발화, 슬라이딩 1초 창 최대 2회. 무대 중 카드·팝오버 자체 맥박은 꺼짐.
- 대비: 합성 배경 위 실측 4.5:1(본문)/3:1(큰 글자·조작). 안전 버튼 ≥44px. 200% 확대·긴 제목·가로 넘침 0.
- gfx: full 입자 120 / lite 40 / soft·off 0(정적 스크린 + 페이드). 모바일은 앰비언트 캔버스 새로 만들지 않음, 무대 입자는 별도 경량 캔버스 1장(gfx 따름).
- 원칙: 전역 filter 금지, transform/opacity만, 단계는 `html[data-premiere]` + `--pm-*` 변수, 표면 `[data-export-surface]` 기하 불변(스크린은 표면 밖 포털, 클론 대신 공용 presenter로 렌더).

## 8. 남은 위험

- 마지막 1~3초 안의 시각 변경은 모든 탭에서 효과까지 동시 취소를 보장하지 못한다(최대 약 3초+왕복). 내용 공개는 항상 DB 판정이라 잘못 공개되지는 않는다.
- 이미 공개된 내용을 다시 떡밥으로 돌려도 받은 사람에게서 회수할 수는 없다.
- M0가 실패하면 공유 KV(외부 서비스·비용)가 필요하다 — 그때 소유자에게 비용만 확인.
