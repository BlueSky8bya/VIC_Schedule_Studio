# 빅타민의 상황별 연속 행동

Status: In Progress.

소유자: 만들어 둔 동작을 적절한 상황에서 쓰고, 음식 발견→반가운 접근→관성/착지 실수→구름→회복처럼 인과가 이어지는 하나의 행동으로 다양화한다.092의 일반 탐색 사고는 유지하되, 먹이 경로의 사고 제외만 명시적인 유한 식사 장면에 한해 대체한다. 실제 음식/일정 데이터나 사용자 설정은 연출이 바꾸지 않는다.

- 재고:32논리행/496물리 그림과 실제 소비처를 대응한다. 활성31행과 의도된 legacy7/기존 rig·hold 제외를 구분하고, 폐기한 품질 낮은 그림을 노출률 때문에 되살리지 않는다. 새 원화·모델/서버 호출은 필요하지 않다.
- 장면: 식사 의도에 음식ID·선택한 접근 변형·현재 단계·남은 예산·실수 사용 여부만 기억한다. 발견/반가움→실제 달리기 또는 증명한 도약→선택적 실제 음식 접촉/착지 실수→유한 구르기/회복→같은 음식 재접근/기존 식사→종별 마무리를 잇는다. 각 다음 단계는 현재 음식/지지면/권한으로 다시 계산하며 절대좌표 action 배열을 저장하지 않는다. 긴급 허기·좁은 발판·집/컨트롤·점프OFF는 조심스러운 접근으로 양보한다. 장면당 사고 최대1회와 기존 mishap 제한을 유지한다.
- 다른 맥락: 기상 뒤 기지개/몸털기, 친근한 접촉 뒤 종별 놀이/몸단장, 기존 하트 거절·헛디딤·숨기/발견의 실제 후속까지 사용처를 확인한다. 쓰다듬기 보상 함수를 가짜 기쁨 표현에 재사용하지 않는다. 식사/친밀도/학습/기록은 기존 실제 입력/소비 성공에서만 생긴다.
- 소유권: action 완료와 중도 취소를 구분한다. 직접 집기·키보드·귀가·새 창/편집·최초공개·비활성/숨김·감소/OFF·설정 해제는 연속 장면을 취소하고, 공중에서는 기존 안전 착지를 지킨다. 잡히거나 가려진 음식과 삭제를 구분하며 같은 음식 소유권/유한 route 예산·실제 consume1회를 보존한다.
- 성능/공유: 시청자·편집실·미리보기·비로그인은 같은 brain/renderer를 사용하고 모바일 제외를 유지한다. 기존 단일 tick과 exact decoder2 in-flight/3 retained 안에서 현재/바로 다음 반응만 준비한다. 프레임별 경로 탐색/난수 추첨·새 loop/timer/React 프레임 상태·전수 이미지 preload는 만들지 않는다.
- 검증: 상태를 실제 진행하는 seed 단위검사로 각 변형/동일ID/예산/사고1회/소비1회/취소·설정·실제 기하를 확인한다. production fixture에서 native 입력·실제 HD채택/접촉/착지/입 위치·쓰기 차단을 확인하고 무작위 관찰과 재현 회귀를 나눈다.092에서 부적절했던 ‘임의90초 내 모든 행동’ 보장을 다시 만들지 않는다. 전체 unit/typecheck/lint/build/harness, 독립 교차 검토와 검증 소스 일치 뒤 기존 승인된 후속 commit/push/원격CI·Vercel·운영 SHA/표시를 확인한다.
