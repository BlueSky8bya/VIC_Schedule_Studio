# PLAN-20260908-010 — 아트 보드 목록 재작성

Status: **Accepted · 구현 완료**(2026-09-08) · Level: **L2(구조적)**
> 실측: 첫 카드 y **590 → 316**(목표 300) · 상시 칩 **40+ → 4** · 필터 6줄 → 1줄 + 서랍 · 카드에서 브리프·규격 칩 제거(계약 테스트).
소유자: "배경아트보드 창 아직 너무 어수선해. 대대적인 리폼해달라니까? 처음부터 다시 계획 세워서 다시 깔끔하게 지금 상황에 맞게 대개편해줘."

PLAN-009는 **상세 라우트만** 새로 만들고 목록은 손대지 않았다. 어수선함은 목록에 있다 — 이 계획은 목록을 다시 쓴다.

## 진단 — 지금 화면이 왜 어수선한가(실측)

첫 화면(1400×900)에서 **자리 카드가 시작되는 지점이 y ≈ 590**. 화면의 **65%를 크롬이 먹는다.**

| 무엇 | 지금 | 문제 |
|---|---|---|
| 머리말 | 파이프라인 설명 5줄 | 한 번 알면 필요 없는 내용이 매번 첫 화면을 먹는다 |
| 통계 | 6칸(파일럿·전체·도감 3권·빈 자리) | "0/40 도감·물고기"처럼 **시작도 안 한 것**이 합격 진행률과 같은 크기 |
| 프롬프트 버튼 | 6개 나란히 | 자주 쓰는 건 1~2개인데 여섯이 같은 무게 |
| 필터 | **6줄 · 칩 40개 이상** | 밀도·범주·차수·상태·지금·정렬이 전부 같은 칩이라 **지금 뭐가 켜졌는지 스캔이 안 된다** |
| 카드 | 이름·id·진행·미리보기 2장·칩 6개·**브리프 전문** | 카드 하나가 화면 높이의 절반. 브리프 마크다운의 `**`가 그대로 보인다 |

## 원칙 — 목록과 상세의 역할을 가른다

**목록이 답할 질문은 하나다: "무엇이 남았나."** 규격·브리프·프롬프트는 상세(`/studio/ambient-art/[slotId]`)가 맡는다.
PLAN-009에서 상세를 만들어 놓고 카드는 여전히 전부를 보여 주고 있었다 — 그게 어수선함의 뿌리다.

## 결정

### D1 — 크롬을 한 줄로

- 머리말 5줄 → **접힌 도움말**(`<details>`, 기본 닫힘). 첫 줄만 남긴다.
- 통계 6칸 → **한 줄 진행 바 하나**(1차 자리 기준) + 빈 자리 수. 도감 3권은 2차라 아직 0이므로 도감 뷰 안으로 옮긴다.
- 프롬프트 버튼 6개 → **하나(주 동작 = 남은 파일만)** + 나머지는 메뉴.

### D2 — 필터는 한 줄, 상태는 세그먼트

칩 40개를 **검색 + 범주 + 상태 + 정렬** 넷으로 줄인다. 범주는 `RhhSelect`(설정에서 쓰는 커스텀 셀렉트, 네이티브 금지 규칙),
상태는 3상태 세그먼트(전체 · 남음 · 납품됨) — 프로젝트가 이미 쓰는 `--seg-on-*` 어법을 그대로 쓴다(globals.css).
계절·차수·"지금" 필터는 쓰임이 드물어 **접힌 서랍**으로 내린다.

### D3 — 카드는 자리 한 줄로 줄인다

카드에 남길 것: **미리보기 1장 · 이름 · id · 진행(칸)** 넷. 규격 칩·브리프·동숲 참고는 상세로.
진행은 "3/8" 숫자가 아니라 **칸 8개**로 — 빈 칸이 산수보다 빠르다(상세에서 검증된 방식).
카드 전체가 상세로 가는 링크다(제목만 링크였던 것을 넓힌다 — Fitts).

### D4 — 도감 뷰는 그대로 둔다

`CodexRow` 표(동물의 숲 도감 형식)는 2차 종을 위한 별도 뷰이고 잘 동작한다. 밀도 전환에서 "도감"만 남기고
카드/목록 두 밀도는 **하나로 합친다**(카드가 이미 한 줄로 줄었으므로 목록 밀도가 따로 있을 이유가 없다).

## 범위 밖

- 상세 화면(PLAN-009 P3)은 이번에 안 건드린다 — 방금 만들었고 소유자 지적 대상이 아니다.
- 매니페스트·프롬프트 생성기는 그대로.

- 첫 화면(1400×900)에서 **자리 카드가 y ≤ 300에서 시작**한다(지금 590).
- 필터 줄 수 ≤ 2, 상시 노출 칩 ≤ 12개(지금 40+).
- 카드에 브리프 텍스트가 없다(계약 테스트).
