# PLAN-20260918-023 — 시청자 검색("그거 언제 어디쯤이었지?")

Status: **Shipped** P0–P3 (2026-09-18; 결과 UI 2차 개정 §5, 0076/0077) · Task Risk: **L2** (공개 API·마이그레이션·머리줄 크롬 교체)
Created: 2026-09-18 (KST)

## 0. 한 줄

시청자·미리보기·비로그인 화면 머리줄 가운데 "내 관심" 토글을 **검색** 버튼으로 교체한다. 검색은 공개 데이터 세 원천(일정 제목·설명, 다시보기 제목, 팬 타임라인 챕터)을 한 색인으로 묶어, 결과를 누르면 그 달·그 칸으로 가거나 다시보기의 **그 시각**으로 바로 뛴다. 순위는 유튜브 검색의 골격(관련도 → 참여 신호 → 최신성 → 사용자 맥락)을 우리 신호로 옮긴다.

예: "젤다" →

```
2026-03-14 (토) 20:00  일정      젤다 야숲 엔딩 도전                  [달력으로]
2026-03-14 (토)        다시보기  젤다 엔딩 봤다 · 3h 12m              [다시보기]
   ├ 00:42:10  젤다 가논 1페이즈                                    [이 시각부터]
   └ 02:58:03  젤다 엔딩 크레딧
2025-11-02 (일) 19:30  일정      젤다 티오킹 첫 방
```

## 1. 원칙

1. **공개 데이터만.** 색인·API는 `public-loader` 계열에서만 만든다. 비공개·엠바고·작업자 일정은 색인에 들어가지 않는다(경계 검사가 통과 조건).
2. **한 기능 = 한 구현.** 시청자·미리보기·/onair·비로그인은 `interactive` 분기 하나로 같은 검색 컴포넌트(G-18/UI-18). 새 모달 금지, 사이드 패널 훅(ADR-0025) 재사용.
3. **머리줄 교체.** `poster-interest`(내 관심) 자리를 `poster-search`가 차지한다. ♥ 필터는 범례 줄에 그대로 남는다(기능 손실 없음).
4. **검색어는 남기지 않는다.** 활동 로그·통계에 검색어를 저장하지 않는다(소유자 결정). 따라서 클릭 학습(CTR) 없이 **정적 신호만**으로 순위를 낸다.
5. **캐시 친화.** 응답은 익명 동일 → 공개 API CDN `s-maxage`. 쓰기·수집 때 revalidate 규약 준수.

## 2. 데이터

| 원천 | 필드 | 비고 |
|---|---|---|
| `events` (public만) | `public_title`, `public_description`, `date_key`, `start_time`, 태그명 | 설명 본문 포함(결정 3), 가중치 낮음 |
| `vod_archive` | `title`, `broadcast_day`, `duration_ms`, `read_cnt`, `like_cnt`, `comment_cnt` | 이미 anon SELECT |
| `vod_timeline.entries` | `{sec,label}` jsonb | **검색 불가 형태** → 평탄화 필요 |

새 테이블 `vod_chapter_index(title_no, sec, label, label_norm)`: 수집기(`lib/broadcast/vod-timeline.ts`)가 타임라인을 갱신할 때 해당 `title_no` 행을 지우고 다시 넣는다. RLS + anon SELECT + service_role DML grant(0035/0043 교훈).

정규화 함수 `search_norm(text)`: NFKC, 소문자, 공백·기호 제거, 한글 자모 분리 없음. "야 숲!" = "야숲".

인덱스: `pg_trgm` GIN을 `events.public_title`, `public_description`, `vod_archive.title`, `vod_chapter_index.label_norm`에. 한글은 Postgres 전문검색 형태소가 없어 트라이그램이 현실적.

## 3. 순위 — 유튜브 벤치마킹표

유튜브 검색은 크게 **관련도(relevance) · 참여(engagement) · 품질(quality) · 최신성(freshness) · 개인화**의 합이다. 각 신호를 우리 데이터로 옮긴다. 검색어 저장 안 함 → 클릭·시청시간 학습은 제외.

| 유튜브 신호 | 우리 대응 | 구현 |
|---|---|---|
| 제목·설명·태그·자막 매칭 | 일정 제목(3.0) > 다시보기 제목(2.0) > 챕터 라벨(1.5) > 태그명(1.2) > 일정 설명(0.7) | 필드별 가중치 × `similarity()` |
| 정확 구 매칭 우선 | 정규화 후 **부분 문자열 포함**이면 +1.0, 단어 시작 위치 매칭 +0.3 | `position()` |
| 여러 단어 AND | 공백 분리 토큰 전부 포함이면 통과, 일부만이면 절반 점수 | 토큰별 similarity 평균 |
| 오타 허용(did you mean) | 트라이그램 유사도 ≥ 0.25면 후보 유지, 정확 포함 없을 때만 "이걸 찾으셨나요?" 힌트 | P3 초성 검색은 별도 |
| 조회수·좋아요·댓글 | `log1p(read_cnt)/log1p(월 최댓값)` ×0.4 + `like_cnt`·`comment_cnt` 동식 ×0.2 | 다시보기·챕터에만 |
| 시청 지속시간 | 없음 → 대체: 챕터가 **많은** 다시보기는 팬이 정리할 만큼 밀도 높음 → `entry_count` 정규화 ×0.2 | |
| 시청자 반응(관심) | 일정 `event_hearts` 집계(이미 공개 RPC) 정규화 ×0.4, 떡밥 기대 수 ×0.1 | 일정에만 |
| 최신성 | `exp(-경과일/365)` ×0.3 (1년 지나면 약 0.11) — **관련도 우선 + 최신 가산**(결정 4) | 정렬 최종 tiebreak도 날짜 desc |
| 개인화(시청 기록) | 로그인 시청자 본인 ♥ 일정 +0.3, 기기 로컬 최근 열어본 다시보기 +0.1 | 클라이언트에서 가산(서버 응답은 익명 동일 유지) |
| 키 모먼트(영상 안 검색) | 챕터 히트를 다시보기 아래 **들여쓰기**로 묶고 클릭 시 `t=초`로 시킹 | 본 기능의 핵심 |
| 채널 내 검색 | 단일 스트리머라 항상 채널 내 검색과 같음 | — |
| 자동완성 | 검색어 저장 안 함 → 태그명 칩 제안(정적) | 출고 |
| 동의어·줄임말(query rewriting) | 큐레이션 사전(seed) + 제목↔챕터 줄임말 관계 자동 채굴(auto, ≥3 방송) + 첫 음절 부분열 안전망(낮은 등급). Lucene synonym_graph식 토큰 확장 | 0078 |
| 정렬 옵션 | 관련도(기본)·최신·오래된·인기(popularity = 참여 신호) — 묶음 단위, 비슷한 결과는 항상 뒤 | 0078 |

점수식(서버 RPC):

```
score = field_w × sim + exact_bonus + engagement + freshness
```

클라이언트는 여기에 개인화 가산만 더해 재정렬. 같은 날짜의 일정·다시보기·챕터는 **날짜 묶음**으로 접고, 묶음 점수 = 안의 최댓값.

## 4. API

- `GET /api/public/vic/search?q=…&limit=50` → `{ groups: [{ date, items: [{kind:'event'|'vod'|'chapter', id, titleNo?, sec?, title, snippet, score}] }] }`. 명시적 DTO. `q` 정규화 후 2글자 미만은 빈 배열.
- RPC `search_public(p_calendar_id, p_q, p_limit)` SECURITY DEFINER, 세 원천 UNION ALL, 상위 N. 원본 행·비공개 컬럼 반환 금지.
- 캐시: `s-maxage=300, stale-while-revalidate`. 일정 저장·삭제·수집기 갱신 시 검색 태그 revalidate(3줄 규약).
- 클라이언트 디바운스 300ms, 이전 요청 취소(AbortController).

## 5. UI

- **버튼**: 머리줄 가운데 🔍 "검색". '이 달 기록'과 같은 폭·글자. 캡처면·꾸미기 모드엔 없음(표면 밖 크롬).
- **패널**: `use-side-panel` 방향·폭 그대로. 상단 입력창 자동 포커스, 아래 날짜 묶음 결과. 매치 글자 `<mark>`. 모바일은 같은 패널이 전폭 시트.
- **클릭**:
  - 일정 → `onViewChange(year, month)` + 칸 `cell-range-selected` 1.2s 점등 + 카드로 스크롤.
  - 다시보기·챕터 → 시청자 `/replay/<날짜>?part=N&t=<초>`; 미리보기·onair는 `DayVodWindow` 모달에 `t` 전달. 시킹은 `PseekTo` 경로.
- **키**: `/` 열기(감상 중 키 삼킴과 충돌 시 감상 우선), Esc 닫기, ↑↓ 이동, Enter 실행.
- **빈 결과**: "이걸 찾으셨나요?" 후보(유사도 하위 임계) 또는 최근 챕터 5개.
- 햅틱: 열기·결과 클릭 각 1회 `hapticTick`.

## 7. 검증

- 픽스처 일정은 **과거 달**에만, `finally` 청소.
- e2e: "젤다" → 3종 결과 → 클릭 → 달 이동/시킹. 시청자·미리보기·비로그인 3화면 동일 DOM.
- **경계 검사**: 비공개·엠바고 일정 제목으로 검색 → 0건이어야 통과. 응답 JSON에 금지 필드명(private/embargo/work/codename/editor/request) 부재 검사.
- 순위 테스트: 제목 정확 매치 > 설명만 매치, 같은 점수면 최신 우선, 인기 다시보기 가산 확인.
- `npm run build` exit code, `npx next lint`(로컬 ESLint 설치 후).

## 8. 소유자 결정 — 확정(2026-09-18)

1. 머리줄 "내 관심" → 검색으로 **교체**(♥ 필터는 범례에 잔존).
2. 검색어 **통계에 남기지 않음**.
3. 일정 **설명 본문까지** 검색(가중치 낮음).
4. **관련도 우선 + 최신 가산**.
5. 순위는 **유튜브 검색 알고리즘 최대 벤치마킹**(§3).
