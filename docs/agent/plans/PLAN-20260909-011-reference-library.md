# PLAN-20260909-011 — 취향 레퍼런스 서고(엔티티별 참고 그림)

Plan ID: PLAN-20260909-011
Status: Proposed (2026-09-09)
Task Risk: L2 (구조적 — 생성 의뢰의 입력이 "글"에서 "그림"으로 바뀐다. 외부 저작물이 저장소에 들어온다)
Created / Updated: 2026-09-09

## 왜 (소유자 제안, 2026-09-09)

> "각 엔티티별로 레퍼런스 폴더를 각각 따로 만들어서 그 안에 내가 원하는 느낌의 픽셀아트를 채우면,
> GPT가 거기 있는 레퍼런스 사진들 토대로 이미지 생성할 수 있게 프롬프트 작성하는 거지."

3차 소나무 납품이 **수치 여덟을 전부 통과하고 반려**됐다. 틀린 둘은 **말로만 적혀 있던 것**이었다
(눈이 앉는 자리 · 밑동 모양). 교훈은 "지표를 늘려라"가 아니라 **말은 새고 그림은 안 샌다**이다.
이 계획은 그 교훈을 입력 전체로 확장한다 — 소유자의 취향도 문장이 아니라 **그림**으로 전달한다.

특히 **도감 129종(물고기·곤충·동물)은 합격본이 0장**이다. 화풍을 붙잡을 우리 그림이 그 범주에 없으니,
취향 참고가 없으면 65장짜리 배치가 3차와 같은 빈칸 위에서 시작한다.

## 설계 결정 셋

### ① 분류는 새로 만들지 않는다 — `ArtCategory`를 그대로 쓴다

`manifest.ts`의 `ArtCategory`가 이미 소유자가 말한 아홉이다:
`tree` 나무 · `plant` 풀·꽃 · `ground` 지형 · `water` 물 · `prop` 소품 · `sky` 하늘·천체 ·
`fish` 물고기 · `bug` 곤충 · `animal` 동물. 자리마다 `category`가 붙어 있으므로 폴더 키는 공짜다.

⚠ 새 분류 체계를 세우면 매니페스트와 폴더가 갈라진다. **갈라진 두 목록은 이 저장소에서 이미 사고를 냈다**
(`world/species.ts` ↔ `codex.ts` — ADR-0019에서 폐기).

### ② 그림을 그대로 첨부하지 않는다 — **한 장으로 합성**한다

가장 중요한 결정이다. 4차 프롬프트는 "우리 시트가 정본, 바깥 그림은 발상만"을 **글로** 적었다.
그런데 3차가 증명한 것이 글은 안 먹힌다는 것이다. 참고 5장에 우리 시트 1장을 붙이면 생성기는 **다수를 따라간다**.
바깥 픽셀아트는 대개 우리보다 촘촘해서 도트 굵기와 팔레트가 그쪽으로 끌려가고, 한 장면에 두 화풍이 섞인다.

그래서 `ambient-art-reference.mjs`가 두 구역을 **하나의 PNG로** 굽는다:

```
┌─────────────────────────────────────────┐
│ ① 우리 합격본 — 이 어법으로 그린다      │  ← 위 · 크게 · 항상 먼저
│   (전체 · 밑동 확대 · 눈 확대)          │
├─────────────────────────────────────────┤
│ ② 취향 참고 — 형태의 발상만             │  ← 아래 · 작게 · 최대 6장
└─────────────────────────────────────────┘
```

우선순위를 **문장으로 주장하지 말고 배치로 보여준다.** 취향 참고는 개수 상한을 둔다(볼륨이 위계를 못 이기게).

### ③ 화풍 기준과 소재 참고는 다른 것이다

도감 범주엔 ①로 쓸 우리 그림이 **없다.** 그래서 시트는 두 출처를 구분해 뽑는다:

- **화풍 기준(①)** = 그 자리의 합격본. 없으면 **가장 가까운 합격 범주**(바위·나무)에서 빌려온다 —
  도트 굵기·색 단수·외곽선을 나르는 역할이지 소재를 나르는 역할이 아니다.
- **소재 참고(②)** = 취향 폴더. 형태·실루엣·부위가 붙는 방식만.

## 저장 규칙 (소유자 결정: 라이선스 깨끗한 것만 커밋)

- 폴더: `art-src/reference/<category>/`
- 그림마다 **사이드카** `<name>.json`: 출처 URL · 라이선스 · 작성자 · 원제 · 받은 날.
- `art-src/reference/NOTICE.md`는 **살아남은 사이드카에서 다시 굽는다.** 소유자가 그림을 지우면
  그 줄도 같이 사라진다 — 손으로 관리하는 목록은 반드시 낡는다(이 저장소가 두 번 겪었다).
- **CC0만 받는다.** 검색 필터를 믿지 않고 **개별 페이지의 라이선스를 다시 확인**해서 CC0가 아니면 버린다.
- ⚠ 참고는 **발상만**이다. 베끼거나 트레이스한 결과물은 못 쓴다(ADR-0019). 이 문장은 프롬프트에도 남는다.

## 순서

- **P0** 폴더 아홉 + 사이드카·NOTICE 규약, `scripts/ambient-ref-fetch.mjs`(CC0 수집), `scripts/ambient-ref-notice.mjs`(NOTICE 재굽기)
- **P1** 소유자가 솎아낸다(내가 받아 놓고, 소유자가 남길 것만 남긴다)
- **P2** `ambient-art-reference.mjs`에 ② 구역 + 화풍 기준 대체(가장 가까운 합격본) — 시트가 한 장으로 나온다
- **P3** `manifest.ts`의 프롬프트가 첨부 한 장을 가리키게(현재는 "첨부 둘"을 글로 서열 매긴다)

소나무 4차는 **이 계획을 기다리지 않는다**(소유자 결정) — 지금 구조 그대로 보낸다.
이 서고는 **도감 65장 배치**를 위한 것이다.

## 검증

- 사이드카 없는 그림 0 · CC0 아닌 항목 0 (계약 테스트)
- NOTICE의 줄 수 = 폴더의 그림 수 (지운 그림이 목록에 남지 않는다)
- 시트 한 장에서 ① 구역의 픽셀 면적이 ② 구역보다 크다 (위계가 그림에 있다)
- 기존 게이트: tsc · lint · vitest · build
