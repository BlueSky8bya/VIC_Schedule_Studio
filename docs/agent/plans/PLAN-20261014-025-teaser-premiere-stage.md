## 0. 한 줄

지금은 상세 팝오버 안에서만 링 카운트다운이 돈다. 앞으로는 최초공개 시각이 다가오면 **시청자 화면 전체가 공개를 위한 무대로 변신**한다. 크롬(데뷔일 박스·태그 필터·계절 배경·버튼)과 다른 일정이 재미있게 퇴장하고, 떡밥 카드가 화면 가운데 **영화관 스크린**으로 커지며 주변이 어두워진다. 60초부터 주변이 점점 들끓다가(고조), 10초부터 **태풍의 눈**처럼 고요해져 숫자에만 집중하고, 0초에 **빅뱅**과 함께 스크린에 일정이 공개된다. 그 뒤 무대가 걷히고 공개된 카드가 제 날짜 칸으로 **착지**하며 달력이 다시 조립된다.

## 1. 원칙 (기존 규칙에서 상속)

1. **경계 불변.** 공개 전 실제 제목·태그·시간은 클라이언트에 절대 오지 않는다(뷰 `public_schedule_events`가 DB `now()`로 가림 — 그대로). 무대 연출 때문에 DTO를 넓히지 않는다. 스크램블 가짜 글자 수도 실제 길이를 흘리지 않는다(고정 6–10자 난수).
2. **한 기능 = 한 구현(G-18/UI-18).** 시청자·비로그인·미리보기·/onair가 같은 `PremiereStage` 하나. 강도 곡선은 기존 `lib/ui/hype-curve.ts`(`hypeIntensity`·`hypeCalm`·`hypeFinale`·박자 위상) **그대로 확장**, 새 곡선 금지. 공개 데이터 경로는 기존 `revealTeaserAction`·`resolveTeaserView`·`reconcileTeaserReveal` 하나.
3. **포스터 기하 불변.** `[data-export-surface]`(폭 1840) 안 레이아웃을 reflow하지 않는다. 퇴장·변신은 transform/opacity만, 스크린은 **표면 밖 고정 오버레이**에 클론으로 띄우고 원본 카드는 `visibility:hidden`.
4. **프레임 규칙(frame-jank-causes).** 전역 `filter` 금지(어둠은 비네트 오버레이 opacity), 무한 애니는 transform/opacity만, 호버·단계 전환은 React 전체 리렌더 대신 `<html data-premiere=…>` 속성 + CSS 변수.
5. **몰입 우선이되 탈출은 한 번.** 자동 진입, 언제든 "평소 화면으로"(Esc) 한 번에 원복. 동작 줄이기·gfx 등급·소리 설정을 존중.
6. **라이브만 축하.** 0초를 라이브로 지켜본 화면만 빅뱅(기존 celebrate 규칙). 공개 뒤 들어온 사람은 조용히.
7. **한 시계.** 모든 시청자가 같은 순간 터지도록 서버 시각 보정(§4.1). 방송 중 시청자 화면들이 1초씩 어긋나면 연출이 깨진다.

- 비율은 상수 한 곳(`PREMIERE_TIMING`)에 모아 소유자 조정이 쉬운 형태로.
- **늦게 들어온 사람:** P1–P5 중 진입하면 해당 단계로 1초 압축 진입(퇴장 애니 생략, 바로 무대). P6 이후 진입은 무대 없음.
- **숨김 탭 복귀:** 애니를 재생하지 않고 현재 단계로 즉시 스냅.

### 3.2 일정 퇴장

- **PC 달력:** 떡밥 칸 기준 거리순 지연(`--pm-d`)으로 칸이 1–2° 흔들리다(지진) 아래로 떨어지며 사라짐. 칸 단위 transform(이벤트 단위 아님 → 노드 수 ~35).
- **모바일 일정표:** 떡밥 줄 기준 위/아래로 갈라지며 미끄러져 퇴장(모세의 기적).
- 퇴장 중에도 표면 기하 불변(transform만), 무대 끝나면 transform 제거로 원복.

### 3.3 스크린

- 떡밥 카드 위치 측정 → 고정 오버레이에 클론 → `flipSpring`으로 화면 중앙 16:9(뷰포트 최대 72vw × 60vh, 모바일은 92vw 세로형 4:5).
- 스크린 구성: 위 날짜·요일 라벨, 가운데 `???` 실루엣 + 큰 카운트다운(기존 `TeaserBigCountdown`·링 무대 재사용), 아래 기대돼요. 스크린 테두리 = 보라 액센트(ADR-0029 떡밥 색) + 금(금생수 스킨).
- 무대 바깥 클릭은 무반응(백드롭 무반응 정책 계승), "평소 화면으로"만 탈출.

## 4. 시계·데이터·변경 대응

### 4.1 서버 보정 시계 (신규, 필수)

- 지금은 `Date.now()`만 쓴다(오차 보정 없음 — 계획 문서에 열린 문제로 남아 있음). 기기 시계가 2초 틀리면 빅뱅이 2초 어긋난다.
- `usePremiereClock`: 서버 시각 표본으로 오프셋 추정(왕복 시간 절반 보정, 표본 3개 중앙값). 표본 출처는 아래 4.2 폴링 응답의 `serverNow` + no-store 경량 엔드포인트 중 소유자 결정(§9-7). 기존 `useRemainSeconds`가 이 오프셋을 받도록 확장 → 카드·팝오버·무대 모두 같은 시계(G-18).

### 4.2 떡밥 감시 (신규, 공개 시각 변경 대응)

- 지금 열린 탭은 공개 시각을 **당겨도 모름**(폴링·실시간 없음). 무대는 이게 치명적이므로 감시 필요.
- `/api/public/[slug]/teasers`: `{id, dateKey, revealAt}[]` + `serverNow`만(뷰가 이미 공개하는 필드뿐 — 경계 변화 없음). CDN `s-maxage=5, stale-while-revalidate=5` → 시청자 수와 무관하게 DB 부하 ≈ 5초당 1회(nano DB 보호).
- 폴링 주기: 가장 가까운 떡밥이 30분 밖이면 안 함 / 30분–3분 60초 / 무대 중 10초 / 숨김 탭 정지.
- 쓰기 액션에서 이 경로도 revalidate(cache-revalidate-on-writes 규약).

### 4.3 상황별 대응 (순수 함수 `planPremiere(teasers, now)`가 단계·묶음 결정, 전부 유닛 테스트)

| 상황 | 대응 |
|---|---|
| 공개 시각을 **뒤로** 미룸(새 T > now+180) | 무대 "인터미션": 스크린에 "공개가 미뤄졌어요 · HH:MM" 2초 → P7 귀환(빅뱅 없이). 새 T−180에 다시 무대 |
| 뒤로 미뤘지만 아직 무대 구간 | 단계만 재계산해 이어감(되감기 애니 없이 곡선 연속) |
| **앞으로** 당김 | 남은 시간에 맞춰 단계 압축: 남은 ≥60초면 P2를 3초로 압축 후 계속, <60초면 P2 생략 1초 즉시 무대, <10초면 바로 P5 |
| 소유자가 즉시 공개(떡밥 해제) | 감시 응답에 사라짐/공개됨 → 바로 빅뱅(압축 1초 카운트 "지금 공개!") |
| 떡밥 삭제·비공개 전환 | 무대 조용히 걷힘("공개가 취소됐어요"는 띄우지 않음 — 정보 노출 최소, 소유자 결정 §9-6) |
| 0초인데 데이터 미도착(DB 지연·캐시) | 섬광·충격파는 즉시, 스크린 스크램블이 계속 돌며 대기(기존 2초 재시도), 6초 넘으면 "곧 보여요" 작은 문구 |
| 서버·기기 시계 경계 차이(뷰는 DB now, 매퍼는 Node now) | 0초 직후 1회는 서버가 아직 stub을 줄 수 있음 → 재시도로 흡수. Node가 앞서 빈 제목 비-떡밥을 줄 수 있는 경계 버그는 M1에서 수정(`mapEvent`가 뷰의 빈 제목+teaser를 stub으로 유지) |
| 다른 달을 보고 있음 | 무대는 보고 있는 달과 무관하게 열림, 귀환 시 그 달로 이동 후 착지(소유자 결정 §9-8) |
| 상세 팝오버 열린 채 진입 | 팝오버가 스크린으로 변신(팝오버 링 무대 = 스크린 링 무대, 같은 컴포넌트) |
| VOD 창·검색·설정 모달 열림 | 무대 진입 보류 → P1 띠만 + "무대 보기" 버튼, 닫는 순간 현재 단계로 진입 |

## 5. 여러 떡밥

`planPremiere`가 T순 정렬 후 묶는다.

| 간격 | 묶음 | 화면 |
|---|---|---|
| 같은 시각(≤1.5초) | **멀티플렉스** | 스크린 2개 나란히 / 3개 세 폭 / 4개 2×2 / 5개+ 가운데 큰 스크린 + 회전 띠. 카운트다운 하나, 빅뱅 하나, 글자 확정만 150ms 엇갈림 |
| 1.5초–15초 | **연쇄 폭죽** | 멀티플렉스 + 스크린마다 작은 카운트 칩. 앞쪽은 작은 빅뱅(국소 충격파), 마지막이 큰 빅뱅. P5 고요는 첫 번째 T−10부터 마지막까지 유지 |
| 15초–180초 | **연속 상영** | 무대 유지. 공개된 스크린은 줄어 아래 **필름 띠**에 꽂히고, 다음 스크린이 옆에서 밀려 들어옴. 다음 떡밥까지 >60초면 P3로 돌아가 대기 |
| 180초 초과 | 별개 무대 | 귀환 후 다음 T−180에 재진입 |

- 묶음은 감시 응답이 바뀔 때마다 재계산(시각 변경으로 묶음이 합쳐지거나 갈라질 수 있음 — 스크린 추가/제거는 FLIP).
- 공개 호출은 묶음 단위 배치 1회(지금은 카드마다 개별 호출 + 2초 재시도 N개).

## 6. 추가 아이디어 (제안 — 소유자 선택)

1. **계절 태풍.** 고조 입자를 보고 있는 달의 계절 소재로(봄 꽃잎·여름 물방울·가을 낙엽·겨울 눈). 계절 배경(ADR-0017)과 결이 맞고, 캔버스 없는 모바일·배경 OFF에서도 무대 전용 경량 입자층(gfx: full 120 / lite 40 / soft 0 + 정적 그림)으로 동작.
2. **응원봉.** 무대에서 기대돼요를 누르면 객석(화면 아래 어둠)에 내 응원봉 하나가 켜지고 고조 박자에 맞춰 흔들림. 다른 사람 수는 표시하지 않음(배지 개발자 전용 결정 유지) — 객석의 다른 불빛은 장식이라 숫자로 읽히지 않게 흐릿하게.
3. **리허설 모드.** 소유자/개발자가 편집실 미리보기에서 "무대 리허설"로 가짜 떡밥(더미 제목, 30초 후)을 자기 화면에서만 재생 — 방송 전 연출 확인용. 실제 데이터·DB 쓰기 없음.
4. **필름 띠 엔딩.** 연속 상영 끝나면 공개된 것들 모아 "오늘 공개된 일정" 엔딩 크레딧 2초.
5. **소리.** 고조 저음 드론 → 눈 구간 무음 + 심장박동 → 빅뱅 팡파르. 기존 소리 설정(`sfx` 카테고리 celebrate) 따라감, 기본은 기존 기본값.
6. **방송 화면 친화.** /onair·방송 패널에서 띄워도 크롬이 없으므로 그대로 방송 화면이 됨(추가 구현 없이 확인만).

## 7. 접근성·안전

- 동작 줄이기: 퇴장/귀환은 0.2초 페이드, 흔들림·입자·충격파 없음, 어둠·스크린·카운트다운·글자 즉시 확정은 유지(기존 `quantizeStaticIntensity` 계승).
- 섬광: 빅뱅 단일 섬광 1회, 고조는 초당 3회 미만(기존 0.62초 하한). 빅뱅 휘도 변화 상한 문서화 + 측정.
- `aria-live="polite"`: "3분 뒤 최초공개", "1분", "공개: <제목>". 카운트다운 매초 낭독 금지.
- 키보드: Esc = 평소 화면, 포커스는 "평소 화면으로" 버튼에 가둠 없이 둠.
- 평소 화면으로 나간 사람: 그 묶음에 다시 들어오지 않음(세션 기억), 카드 카운트다운은 지금처럼. 띠에 "무대 다시 보기" 남김.

- `public-poster.tsx`(5,655줄)에는 진입점·속성 연결만. 공개 파이프라인(`revealedEvents`, celebrate)은 무대가 **읽기만**.
- 단계 → `<html data-premiere>` + `--pm-*` CSS 변수를 10Hz 루프 하나가 씀(기존 카드 루프와 통합; 지금 카드마다 평생 도는 100ms 루프는 60초 창으로 제한 — 비용 정리 겸).
- 기존 소스 문자열 단언 유닛 테스트(`teaser-reveal-selfheal` 등)가 코드 이동에 깨지므로 같은 커밋에서 갱신.

## 9. 소유자 결정 필요

1. **시작 시점:** 예고 T−180·변신 T−150(제안) vs T−120 단일.
2. **자동 진입 vs 묻기:** 자동 + 평소 화면 버튼(제안) vs "무대 보기" 버튼 눌러야 진입.
3. **늦게 들어온 사람:** P5 중 진입도 무대 보여줌(제안) vs 60초 전까지 진입한 사람만.
4. **응원봉에 숫자:** 없음(제안, 배지 비노출 결정 유지) vs 공개.
5. **빅뱅 뒤:** 8초 후 자동 귀환(제안) vs 클릭할 때까지 유지.
6. **떡밥 취소 시 문구:** 조용히 걷힘(제안) vs "취소됐어요".
7. **시계 표본:** 감시 응답 `serverNow`+CDN Age 보정(제안, 추가 요청 0) vs 별도 no-store 엔드포인트(정확, 요청 증가).
8. **다른 달 떡밥:** 무대 열고 귀환 시 그 달로 이동(제안) vs 보고 있는 달 떡밥만.
9. **편집실 미리보기 포함:** 포함(G-18, 제안) / 편집 화면 자체는 제외.
10. **소리 기본값:** 기존 설정 그대로(제안) vs 무대만 기본 무음.
