# ADR-0014 — 편집실 비공개 레이어 UI 철수 (비밀번호는 최초공개 게이트 전용)

Status: Accepted
- Date: 2026-08-27
- Supersedes(부분): ADR-0011의 "잠금해제 auth-session 단위" — 서버 모델은 그대로 두고 **편집실 UI 진입점만**
  없앤다. ADR-0012(범위 fail-closed) 불변식은 그대로 유효.
- 관련: `lib/permissions/roles.ts`, `app/api/unlock-private-layer`, `components/private-layer/private-layer-panel.tsx`

## 맥락

관리자(빅토리)가 "공개 범위 옵션"과 "비공개 일정 보기"를 **쓰지 않는다**고 밝혔다(2026-08-27,
사용자 전달). 개발자도 쓰지 않는다. 실제 데이터도 같은 말을 한다 — 프로덕션 `events`에 비공개
범위 일정은 1건(`work`)뿐이고 나머지는 전부 `public`.

반면 같은 비밀번호(`/api/unlock-private-layer`, `verifyOnly`)는 **최초공개(떡밥) 게이트**에 쓰인다 —
아직 안 풀린 떡밥을 편집하려면 비번을 넣어야 한다. 이건 관리자가 쓰는 기능이라 남겨야 한다.

## 결정

1. **편집실 UI에서 철수**: 액션바·모바일 툴바의 '비공개 일정 보기' 토글, 하단 '지금 잠그기' 배너,
   모바일 상단 '비공개 일정 표시 중' 배너, 태그 범례의 '비공개' 필터 칩, 편집 폼의 공개 범위 피커
   (웹 `scope-picker`·모바일 `me-seg`). 접힘 헤더는 "공개 범위 · 옵션" → **"옵션"**, 요약은
   미정/업 도움/최초공개만(없으면 "없음").
2. **서버 모델·권한 검사는 그대로**: `visibility_scope` 컬럼·RLS·`canReadPrivateLayer`·저장 시
   fail-closed(비공개 범위는 잠금 해제 상태에서만) 전부 유지. 공개 API 경계 불변. UI가 없으니 새
   일정은 항상 `public`으로 저장된다.
3. **비밀번호는 유지, 용도는 최초공개 게이트 + 변경**. '비밀번호 변경'은 관리자만, 관리 묶음
   (웹)·모바일 툴바(옛 토글 자리)에서 연다(`PrivateLayerPanel startChanging` — 현재 비번 입력).
4. 기존 비공개 일정 1건은 편집실에서 더는 보이지 않는다(잠금 해제 경로가 없음). 관리자 결정으로
   공개 전환 또는 삭제 — 이 ADR은 데이터를 건드리지 않는다.

## 대안과 기각

- **비공개 모델까지 삭제(컬럼·API·암호화)**: 되돌리기 비쌈, 보안 경계 문서·테스트 전부 손봐야
  하고 얻는 건 코드 몇 백 줄. UI 철수만으로 사용자 목적(화면 단순화)은 달성된다 → 기각.
- **토글은 두고 기본 숨김(설정에서 켜기)**: "안 쓴다"가 명확한데 설정 항목을 남기면 관리 UI가
  또 늘어난다 → 기각.

## 되돌릴 조건

관리자가 엠바고/작업자 일정을 다시 쓰고 싶어질 때. 서버는 그대로이므로 토글·피커 UI만 복원하면
된다(`git log -S "private-toggle"` 참고, 커밋 이 ADR과 같은 날).
