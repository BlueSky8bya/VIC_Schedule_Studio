# ADR-0023 — Spring meadow source composition

Status: Accepted · 2026-09-11 KST

## Decision and authority

The owner likes the finer spring-meadow concept and authorizes another detail refinement if performance impact is modest, non-mobile desktop application, and push/deployed review. This replaces PLAN-015's wait for all 12 meadow files for this scoped spring pilot. Other seasons and the deep seal remain intact.

One original opaque 1536×1024 image supplies the terrain. F clips out source sky using pixel-derived canopy boundaries; M crops grass uniformly around the existing 0.26h horizon; the low procedural N frame remains. These are not three delivered transparent PNG layers and do not complete the 123-file art programme. Public geometry contains no private workflow metadata.

This spring source path replaces the early transparent 6–10-color / 384×256 candidate-normalization requirement for this owner-liked release. Preserve the explicitly liked soft color impression and finer detail. Earlier failed transparent candidates remain failed. General entity sprite rules are unchanged.

## Runtime and ratios

Source area stays fixed at 1536×1024 (6MiB RGBA, excluding browser/GPU overhead). The decoded image is shared; per-scene far cache is ≤2MiB and reduced for lite/still. Ground uses the existing depth cache. Pointer position is not a baking key. Distant sides repeat mirrored panorama segments on cache-pixel boundaries; very wide screens can reveal repeated tree masses. Ground scales uniformly around the center.

Engine sky/weather/light/creatures remain live. Source sky is excluded. Clear spring-meadow daylight gets a brighter sky palette without changing other biomes or dusk/night/weather palettes. Late decode requests one stationary dt=0 frame; frozen fixtures own their advancement. Loading starts after the mobile gate. Dispose prevents late redraw and releases the far cache.
