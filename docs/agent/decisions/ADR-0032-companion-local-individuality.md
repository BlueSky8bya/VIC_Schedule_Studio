# ADR-0032 — 빅타민의 기기 내 기질과 교감 습관

Status: Accepted

Date: 2026-11-26 KST

## Context

Owner approved the staged local personalization plan in the current chat. Federated learning and all companion learning uploads are excluded. Nine temperaments alone do not distinguish the habits of companions raised through different interactions. Document-by-document automatic rerolls also interrupt continuity.

## Decision

Keep the existing utility planner, physical ownership and settings gates. Add bounded home/outside tendencies around the authored temperament, plus coarse support-family affinity. Confirmed contact/play/home invitations teach only small changes with active-time credit; absent feedback is not dislike. Discovery alone earns no social reward. Existing agent-experience completion scores remain performance evidence; they are not migrated into social satisfaction.

Use the separate browser key vic.companionIndividual.v1 for settled automatic temperament and sanitized learning, never identities, raw input, schedule content or wall-clock absence. Preserve ordinary preferences version 1, care version 3 and all earned records. Manual personality remains authoritative. Learning OFF ignores and stops updating the new learned corrections; reset keeps identity/settings/assets while clearing tendencies through the existing generation boundary.

The 138/139 per-document automatic reroll clauses are superseded only for temperament persistence. An explicit random selection settles a new automatic child. No server inference, federation, account linking, new consent dialog or new analytics metadata.

Superseded public-history clause (owner2026-11-26 follow-up): the initial collapsed public timing/comparison section is removed entirely, including its table-of-contents item and terms link. Operational history remains in the existing developer settings surface with an authenticated actual-developer server action; role preview does not grant access. Public legal pages remain static and do not resolve actors. Current processing, retention and rights descriptions remain in the policy body. [Removal record](../plans/PLAN-20261126-public-policy-history-removal.md).

## Consequences and recovery

A shared browser profile has one companion; no inference of distinct people. New settings, devices or browser-data deletion cannot recover memories from a server. Reverting code can ignore the optional new key without deleting old preferences/assets. No DB migration or data cleanup is required.

Implementation and evidence: [plan](../plans/PLAN-20261126-companion-local-personalization.md). The actual renderer was exercised in a bounded offline React wrapper. Next app hydration/topology and independent integration review remain separate gates, not proven by that wrapper, unit tests or static document screenshots.


Independent review added controller-epoch cancellation for preference notifications (including OFF→ON in one task), context-correct behavior inputs, and optimistic same-generation storage stamps with reload on conflict. Native cross-process atomic storage is not guaranteed. Actual Next production SSR/RSC/hydration and role fixtures are verified; native focus, genuine owner login/RLS and production edge remain separately scoped in the report.
