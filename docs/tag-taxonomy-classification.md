# 태그 분류 체계 — 무엇을 대분류/세부로, content냐 modifier냐

작성: 2026-06-03 · 상태: **분류 확정(v3.1)**, kind 플래그 채택. 구현 전 스펙.

`tag-hierarchy-plan.md` = 메커니즘(parent_id·색 상속·렌더, 이미 shipped).
이 문서 = **실제 콘텐츠를 어떤 축으로 갈라 어디에 둘지**의 결정(내용).

---

## 1. 핵심 모델 3줄

1. 모든 태그는 **2계층 대분류/세부**(기존 `parent_id` 시스템 그대로). 별도 "수식어 트리/축"은
   만들지 않는다 — 이벤트가 대분류를 **여러 개 쌓아서**(≤6) 표현.
2. 콘텐츠는 **포맷 + 인스턴스** 구조 → **대분류 = 포맷**, **세부 = 그날의 구체 인스턴스(반복하는 것만)**.
3. 태그마다 **`kind` 딱지**(`content` | `modifier`)를 붙여, 색·통계·피커에서 둘을 다르게 취급.

## 2. kind 플래그 (채택 확정)

`broadcast_tags.kind text not null default 'content'` (`content` | `modifier`).

| kind | 캘린더 셀 색 | 인사이트 컨텐츠 순위 | 피커 위치 |
|---|---|---|---|
| content | ≤2 대표색 차지(기존) | 카운트됨 | [콘텐츠] 칸 |
| modifier | 색 X, **점만** | 제외 | [수식어] 칸 |

목적 = "**색·통계는 콘텐츠만, 수식어(합방·시참 등)는 곁다리**". 없으면 합방색이 셀을 먹고
컨텐츠 통계에 합방/시참이 섞여 지저분.

판정 규칙(애매하면 무조건):
1. **1회성이면 세부 아님 → 제목/메모.** (테스트: "뷰어가 이걸로 *필터*하나?" No면 태그 아님)
2. **"뭘 함"=content / "어떻게·누구·얼마나·무슨 장비"=modifier.**

## 3. 확정 트리 (v3.1)

```
[상태/주체]  (content · 색)
 ├ 휴뱅 (시스템 잠금, 회색 고정)
 └ 외부출연 (신설) ─ 세부: 토크쇼, 타스뱅송       ← 토리 본인 방송 아님(남 방송 출연)

[콘텐츠]  (content · 색 · 세부=반복 인스턴스, 개별/1회성은 제목)
 ├ 게임      ─ 명조·와우·오버워치·마스터듀얼·실크송·할로우나이트·배그·철권 …
 ├ 노래 (신설) ─ 신청곡·코노(코인노래방)·완창         ← 개별 곡 = 제목
 ├ VRChat   ─ 릴동파·아바타요 (모캡/골프/낚시 = 제목)
 ├ 서버(숲)  ─ 천벌서버·더켓몬·픽크타
 ├ CK        ─ 오버워치CK … (인생게임/명조가챠 = 제목)
 ├ 시네티     ─ (작품 = 제목: 도깨비·슬램덩크·그렌라간)
 ├ 월드컵     ─ (테마 = 제목: J-POP·매점·의상·음식)
 ├ 별별랭킹    ─ —   (월례 시청자 참여 정기컨텐츠. 독립 대분류)
 ├ 소통뱅     ─ —   (본인 방송 시청자 소통 + 다시보기/빅이봤 류)
 └ 기타       ─ —   (조공 등 희귀. 조공=8개월 1회라 흡수)

[수식어]  (modifier · 색 X, 점만 · 콘텐츠 위에 얹힘)
 시참 · 합방 · 대회 · 짧뱅 · 풀트 · 구플(부활)
```

### 배치 근거 (제목 텍스트 8개월 실측)
- **합방**(29): 제목 전부 "누구랑"(여교멤/공겜동/아카데미) → modifier.
- **대회**(21): 릴동파/감왁대전/봉준배 = 게임 위 경쟁 → modifier. (게임 태그 없을 때 단독으로도 찍힘)
- **짧뱅**: 항상 페어(노래뱅+/소통+) → 순수 modifier.
- **풀트**: 풀트래커=장비="어떻게" → modifier. (단독 14회는 *미정비 태그*라 가중치 X)
- **시참**: 시청자 참여 표식 → modifier. **별별랭킹은 시참의 자식이 아니라 독립 content**
  (그래야 "별별랭킹+시참", "게임>버블파이터+시참" 둘 다 시참=modifier 한 역할로 일관).
- **VRChat**: 종겜과 한 번도 동시출현 X(실측), 릴동파(VR올림픽)·모캡 등 → **독립 대분류**(게임 세부 아님).
- **외부출연**: 타스뱅송이 휴뱅과 동시(본인 방송 X) 2회, 토크쇼는 남 토크쇼 출연 → "주체=남" 묶음.

### 세부 = 제목 + 세부태그 **둘 다**
제목 = 시청자 한눈에("버블파이터 시참데이"), 세부태그 = 통계 입자(`게임>버블파이터`).
같은 정보 중복 아님 — 역할 다름. 게임 세부 시드는 제목서 반복된 것부터, 나머진 운영하며 추가.

## 5. 구현 단계 (다음 작업)

- **PR1 — kind 토대**: 마이그레이션 `00xx_tag_kind.sql`(`kind` 컬럼, default content) +
  `BroadcastTag.kind` 타입 + 로더 select. 렌더 영향 0(전부 content 기본).
- **PR2 — 태그 재배치 시드**: 신설(외부출연/노래/별별랭킹) + reparent(토크쇼·타스뱅송→외부출연) +
  kind=modifier 지정(시참·합방·대회·짧뱅·풀트·구플) + 조공→기타. event_tags 연결 보존.
- **PR3 — 색·점 분기**: month.ts 색 함수가 `modifier`는 색 제외(점만). 셀 ≤2색은 content만.
- **PR4 — 피커 그룹**: [콘텐츠]/[수식어] 칸 분리.
- **PR5 — 인사이트**: 컨텐츠 순위/트렌드는 content만 롤업, modifier는 별도 보조 통계.

각 PR: TS+lint+`next build` 통과, 공개/비공개 경계 재확인, commit/push(main).

## 7. 【미래 기획 / 구현 X】 노래방 songbook 연동

> 토리님이 **노래**를 불렀을 때, 그날 **어떤 곡**을 불렀고 곡별로 **본인이 어땠는지**(자평/컨디션/하이라이트
> 등)를 기록·연결하는 기능. 단계적 기획만, 지금 구현 안 함.

참고 레퍼런스:
- https://meloming.com/musicbook  (스트리머 노래방 / 뮤직북)
- https://www.songstudio.live/    (송 스튜디오)

아이디어 메모:
- `노래` 대분류 태그가 붙은 이벤트에 **곡 리스트**(setlist)를 연결: 곡명·아티스트·순서·곡별 코멘트.
- 개별 곡은 태그로 안 만든다(무한·1회성) → **별도 songbook 데이터**(이벤트 1 : 곡 N)로.
- 곡별 "본인이 어땠는지" = 스트리머 자평 필드(공개/비공개 구분 필요 — 비공개 자평은 사적 레이어).
- 위 두 서비스가 곡 메타/링크 소스가 될 수 있음(임베드 or 수동 입력). 공개 노출은 공개 곡 정보만.
- 단계: (1) 이벤트에 텍스트 setlist 메모 → (2) 구조화 곡 테이블 → (3) 곡별 자평·통계("최다 부른 곡")
  → (4) 외부 songbook 연동/임베드.
- **경계 주의**: 비공개 자평/컨디션은 공개 API에 절대 안 나가게(현 public/private 경계 규칙 준수).
