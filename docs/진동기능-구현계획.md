# 진동(햅틱) 기능 — 쉬운 설명 + 단계별 구현 계획

> 작성일: 2026-05-29 · 대상: VIC Schedule Studio
> 같이 보면 좋은 문서: [모션·햅틱·몰입 보고서](motion-haptics-immersion-report.md)
> 이 문서는 **코드를 잘 몰라도 읽을 수 있게** 비유와 우리 앱 상황별 예시로 썼다.
> 핵심 방침: **진동은 Android에서만 진짜로 울리고, 아이폰에선 조용히 넘어간다.** 즉
> "울리면 손맛↑, 안 울려도 화면은 똑같이 잘 돌아간다" — 누구도 불편하지 않게.

---

## 1. 한 줄 요약

일정표를 만질 때 폰을 아주 살짝 **"지잉"** 울려서 *손맛*을 준다. 하트를 누르거나, 일정을
저장하거나, 비공개를 풀 때처럼 "방금 뭔가 됐다"는 느낌을 손끝으로도 전한다. 단, 이건
**보너스**다 — 안 울려도 앱은 평소처럼 완벽히 동작한다.

---

## 2. 왜 "Android만"이고, 왜 "타협"이 필요한가 (쉬운 비유)

웹페이지(우리 앱은 설치형 앱이 아니라 브라우저로 도는 웹앱이다)가 폰의 진동 모터를 켜려면,
폰 제조사가 "문"을 열어줘야 한다.

- **안드로이드폰** 🟢 → 그 문이 **열려 있다**. 웹에서 코드로 진동을 켤 수 있다.
- **아이폰** 🔴 → 애플이 그 문을 **잠가놨다**. 웹에서는 코드로 진동을 **못** 켠다.
  (아이폰 *앱*은 되지만, *웹*은 애플이 막아둠. 이건 우리가 바꿀 수 없는 애플 정책이다.)
- **아이폰의 단 하나 예외** 🟡 → 화면에 **진짜 켜기/끄기 스위치**가 있고, 그걸 사용자가
  *손가락으로 직접 탁* 누르면 — 그때만 아이폰도 살짝 진동한다. (설정 앱에서 토글 누를 때
  손끝에 오는 그 느낌.) 단, 코드로 대신 눌러주는 건 안 통한다(애플이 2026년에 그 방법도 막음).

그래서 **타협**은 이렇게 한다:

> 진동은 "있으면 좋은 보너스"로 취급한다.
> - 안드로이드 유저 → 손맛을 제대로 느낀다.
> - 아이폰 유저 → 평소와 똑같다(진동만 없을 뿐, 불편함 0).
> - 단, **하트·비공개 잠금 같은 "토글"은 진짜 스위치로 만들면** 아이폰 유저도 *그것만은*
>   손끝 진동을 느낄 수 있다 → 이건 나중에 선택적으로(8번 항목).

이 방식의 큰 장점: 기존 화면·동작은 하나도 안 건드리고 진동만 **위에 살짝 얹는** 구조라,
**기능이 깨질 위험이 거의 없다.**

---

## 3. 언제, 어떤 느낌으로 울릴까 — 우리 앱 상황별 예시

진동은 길이(밀리초, 1000ms = 1초)와 리듬으로 "느낌"을 만든다. 우리 앱에 맞춘 표:

| 상황 | 느낌(리듬) | 길이 | 왜 |
|---|---|---|---|
| ❤️ **하트 누르기**(뷰어) | 톡 (한 번) | 12ms | 가장 자주 쓰는 기분 좋은 반응. 짧고 가볍게 |
| 👆 **일정 카드 탭**(수정 열기) | 아주 짧게 틱 | 10ms | "눌렸다"는 즉각 확인 |
| 💾 **일정 저장 성공** | 톡-(쉼)-톡 | 12·40·12ms | "잘 저장됐어요" 하는 안심되는 두 박자 |
| 🗑️ **일정 삭제** | 또렷하게 한 번 | 25ms | 되돌리기 어려운 동작이라 조금 더 분명히 |
| 🔓 **비공개 잠금 풀기 성공** | 부드러운 성공 | 12·40·12ms | 안전하게 들어왔다는 느낌 |
| ❌ **비밀번호 틀림** | 다-다-닥 | 30·40·30·40·30ms | "삐빅, 틀렸어요"의 촉각 버전 |
| ✋ **일정 드래그로 집어들 때** | 톡 | 12ms | "들렸다"는 손맛(나중 단계) |
| 📅 **월 넘기기**(스와이프) | 아주 약하게 틱 | 8~10ms | 페이지가 넘어갔다는 가벼운 확인(나중 단계) |

**원칙: 짧게, 꼭 필요할 때만.** 진동이 길거나 너무 자주 울리면 거슬려서 오히려 몰입을 깬다.
"있는 듯 없는 듯, 기분 좋은 정도"가 목표다.

---

## 4. 꼭 지킬 안전장치 — "자물쇠 3개"

진동을 울리기 전에, 매번 **세 개의 자물쇠**를 모두 통과해야만 울린다:

1. 🔒 **이 폰이 진동을 지원하나?** → 안 되면(아이폰 등) **그냥 조용히 넘어간다.** 에러도 안
   나고, 화면도 멀쩡하다.
2. 🔒 **사용자가 진동을 켜뒀나?** → 설정에서 끌 수 있다. 진동을 싫어하는 사람도 배려.
3. 🔒 **과하지 않나?** → 짧은 패턴만, 꼭 필요한 순간에만.

이 세 자물쇠를 **한 곳(스위치보드)** 에 모아두는 게 핵심이다(다음 항목).

## 5. 핵심 아이디어 — "진동 스위치보드" 하나 만들기

집의 전기 배선을 생각해보자. 방마다 콘센트가 따로 벽 안에서 외부 전선과 연결돼 있으면,
나중에 뭐 하나 바꾸려면 집을 다 뜯어야 한다. 그래서 **두꺼비집(배전반)** 을 둔다 — 전기는
전부 거기를 거친다.

진동도 똑같이 한다. 앱 곳곳에서 "여기서 진동!" 하고 직접 모터를 켜는 게 아니라, **`haptics`라는
작은 파일 하나**를 거치게 한다. 그러면:

- 자물쇠 3개를 **한 곳에서** 검사한다(중복 없음, 빠뜨림 없음).
- 아이폰 대응, 설정 연동을 **한 번만** 짜두면 전체에 적용된다.
- 나중에 "진동 좀 더 약하게"처럼 바꿀 때 **그 파일 한 곳만** 고치면 된다.

실제로는 이렇게 생긴 작은 파일이다(주석을 친절하게 달아둠 — 코드를 몰라도 흐름만 보면 된다):

```ts
// lib/ui/haptics.ts  — 모든 진동이 거쳐 가는 "두꺼비집"

const 설정키 = "vic.haptics";

// [자물쇠 1·2] 이 폰이 진동되나? + 사용자가 켜뒀나?
function 진동켜짐() {
  if (!("vibrate" in navigator)) return false; // 아이폰 등 → 조용히 false
  return localStorage.getItem(설정키) !== "off"; // 사용자가 끄지 않았으면 켜짐(기본 ON)
}

// 실제로 울리는 곳 — 단 한 군데
function 울려라(패턴) {
  if (!진동켜짐()) return;        // 자물쇠 통과 못 하면 그냥 끝(에러 없음)
  try { navigator.vibrate(패턴); } catch {} // 만약을 대비해 안전하게 감쌈
}

// 상황별 "느낌"에 이름을 붙여 둔다 — 앱에서는 이 이름만 부르면 된다
export const 톡 = () => 울려라(12);            // 하트, 탭, 드래그 집기
export const 성공 = () => 울려라([12, 40, 12]); // 저장·잠금풀기 성공
export const 삭제 = () => 울려라(25);          // 삭제
export const 에러 = () => 울려라([30, 40, 30, 40, 30]); // 비번 틀림
```

> 앱 다른 곳에서는 그냥 `톡()` `성공()` 처럼 **이름만** 부른다. (실제 코드에선 영어 이름
> `hapticTick()`·`hapticSuccess()` 등을 쓰지만 의미는 똑같다.) 자물쇠 검사는 이 파일이
> 알아서 한다.

## 6. 사용자 설정 — "진동 켜기/끄기" 토글 하나

- 진동을 끄고 싶은 사람을 위해 **on/off 토글 하나**를 둔다.
- 기본값은 **켜짐**(아이폰은 어차피 무동작이라 켜져 있어도 영향 없음).
- 위치: 모바일은 *컴팩트가 생명*이니 라벨은 짧게("진동"), 역할 바/설정 근처에 작게.

---

## 7. 단계별 구현 순서 (작게, 안전하게, 되돌리기 쉽게)

한 번에 다 하지 않는다. **작은 조각으로 나눠** 매 단계마다 "빌드 통과 → 안드로이드 실제 폰에서
확인 → 커밋"을 반복한다. 그래야 문제가 생겨도 어디서 생겼는지 바로 안다.

| 단계 | 무엇을 | 위험 | 확인 방법 |
|---|---|---|---|
| **0단계** | 두꺼비집(`haptics.ts`) 파일 만들기. 아직 아무 데서도 안 부름 | 거의 0 | 빌드만 통과하면 됨 |
| **1단계** | 가장 자주·안전한 곳에 연결: ❤️하트, 👆일정 탭, 💾저장, 🗑️삭제 | 낮음 | 안드로이드폰에서 각각 눌러보며 "지잉" 확인 |
| **2단계** | 🔓잠금 풀기 성공/실패, ✋드래그 집기 | 낮음 | 비번 맞게·틀리게 둘 다 테스트 |
| **3단계** | "진동 켜기/끄기" 설정 토글 노출 + 강도 미세조정 | 낮음 | 껐을 때 진짜 안 울리는지 확인 |
| **(선택) 4단계** | 📅월 스와이프 진동 등 더 얹기 | 낮음 | — |

각 단계는 **독립적**이다. 1단계만 하고 멈춰도 앱은 완벽히 잘 돌아간다. 마음에 안 들면 그
단계만 빼면 된다(전부 "얹기"라서 떼어내기 쉬움).

---

## 8. (선택·나중에) 아이폰도 살짝 챙기는 방법

5~7단계와 별개로, **하트와 비공개 잠금 토글을 "진짜 스위치"로 만들면** 아이폰 유저도 *그
두 가지만은* 손끝 진동을 느낄 수 있다(2번의 🟡 예외). 다만 하트 모양(어항 하트)의 속을
스위치 구조로 살짝 바꿔야 하므로, 기존 하트 동작(누른 기록 저장·빨강 채움 애니메이션)이
안 깨지는지 따로 확인이 필요하다. → **급하지 않으니 나중에 따로** 진행 권장.

---

## 9. 이 계획이 "안 깨지는" 이유 (안심 포인트)

- 진동은 기존 화면/저장/권한 로직을 **하나도 바꾸지 않고** 위에 얹기만 한다.
- 아이폰·진동 미지원 기기·설정에서 끈 사람 → **자동으로 조용히** 지나간다(에러 없음).
- 모든 진동이 **한 파일**을 거치므로, 문제가 생겨도 그 파일만 보면 된다.
- 단계가 작고 독립적이라, 언제든 멈추거나 되돌리기 쉽다.

---

## 10. 시작 전에 정해주면 좋은 것 (질문 거리)

1. 진동 기본값을 **켜짐**으로 둘까(추천), 꺼짐으로 둘까?
2. 설정 토글을 **어디에** 둘까 — 모바일 역할 바 근처? 별도 설정 영역?
3. 1단계 4곳(하트·탭·저장·삭제) 중 **하트만 먼저** 해보고 느낌을 볼까, 4곳 한 번에 갈까?
4. 진동 세기 표(3번)의 길이값이 적당한지는 **안드로이드 실제 폰에서** 같이 맞춰보면 좋다.
