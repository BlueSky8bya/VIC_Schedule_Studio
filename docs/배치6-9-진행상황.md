## ⏸ 보류(블라인드 진행 위험 — 설계 결정/검증 필요)

이 항목들은 **DB 스키마 변경·전역 구조·되돌리기 어려운 변경**이라, 토리님 확인 없이 자동으로
넣으면 기존 기능을 깰 위험이 큼. 다음에 하나씩 같이 진행 권장.

- **#13 동시 수정 충돌 보호** — `events.updated_at`(또는 버전) 비교를 쓰기 경로 전반에 추가하고
  충돌 시 "남이 먼저 바꿈" UI를 띄워야 함. 서버 액션·로더·낙관적 큐를 모두 건드리는 작업이라
  회귀 위험. 별도 세션에서 마이그레이션 + 단계별 검증 권장.
- **#22 레이어 목록** — 스티커/글자를 목록(이름·숨김·잠금·순서)으로 관리하는 신규 패널. 잠금은
  이미 있음(0031). 숨김·순서·목록 UI는 새 상태·DB 필드(z-order/hidden)·드래그 정렬이 필요한 큰
  기능. 단독 배치로 진행 권장.
- **#26 시선 중심 1개** — 화면별로 비핵심 요소 채도·대비를 낮추는 전역 디자인 패스. 주관적이라
  화면마다 토리님 확인하며 다듬는 게 안전(잘못 낮추면 정보가 안 보임).
- **#32 zoom 제거** — 현재 `studio-shell.css`는 큰 화면 studio에 `zoom`을 **의도적으로 유지**
  (주석 참조: 이 앱에선 드래그/캡쳐/sticky를 안 깨고, 제거하면 칸이 거대해지는 '엉성함'이 되돌아옴).
  제거하려면 zoom 대신 컨테이너 쿼리/스케일 기반 반응형으로 **갈아엎는 큰 작업**이 필요 → 보류.
- **#33 점진적 로딩** — 공개 달력 먼저 그리고 스티커·통계를 뒤따라 로딩. 데이터 로더 분리(SSR
  페이로드 쪼개기 + 클라이언트 지연 로드)라 구조 변경 큼. 현재도 스켈레톤은 있음. 별도 진행 권장.
