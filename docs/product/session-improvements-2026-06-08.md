## 연구로 검증된 설계 (벤치마킹)

### 1. 낙관적 UI + 순서 보장 쓰기 큐 (이번에 구현한 enqueueWrite)
- 업계 표준과 일치: "낙관적으로 즉시 반영 → 순서 있는 큐로 동기화, 의존 연산
  (생성 후 수정/삭제)은 순서 보장 필수." 내 구현 = 전역 직렬 체인 + temp→real
  영구 매핑이 정확히 이 패턴.
- **다음 단계(안전, 미구현)**: "성공 신호 전에 outbox를 디스크(localStorage)에
  먼저 적어라(persist-first)." 지금은 in-memory 큐 + keepalive fetch라 탭 크래시
  중 유실 가능. localStorage outbox로 올리면 크래시에도 안전. (중간 난이도, 별도
  세션 권장)
- 출처: [LogRocket offline-first 2025](https://blog.logrocket.com/offline-first-frontend-apps-2025-indexeddb-sqlite/),
  [beefed: queueing & sync](https://beefed.ai/en/offline-first-queueing-sync)

## 우선순위 다음 작업 (토리 깨면 같이 결정)
1. **떡밥 즉시공개 실사용 확인** — 미래 시각으로 떡밥 하나 만들어 시크릿창에서
   카운트다운→그 순간 펼쳐지는지 눈으로. (코드/서버 경로는 검증됨)
2. **비로그인 집계 실데이터 확인** — 배포 후 비로그인 방문이 쌓이면 인사이트
   방문 패널 역할 막대에 '비로그인' 등장 확인.
3. (선택) outbox localStorage 영속화 — 크래시 안전.
4. (선택) 떡밥 드립 힌트(색·수수께끼) — 기대감 단계화.
5. 이전에 합의한 **관심 배지 상대순위 전환**(참여 볼륨 늘면).
