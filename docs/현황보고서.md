# VIC Schedule Studio 현황 보고서

> 코드를 몰라도 읽을 수 있도록 쉬운 말로 정리했습니다.
> 작성일: 2026-05-21

## 0. 이 앱이 뭔가요? (한 문장)

빅토리님이 방송 일정을 직접 짜고, **시청자는 예쁜 월간 일정표만 구경**하고,
**매니저·작업자는 비밀번호로 "숨겨진 일정"까지 확인**할 수 있는 스트리머 전용 일정표 웹앱입니다.

가장 중요한 약속은 딱 하나입니다:

> **시청자에게는 절대 비밀 일정(엠바고/작업/개인)이 보이면 안 된다.**

이 보고서는 (1) 앱을 켜려면 필요한 "열쇠(key)"들, (2) 지금까지 만든 것, (3) 앞으로 만들 것 순서로 설명합니다.

---

## 1. 앱을 켜려면 필요한 "열쇠(Key)" 목록

앱은 외부 서비스 두 개의 도움을 받습니다. 그 서비스에 들어가기 위한 비밀번호 같은 값들이 필요합니다.
이 값들은 `.env` 라는 비공개 설정 파일에 적어 넣습니다. (절대 외부에 공유하면 안 됩니다.)

### 1-1. Supabase (데이터 저장 + 로그인 담당 서비스)

> Supabase = 일정 데이터를 보관하는 창고 + 로그인 문지기 역할을 하는 무료 서비스입니다.
> [supabase.com](https://supabase.com) 에서 프로젝트를 하나 만들면 아래 값들이 자동으로 발급됩니다.

| 열쇠 이름 | 쉬운 설명 | 어디서 구하나 | 지금 채워졌나? |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 우리 창고 주소 | Supabase 프로젝트 → Settings → API | ❌ 비어 있음 |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 일반 손님용 출입증 (읽기용) | 같은 화면 | ❌ 비어 있음 |
| `SUPABASE_SERVICE_ROLE_KEY` | 관리자 마스터 키 (절대 외부 노출 금지) | 같은 화면 | ❌ 비어 있음 |
| `SUPABASE_STORAGE_BUCKET` | 스티커 이미지 보관함 이름 | 직접 정함 (이미 `vic-schedule-assets`로 적혀 있음) | ✅ 채워짐 |

### 1-2. Google 로그인 (구글 계정으로 로그인하기)

> 빅토리님·매니저·작업자가 **구글 계정으로 로그인**합니다. 이를 위해 구글에서 허락을 받아야 합니다.

| 항목 | 쉬운 설명 | 어디서 구하나 |
|---|---|---|
| Google OAuth Client ID | 구글이 우리 앱에게 발급하는 신분증 번호 | [Google Cloud Console](https://console.cloud.google.com) → OAuth 동의 화면 |
| Google OAuth Client Secret | 그 신분증의 비밀번호 | 같은 곳 |

⚠️ 이 두 값은 `.env` 파일이 아니라 **Supabase 관리 화면**(Auth → Providers → Google)에 입력합니다.
(설정 파일에도 안내 주석이 적혀 있습니다.)

### 1-3. 우리 앱 자체 설정값

| 열쇠 이름 | 쉬운 설명 | 지금 값 |
|---|---|---|
| `OWNER_EMAIL` | **빅토리님(주인)의 이메일**. 이 이메일로 로그인한 사람만 일정을 편집할 수 있음 | `blackspace665@gmail.com` (지금은 개발용, 실제 운영 전 빅토리님 계정으로 교체 필요) |
| `NEXT_PUBLIC_SITE_URL` | 앱 주소 | `http://localhost:3000` (지금은 내 컴퓨터용, 배포 시 실제 주소로 교체) |
| `PRIVATE_LAYER_UNLOCK_SECRET` | 비공개 레이어 잠금해제 기능에 쓸 보안 암호 | ❌ 비어 있음 |

### 📌 정리: 지금 당장 채워야 할 열쇠 (우선순위 순)

1. **Supabase 3종** (`URL`, `ANON_KEY`, `SERVICE_ROLE_KEY`) → 이게 있어야 데이터 저장·로그인이 작동
2. **Google OAuth 2종** → 로그인 기능을 위해
3. **`PRIVATE_LAYER_UNLOCK_SECRET`** → 비공개 레이어 기능 만들 때
4. **`OWNER_EMAIL` 최종 확정** → 운영 시작 전 빅토리님 실제 계정으로

> 💡 지금은 이 열쇠들이 비어 있어도 앱은 **샘플(가짜) 데이터로 화면 미리보기**가 됩니다.
> 실제 데이터 저장·로그인을 켜려면 위 열쇠들을 채워야 합니다.

## 2. 지금까지 만들어진 것 ✅

비유하자면 **"집의 뼈대와 안전장치는 다 세웠고, 일부 방은 가구까지 들어왔다"**는 상태입니다.

### 2-1. 가장 중요한 안전장치 (완성, 검증됨)

이 앱의 1순위 약속인 **"시청자에게 비밀 일정이 새지 않는다"**가 실제로 작동합니다. 자동 테스트로도 확인됨.

- ✅ **시청자 화면에는 비밀 일정이 아예 전달되지 않음** — 화면에서 가리는 게 아니라, 데이터를 보내줄 때부터 비밀 항목을 빼고 보냅니다. (가장 안전한 방식)
- ✅ **편집 권한은 빅토리님(owner)만** — 매니저·작업자는 봐도 수정은 불가능.
- ✅ **비공개 토글 버튼은 시청자에게 안 보임** — 매니저·작업자·주인에게만 보임.
- ✅ **개인 전용 일정(owner_private)은 빅토리님 본인만** 볼 수 있음.
- ✅ **"⚠ 비공개 레이어 표시 중" 경고 문구** — 비밀 일정을 켠 사람에게만 표시 (방송 사고 방지).
- ✅ 자동 테스트 3종 + 코드 검사 모두 **통과**.

### 2-2. 화면 (눈에 보이는 부분)

| 화면 | 상태 | 설명 |
|---|---|---|
| 시청자용 공개 일정표 | ✅ 작동 | 월간 달력, 일정, 태그 색상이 보임 |
| 스튜디오(편집 화면) | ✅ 작동 | 달력에서 날짜 클릭 → 일정 추가/수정/삭제 UI, 태그 선택, 비공개 토글 버튼 |
| 로그인 화면 | ✅ 화면 존재 | 실제 로그인 연결은 열쇠 입력 후 작동 |
| 포스터(이미지 저장용) 화면 | 🟡 일부 | 화면 틀은 있으나 PNG 저장 기능 미완성 |

### 2-3. 기본 데이터 (계획서대로 정확히)

- ✅ 방송 태그 **10개** 전부 (휴뱅·합뱅·대형서버·풀트뱅·잔잔뱅·종겜뱅·월드컵뱅·날먹뱅·노래뱅·기대컨)
- ✅ **휴뱅 = 회색** (약속대로)
- ✅ 날짜 칸 대표 색상 **최대 2개 + "+N" 표시** 규칙
- ✅ 모든 시간 **한국시간(KST)** 고정

### 2-4. 데이터 창고 설계도 (작성 완료, 아직 미적용)

- ✅ 데이터를 어떻게 보관할지 **설계도(테이블 11개)** 와 **출입 통제 규칙(RLS)** 이 글로 다 작성됨.
- ⚠️ 단, 아직 실제 Supabase 창고에 이 설계도를 **"적용(설치)"하지는 않은** 상태. (열쇠가 없어서)

## 3. 앞으로 만들어야 할 것 ❌

비유하면 **"가구가 아직 안 들어온 방들"** 과 **"전기·수도 본선 연결"** 이 남았습니다.

### 3-1. 🔴 가장 시급 — 진짜 데이터 연결 (전기·수도 본선)

지금은 모든 일정이 **샘플(가짜) 데이터**입니다. 즉, 스튜디오에서 일정을 저장해도 **새로고침하면 사라집니다.**

- ❌ Supabase 창고에 설계도 설치하기
- ❌ 앱이 진짜 창고에서 일정을 읽고/저장하게 연결
- ❌ 구글 로그인 실제 작동시키기

> 이게 되어야 "실제로 쓰는 앱"이 됩니다.

### 3-2. 🔴 비공개 레이어 잠금해제 (핵심 기능, 현재 껍데기만)

매니저·작업자가 **비밀번호를 넣어 숨은 일정을 보는** 기능입니다.

- ❌ 비밀번호 입력 → 맞는지 확인 → 잠금해제 (현재는 "준비 안 됨" 메시지만 나옴)
- ❌ 비밀번호 변경 시 기존 잠금 자동 무효화
- ⚠️ 지금은 토글 버튼이 **비밀번호 없이도 그냥 켜짐** (화면 시연용 임시 상태)

### 3-3. 🟡 아직 안 만든 기능 화면들

| 기능 | 설명 | 상태 |
|---|---|---|
| 업 도움 캠페인 관리 | 숲 "업 도움" 기간 등록, 시청자 참여 버튼 | ❌ 폴더만 있고 화면 없음 |
| 스티커 꾸미기 | PNG 올려서 일정표 장식 (크기·회전·투명도) | ❌ 미구현 |
| 포스터 PNG 저장 | 일정표를 이미지로 내려받기 | ❌ 미구현 |
| 태그 이름·색상 수정 | 빅토리님이 태그 직접 편집 | ❌ 화면 없음 |
| 매니저·작업자 관리 | 신뢰 멤버 추가/삭제 | ❌ 화면 없음 |

### 3-4. 🟢 마지막 단계 — 품질 점검

- ❌ 다양한 상황에서 비밀 일정이 안 새는지 자동 테스트 확대
- ❌ 모바일 화면 정리
- ❌ 포스터 이미지가 항상 똑같이 예쁘게 나오는지 점검

## 4. 한눈에 보는 진행률

```
1. 기획·문서·폴더 구조        ██████████ 100%  ✅ 완료
2. 데이터 설계도 + 안전규칙    █████████░  90%  ✅ 작성완료(설치만 남음)
3. 시청자 공개 일정표          ████████░░  80%  ✅ 대부분 작동
4. 빅토리님 편집 스튜디오       ███████░░░  70%  🟡 화면OK, 저장연결 남음
5. 비공개 레이어 잠금해제       ██░░░░░░░░  20%  ❌ 껍데기만
6. 태그·색상 설정 화면         ███░░░░░░░  30%  🟡 색상로직만
7. 업 도움 캠페인              █░░░░░░░░░  10%  ❌ 거의 없음
8. 스티커·포스터 출력          █░░░░░░░░░  10%  ❌ 거의 없음
9. 진짜 데이터(DB) 연결         ░░░░░░░░░░   0%  ❌ 미착수 (가장 시급)
10. 최종 품질 점검             █░░░░░░░░░  10%  🟡 기본 테스트만
```

**전체적으로:** 가장 어렵고 중요한 **"안전 뼈대"는 완성**되었고,
이제 **"진짜 데이터 연결"과 "남은 기능 방들"**을 채워 넣는 단계입니다.

## 5. 추천하는 다음 순서

1. **Supabase 가입 → 열쇠 3개 발급 → `.env`에 입력** (전기 연결)
2. **데이터 설계도 창고에 설치** (`db/` 폴더의 파일 실행)
3. **구글 로그인 연결** (열쇠 입력)
4. **앱이 가짜 데이터 대신 진짜 창고를 보도록 연결**
5. **비공개 레이어 잠금해제 기능 완성**
6. 그 다음에 업 도움 → 스티커 → 포스터 순서로 기능 추가

> 💬 "어디부터 시작할까요?"에 대한 답: **1번(Supabase 열쇠 발급)** 부터 하면 됩니다.
> 열쇠만 주시면 그 다음 연결 작업은 코드로 진행할 수 있습니다.
