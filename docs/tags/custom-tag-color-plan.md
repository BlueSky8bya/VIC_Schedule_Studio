# 태그 색 커스텀화 계획 — 임의 색 + 톤 옵션 + 무늬 제거 + 자동 글자 가독성

작성: 2026-07-18 · 상태: **계획(미구현)** · 관련: [[tag-tier-plan]], `lib/tags/color-gen.ts`,
`lib/calendar/month.ts`, `components/tags/tag-legend-editor.tsx`, `app/globals.css`

## 왜 (토리님·개발자 요청 3건)

1. **고정 팔레트의 한계** — 콘텐츠 12색 / 형식 9색으로 색이 고정. 태그가 그 수를 넘으면
   "색 지정 안 되는 태그(기타 같은)"가 생김. 지우기보다 수정을 권하는 정책이라 방치 중.
2. **체크무늬 때문에 글자가 잘 안 보임** — 콘텐츠 카드에 텍스처(대각선/점/격자)가 깔려
   글자와 싸운다. 단일 색으로 바꾸고 싶음.
3. **색을 원하는 값으로 바꾸고 싶음** — Clip Studio식 색환(HSV 원형 좌표) 피커로 자유 지정.

추가로 토리님 요청(색-의미 매핑): **노란색=노력/소통(풀트뱅·소통뱅), 파란색=합방, 빨간색=게임**
같은 결이면 좋겠다. → 지금 DB에 토리님이 직접 넣은 색을 보면 이미 그 경향이 있다(아래 §7).

## 현재 구조 (읽고 확인한 사실)

- **저장**: `color_palette` 테이블(`key`, `bg_color`, `text_color`, `border_color`, `sort_order`).
  태그(`broadcast_tags.color_key`)가 팔레트 key를 참조. 세부 태그는 부모 대분류 색 상속.
- **커스텀 색은 이미 부분 존재**: `gen-*` 접두사 key. 새 태그 추가 시 `generateTagColor()`가
  기존과 hue ≥28° 떨어진 파스텔을 만들어 `color_palette`에 새 행으로 INSERT
  (`lib/schedules/tag-actions.ts`). 즉 **임의 hex를 저장할 배관은 이미 있다.**
- **무늬**: `app/globals.css`에서 `[data-color="key"]` / `[data-color^="gen-diag-"]` 등으로
  `background-image: repeating-linear-gradient(...)`. 무늬의 **유일한 목적 = 비슷한 파스텔끼리
  구분**(고정 팔레트라 색이 부족해 무늬로 갈랐다). → **색이 자유로워지면 무늬는 불필요**(사용자
  통찰 정확). `isPatternColor(key)`가 콘텐츠(무늬)/형식(단색) 풀을 가르는 데도 쓰임 — 이걸 걷어내야.
- **글자 가독성은 이미 근거 기반으로 구현됨** (`lib/calendar/month.ts:eventInkStyle`):
  - WCAG 2.1 상대휘도로 대비 계산. 태그 글자색이 AA(4.5:1) 미달이면 흑/백 중 대비 높은 쪽으로 교정.
  - 대비 구간별 굵기(cr≥7→700, ≥4.5→800, 그 미만→900). 무늬 색이면 +100 굵기 + 바탕색 헤일로.
  → **이 함수가 커스텀 색 계획의 핵심 자산.** 어떤 hex가 와도 최적 글자를 이미 뽑는다.

## 연구 근거 (외부)

### A. 임의 배경 위 글자 — WCAG 2 vs APCA
- **WCAG 2.1**: 상대휘도 대비비(4.5:1 = 본문 AA). 법적·자동검사 표준. 단 **어두운 색끼리 대비를
  과대평가**하고 폰트 크기·굵기·명암 극성(밝은 글자/어두운 글자 비대칭)을 무시.
- **APCA**(WCAG 3 초안): 인지 대비 Lc(±106). 폰트 크기·굵기·극성 반영. 파스텔/중간톤에서 훨씬 정확.
- **채택 방침**(업계 권고 그대로): **WCAG 2.1 AA를 하한(법적·기계 검증)** 으로 지키고, 그 위에
  **APCA로 굵기·헤일로를 튜닝**한다. 즉 "통과/실패는 WCAG로, 실제 읽힘은 APCA로." 지금
  `eventInkStyle`의 굵기 밴딩을 APCA Lc 기반으로 승급하면 커스텀 색 전반에서 더 안정적.
  출처: Capellic, weableColor, Myndex(SAPC-APCA).

### B. 색 공간 — 왜 HSL이 아니라 HSLuv인가
- 순수 HSL/HSV는 **지각적으로 불균일**: 같은 L이라도 노랑은 밝고 파랑은 어둡게 보인다. 사용자가
  "톤 유지하고 hue만 돌리기"를 하면 색마다 밝기가 널뛰어 카드가 제각각이 된다.
- **HSLuv**(CIELUV 기반, 인간 친화 HSL): 같은 lightness면 **지각 밝기가 같다.** 커스텀 테마에서
  "채도·명도 고정 + hue만 회전 → 대비비가 일정한 팔레트"를 만들기 쉽다.
- **파스텔 vs 비비드**: HSLuv에 pastel 변형이 있음(채도를 낮춰 왜곡 없는 chroma 사각형). 톤 프리셋
  (파스텔=고명도·저채도, 비비드=고채도)을 HSLuv 밴드로 정의하면 색마다 균일하게 적용된다.
  출처: hsluv.org, Boronine, Guavapay(Medium), Programming Design Systems.

### C. 범주 색 구분 한계
- 사람이 안정적으로 구별하는 색상 범주는 대략 **8~12개**. 콘텐츠 대분류가 이 근처라 hue만으로
  구분 가능(무늬 불필요). 단 **색약 사용자**를 위해 피커에서 "기존 태그와 hue가 너무 가깝다" 경고 +
  선택 시 색약 시뮬레이션 힌트를 두는 게 안전(무늬를 걷어내는 대신 이 안전망).

## 제안 설계

### 1) 데이터 모델 — 태그가 자기 색을 갖는다 (팔레트 종속 탈피)
`broadcast_tags`에 색을 직접 싣는다(대분류만; 세부는 상속 유지):
```
ALTER TABLE broadcast_tags
  ADD COLUMN bg_hex   text,             -- 사용자가 고른 배경(HSLuv→hex). null이면 기존 color_key 폴백
  ADD COLUMN tone     text DEFAULT 'soft'; -- 'pastel' | 'soft' | 'vivid' | 'deep' (톤 프리셋)
```
- `text_hex`/`border_hex`는 **저장하지 않고 렌더에서 파생**(단일 진실 소스 = bg + tone).
  파생 함수는 이미 있는 `eventInkStyle`를 확장해 담당(글자색·굵기·헤일로) + 보더는 bg에서
  HSLuv lightness −18% 정도로 자동.
- 기존 `color_key`/`color_palette`는 **폴백으로 유지**(마이그레이션 무중단). `bg_hex`가 있으면
  그걸 쓰고 없으면 팔레트. 형식(modifier) 점 색도 같은 `bg_hex`로 통일 가능.
- 장점: "색 12개 고정" 소멸(요청 1 자동 해결), 팔레트 orphan 정리 로직 불필요.

### 2) 무늬 제거 (요청 2)
- 콘텐츠 카드 = **단색**. `app/globals.css`의 `[data-color^="gen-*"]`·`indigo/mint/sky` 무늬
  규칙 삭제, `.evt-pat`(2색 무늬 오버레이) 제거, `eventInkStyle`의 `isPatternColor` 분기 삭제.
- `isPatternColor`로 콘텐츠/형식 풀을 가르던 것 → **kind로만** 가른다(이미 `kind` 필드 존재).
- 2색 카드(대분류 2개)는 무늬 없이 **HSLuv 그라데이션 반반**으로만 표현(경계 = 카드 가운데).
- 결과: 글자-배경 싸움 사라짐, 캡처(PNG)도 단순해짐.

### 3) Clip Studio식 색 피커 (요청 3)
새 컴포넌트 `components/tags/color-wheel.tsx`:
- **HSLuv 색환**: 바깥 링 = hue(각도), 안쪽 삼각/사각 = 채도·명도(좌표). Clip Studio와 동일 UX.
- **톤 프리셋 행**: `파스텔 / 부드럽게 / 선명 / 깊게` — HSLuv (S,L) 밴드로 정의. hue를 고르면 톤이
  (S,L)을 채워 균일한 결. (예: pastel=S70·L88, soft=S78·L84, vivid=S82·L70, deep=S72·L50+흰글씨.)
- **실시간 미리보기**: 고른 색 위에 실제 일정 카드(제목+소제목)를 렌더하고, 파생된 글자색·굵기와
  **대비 배지**(WCAG 비 + APCA Lc, AA 통과 여부)를 같이 보여준다 → 토리님이 읽힘을 즉시 확인.
- **안전망**: 기존 콘텐츠 태그와 hue가 <20°면 "○○ 태그와 비슷해요" 경고 + 색약 미리보기 토글.
- 좌표/링은 포인터(마우스+터치) 공통. 기존 드래그 물리처럼 `--poster-scale` 무관하게 히트영역 확보.
- `tag-legend-editor.tsx`의 고정 스와치 그리드를 이 피커 트리거(현재 색 원 클릭 → 팝오버)로 교체.

### 4) 자동 글자 — APCA 튜닝 (요청 2의 근본)
`eventInkStyle` 승급:
- 흑/백 폴백은 유지하되, **동색 진한 글씨**(HSLuv 같은 hue, L 25~32%)를 1순위로 시도해 브랜드감
  유지 → AA(WCAG)와 APCA Lc(본문 ≥75 목표) 둘 다 통과하는 가장 진하지 않은 글씨를 고른다.
- 굵기: APCA Lc 밴드로(Lc≥90→650, 75~90→720, 60~75→820, 그 미만은 색 자체를 재교정). 무늬가
  사라지므로 +100/헤일로 분기는 제거.
- 톤='deep'(진한 배경)이면 흰 글씨 + 얇은 굵기로 자동 전환(극성 반영 = APCA의 핵심 이점).

### 5) 톤/다양성 옵션 (요청 확장)
- 톤 프리셋(§3)으로 "같은 hue라도 파스텔/선명/깊게"를 구분 축으로 추가 → 색이 부족하다는 느낌 해소.
- 추후: 대분류는 hue, 세부는 **같은 hue의 명도 계단**(상속을 색 대신 밝기 변주로) 옵션 — 색약에도 강함.

### 6) 마이그레이션·롤아웃 순서 (무중단)
1. 파생 함수(`deriveTagColors(bgHex, tone)`) + APCA 유틸을 `lib/tags/`에 추가(순수 모듈, 테스트 우선).
2. `eventInkStyle`를 파생 함수로 갈아끼우되 **기존 팔레트 색이면 동일 결과**가 나오는지 스냅샷 테스트.
3. 컬럼 추가 마이그레이션(`bg_hex`/`tone`, nullable) — 읽기는 폴백이라 이 시점엔 렌더 불변.
4. 피커 UI 도입 → 저장 시 `bg_hex`/`tone` 기록. 무늬 CSS 제거(콘텐츠 단색화)는 이 배포에 함께.
5. (선택) 기존 태그의 `color_key`→`bg_hex` 백필 스크립트(팔레트 hex 그대로 복사) → 팔레트 종속 완전 탈피.

### 7) 토리님 색-의미 매핑 (지금 DB 경향 + 목표)
스크린샷/`FAMILIES` 기준 현재 경향(토리님이 직접 지정):
- **노랑/주황**(hue ~40~50): 소통, 풀트 → "노력·소통" 결. **← 토리님 목표와 일치.**
- **파랑**(~208): 합방, (형식)카페보기·오픈런. **← 목표와 일치.**
- **빨강**(~0): 게임, (형식)VRChat. **← 목표와 일치.**
- 청록/민트: 타스뱅송·시네티·모캡. 보라/남색: CK·핀볼·연습. 분홍: 서버·대회. 초록: 월드컵·리캡·소통뱅.

→ 제안: 피커 색환에 **의미 hue 앵커**(선택적 가이드)를 얹는다 — "노력·소통🟡 / 합방🔵 / 게임🔴"
   구역에 은은한 라벨. 강제는 아님(자유 지정 유지), 새 태그 만들 때 결을 안내하는 용도.
   백필 시 이 앵커에 맞춰 기존 색을 살짝 정렬해줄 수도 있음(토리님 확인 후).

## 리스크·주의
- **공개 경계**: 색은 공개 데이터(포스터에 이미 노출) → `public-loader` DTO에 `bgHex`/파생색 추가해도
  비공개 누출 아님. 단 파생은 서버/클라 공유 순수 모듈로(포스터·꾸미기·편집실 동일 결과 = 스티커 지오 불변).
- **캡처(PNG)**: 무늬 제거로 오히려 단순·안정. 파생 글자색은 인라인 style이라 html2canvas 그대로.
- **색약**: 무늬라는 비색상 단서를 없애므로 §C 안전망(hue 근접 경고 + 시뮬)로 보완 필수.
- **성능**: HSLuv 변환은 카드마다 아님 — 태그 수(≤대분류 십수 개)만큼만, 렌더 시 메모.
- **되돌리기**: 폴백 유지라 `bg_hex`를 비우면 즉시 옛 팔레트 색으로 복귀(안전).

## 결정 (2026-07-18 합의)
1. **글자색 = 자동.** 브랜드 동색 진한 글씨 우선, 파생만(수동 오버라이드 없음). `eventInkStyle` 재사용·승급.
2. **무늬 = 전면 제거, 콘텐츠 단색.** 색약 대비는 피커의 hue 근접 경고 + 색약 미리보기로만.
3. **톤 = 프리셋 4단**(파스텔/부드럽게/선명/깊게), HSLuv (S,L) 밴드. 자유 슬라이더는 안 넣음.
4. **대비 하한 = WCAG AA 강제 + 자동 보정.** 저장 시 파생 글자가 AA 미달이면 색을 자동 교정
   (자동 글자색 방침이라 사실상 항상 통과 — 극단적 커스텀 bg만 톤 조정). 경고만으로 넘기지 않는다.
5. **백필 = 팔레트 hex 그대로 복사.** 렌더 불변이 최우선. §7 의미 앵커 정렬은 별건으로, 토리님이
   원하면 나중에 피커에서 하나씩(자동 일괄 이동 안 함).

## 구현 착수 순서 (위 결정 반영)
Phase 1 — 순수 모듈(테스트 우선, 렌더 불변 확인): `lib/tags/color-derive.ts`
  (`deriveTagColors(bgHex, tone)` = bg→글자색·굵기·보더, HSLuv + APCA/WCAG). 기존 팔레트 색
  입력 시 현재와 동일 결과 스냅샷. `eventInkStyle`를 이 함수로 교체.
Phase 2 — 마이그레이션 `bg_hex`/`tone`(nullable, 폴백). 렌더 불변.
Phase 3 — 색환 피커 + 무늬 CSS 제거(콘텐츠 단색화) 동시 배포. 저장 경로에 bg_hex/tone 기록.
Phase 4 — (선택) color_key→bg_hex 백필 스크립트.
각 Phase 끝 = tsc+lint+build+공개경계 재확인 → 커밋/푸시.
