# 2계층 태그 + 콘텐츠 다중 태그 + 계층 필터 — 구현 계획서

작성: 2026-06-03 · 상태: 결정 확정, 단계 구현 중

## 1. 문제 (근본)

- **색은 ~12개만 인지 구분** 가능 → "태그 1개 = 색 1개" 모델이라 색이 태그 수를 묶어 **20 상한**.
- **세분화 불가**: 게임 안에 롤·실크송·명조 같은 세부가 있는데 색이 모자라 표현 못 함.
- **하루 6태그 천장**: 카드당 색 2 × 하루 카드 2~3 = 시각 슬롯 6. 하루에 여러 컨텐츠를
  하는데 다 못 담음.

핵심 착오 = **"보여주는 색"과 "데이터 태그"를 같은 것으로 묶음.** 둘을 분리하면 풀린다.

## 2. 결정 (확정)

1. **2계층 트리만**: 대분류(색 보유) → 세부(색 없음, 부모 색 상속, 텍스트 칩). 깊이 1단계.
2. **카드당 콘텐츠 태그 최대 6**. 단 셀 **색은 대표 대분류 ≤2**(현행 그라데이션 유지).
3. **셀 표현**: ≤2색 메인 스트라이프 + 그 일정/날에 있는 **대분류 색 작은 점 줄**(텍스트 없음).
4. **범위 풀**: 필터 UI 전면 개편(대분류 칩→세부 펼침+검색) + 인사이트 계층 통계 재설계.
5. 휴뱅(dayoff)은 그대로 시스템 잠금 태그(대분류, 색 회색 고정).

## 3. 모델

- 대분류 = top tag (`parent_id is null`), `color_key` 보유.
- 세부 = child tag (`parent_id` = 대분류 id). `color_key`는 저장은 하되 **렌더 색은 최상위
  조상 색으로 해석**(상속). 세부는 자기 색을 안 씀.
- 이벤트 색 = 그 이벤트 태그들의 **서로 다른 대분류(top ancestor)** 집합. 그라데이션은 앞
  ≤2개. 점 줄 = 전체 distinct 대분류.
- `event_tags` 스키마 **무변경**(tag_id 다대다). 카드당 6은 앱/서버 검증.
- `is_primary`는 색 결정에 더는 안 씀(대분류 파생으로 대체). 호환 위해 둠.

## 4. 데이터 모델 변경

- `broadcast_tags.parent_id uuid null references broadcast_tags(id) on delete cascade` 추가.
  - 인덱스: `(calendar_id, parent_id, sort_order)`.
  - 마이그레이션 idempotent(`add column if not exists`). 기존 태그는 전부 parent_id null =
    대분류로 자동 해석 → **렌더 무변경, 안전**.
- 세부 삭제는 cascade. 대분류 삭제 시 세부도 삭제(확인 강화).
- 휴뱅은 항상 대분류(parent_id null) 고정.

## 5. 단계 PR

- **PR1 — 토대(렌더 영향 0)**: 마이그레이션(parent_id) + 타입(`BroadcastTag.parentId`) +
  로더 select/map + 카드당 캡 2→6(서버/앱) + MAX_TAGS 상향. 색은 아직 각 태그 colorKey
  그대로(기존 동작 유지). build·경계 점검 후 머지.
- **PR2 — 색 상속 + 카테고리 점 줄**: month.ts 색 함수가 최상위 대분류 색으로 해석. 카드
  3곳(스튜디오 데스크톱/모바일/포스터)에 ≤2색 + 대분류 점 줄 레이어. CSS.
- **PR3 — 태그 편집기 계층화**: 대분류/세부 구조 편집(세부 추가·부모 지정·들여쓰기 표시),
  세부는 색 스와치 숨김(부모 색 상속 안내). 휴뱅 잠금 유지. 서버 검증(부모 유효성).
- **PR4 — 이벤트 태그 피커**: 대분류→세부 드릴다운 + 검색. 카드당 ≤6 검증. 대표 대분류
  색 미리보기.
- **PR5 — 필터(레전드) 전면**: 대분류 칩 → 펼치면 세부 + 검색창. 필터 매칭은 **전체 태그
  집합(세부 포함, 안 보이는 것도)** 기준 → "하루 6 천장" 소멸. 대분류 선택 = 그 하위 세부
  전체 포함.
- **PR6 — 인사이트 계층 통계**: 컨텐츠 순위·트렌드·하트를 **대분류 롤업 + 세부 드릴다운**
  으로. 휴뱅 식별은 tag_key/시스템 기준. 통계가 세부까지 너무 잘게 쪼개지지 않게 기본은
  대분류 집계, 펼치면 세부.

각 PR: TypeScript+lint+`next build` 통과, 공개/비공개 경계 재확인, commit/push(main).
