# VIC Schedule Studio 기능 확장 조사 보고서

작성일: 2026-05-24  
작성 범위: 현재 코드베이스 read/write 점검 + 스트리머 일정/포스터/공유 도구 리서치

## 1. 한글 문구 복구 점검

코드 파일을 UTF-8 기준으로 다시 확인한 결과, 실제 저장된 주요 한글 문구는 정상입니다.

- `app/page.tsx`: `Google로 로그인`, 시청자/스튜디오 라우팅 주석 정상
- `components/studio/studio-shell.tsx`: `빅토리 편집실`, `비공개 일정 보기`, `시청자 화면 보기`, `저장`, `제목` 등 정상
- `components/poster/public-poster.tsx`: `색상 안내`, `단축키`, `텍스트`, 포스터 편집 문구 정상
- `tests/e2e/calendar-ui.spec.ts`: 테스트 대상 한글 문구 정상
- `docs/현황보고서.md`: 문서 본문 한글 정상

깨져 보였던 원인은 파일 자체보다 Windows PowerShell 출력 인코딩 문제에 가깝습니다. 재발 방지를 위해 `.editorconfig`를 추가했고, 프로젝트 기본 문자셋을 `utf-8`로 고정했습니다.

## 2. 현재 제품이 이미 구현 중인 방향

VIC Schedule Studio는 단순 일정표가 아니라 `방송 일정 운영 + 공개 포스터 제작 + 권한 분리` 도구입니다.

현재 구현 축은 다음입니다.

- Google 로그인 후 역할별 라우팅
- 시청자용 공개 캘린더/포스터
- 소유자/개발자용 스튜디오 일정 편집
- 매니저/작업자용 비공개 레이어 읽기
- 비공개 일정 unlock
- 방송 태그/색상 팔레트
- 후원 일정 기간 표시
- 스티커/텍스트 꾸미기
- 포스터 테마
- PNG 캡처/export
- Supabase DB/RLS 이관 준비

## 3. 외부 도구 리서치 요약

조사한 유사 제품과 흐름에서 반복적으로 보이는 기능은 네 종류입니다.

### 3-1. 일정 동기화와 알림

[StreamSchedule](https://streamschedule.live/)은 Twitch 일정 기반 캘린더, Google/Apple/Outlook 연동, 자동 알림, Discord/웹 공유, sponsor callout 같은 기능을 강조합니다.

[pulz.bio](https://pulz.bio/)는 Twitch 연동으로 live indicator, viewer count, stream title, game category, schedule creation을 링크인바이오 페이지에 붙이는 흐름을 제공합니다.

이 프로젝트에 적용할 수 있는 기능:

- Google Calendar / Apple Calendar / Outlook용 `.ics` export
- 다음 방송 D-day / 카운트다운
- Discord 공지용 문구 자동 생성
- X/Twitter 공지용 문구 자동 생성
- 방송 시작 전 알림 예약
- 라이브 상태 표시

### 3-2. 포스터 제작과 다중 플랫폼 export

[StreamLadder Schedule Maker](https://www.streamladder.com/schedule-maker)는 한 번 만든 스케줄을 Twitter, Discord, Twitch 채널 페이지 등에 올리기 쉽게 export하는 방향을 강조합니다.

[Canva templates](https://www.canva.com/templates/)는 drag-and-drop 기반 템플릿 편집을 핵심 사용성으로 내세웁니다.

이 프로젝트에 적용할 수 있는 기능:

- X/Twitter, Discord, YouTube Community, Instagram Story용 export 프리셋
- 월간/주간/오늘 일정 포스터 템플릿
- 텍스트 자동 줄바꿈/안전 영역 가이드
- 포스터 버전 저장
- 포스터 복제 후 새 달에 재사용
- 브랜드 색상/폰트 preset

### 3-3. 합방/협업 일정 조율

[StreamDay](https://www.streamday.gg/)는 Twitch/YouTube 일정을 가져오고, 스트리머 여러 명의 가능 시간을 모아 공개 페이지에 게시하는 협업 캘린더 흐름을 제공합니다.

이 프로젝트에 적용할 수 있는 기능:

- 합방 후보 시간 투표
- 게스트별 가능 시간 수집
- 확정 전 `embargo` 일정 관리
- 공동 출연자에게 읽기 전용 공유 링크 제공
- 합방 확정 시 공개 일정으로 승격
- 공동 출연자별 프로필/채널 링크 표시

### 3-4. 시청자 참여와 리텐션

검색 결과와 스트리머 일정 도구 흐름에서 시청자에게 중요한 것은 “언제 볼 수 있는지”, “내 캘린더에 넣을 수 있는지”, “놓치지 않게 알림을 받을 수 있는지”입니다.

이 프로젝트에 적용할 수 있는 기능:

- 관심 일정 하트/북마크
- 관심 일정만 `.ics`로 받기
- 공개 일정별 알림 신청
- 이번 주 방송 요약
- 다음 방송까지 남은 시간
- 공개 일정 변경 이력 표시
- 취소/변경 공지 배너

## 4. 추천 추가 기능 우선순위

### 1순위: 실제 운영에 바로 필요한 기능

1. `.ics` 캘린더 export
   - 시청자가 Google/Apple/Outlook에 방송 일정을 추가할 수 있음
   - 현재 public DTO만으로 구현 가능

2. Discord/X 공지문 자동 생성
   - 스트리머가 일정표를 여러 곳에 복붙하는 문제를 줄임
   - KST 기준 문구 + 주요 해외 시간대 보조 표기 가능

3. 다음 방송 카운트다운
   - 공개 포스터 상단이나 사이드에 “다음 방송”을 즉시 보여줌
   - 시청자 입장에서 가장 빠르게 가치를 느끼는 기능

4. 일정 변경 알림/변경 배지
   - 취소, 시간 변경, 제목 변경을 시청자가 놓치지 않게 함
   - 스튜디오에는 변경 사유 입력란 추가 가능

### 2순위: VIC Schedule Studio의 차별화 기능

1. 합방 조율 워크플로
   - 요청함 → 후보 일정 → 내부 검토 → 공개 승격 흐름
   - 현재 `requests`, `proposals`, `variantGroups` 개념과 잘 맞음

2. 포스터 export 프리셋
   - 월간 포스터, 주간 카드, 오늘 방송 카드, Discord 공지 이미지
   - 현재 Playwright 캡처 구조를 확장하기 좋음

3. 포스터 템플릿/버전 저장
   - 매달 처음부터 꾸미지 않아도 됨
   - 스티커/테마/메모 레이아웃을 preset으로 저장

4. 공개 화면 태그 필터 고도화
   - 게임, 합방, 휴방, 공지, 후원 같은 태그별 보기
   - 모바일에서 특히 유용함

### 3순위: 성장/참여형 기능

1. 관심 일정 하트/북마크
   - 숫자를 직접 노출하지 않고 “인기 비율”이나 “관심 높음” 정도로 표현 가능

2. 출석/연속 방문 streak
   - 과하면 피로하지만, 가볍게 “이번 주 일정 확인 완료” 정도는 가능

3. 방송 후 회고/클립 연결
   - 완료된 일정에 VOD/클립/하이라이트 링크 연결

4. 분석 대시보드
   - 포스터 조회, 일정 클릭, 캘린더 export, 알림 신청 수

## 5. 권한/보안 관점 주의점

이 프로젝트의 핵심은 공개/비공개 경계입니다. 새 기능도 이 규칙을 따라야 합니다.

- 공개 export에는 `public-loader` 데이터만 사용
- Discord/X 자동 문구 생성도 공개 DTO 기준으로만 생성
- `.ics` 파일에는 비공개 일정, 엠바고 일정, 작업자 메모 포함 금지
- 합방 후보/요청함은 스튜디오 내부 데이터로 유지
- 매니저/작업자는 읽기/꾸미기 중심, 일정 작성 권한은 기본적으로 소유자만
- owner_private 일정은 owner 전용 유지

## 6. 다음 작업 제안

가장 추천하는 다음 구현 순서는 다음입니다.

1. 공개 일정 `.ics` export API 추가
2. 공개 포스터에 “다음 방송” 카드 추가
3. 스튜디오에서 Discord/X 공지문 복사 버튼 추가
4. 포스터 export 프리셋을 월간/주간/오늘 카드로 분리
5. 합방 요청을 일정 후보로 승격하는 내부 워크플로 추가

이 순서가 좋은 이유는 기존 public DTO, Playwright export, requests/proposals 구조를 크게 흔들지 않고 바로 사용자 가치가 생기기 때문입니다.
