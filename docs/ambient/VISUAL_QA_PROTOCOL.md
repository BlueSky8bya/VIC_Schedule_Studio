# 비주얼 QA 프로토콜 — 세 검사자 · 통합 판단 · 제한 수정(2026-09-05)

> 계절 배경(바이옴 세계)의 몰입 품질을 **라운드 단위**로 올리는 절차. 규칙은 다른 문서가 쥐고, 이 문서는 **누가·무엇을·어떤 형식으로·어떤 순서로**만 정한다.
> 상태·백로그·라운드 기록: [QA_PROGRESS](QA_PROGRESS.md). 파이프라인 구축 계획: [PLAN-20260905-005](../agent/plans/PLAN-20260905-005-ambient-visual-qa.md).

## 0. 한 라운드의 모양(직렬 핑퐁 금지)

```
같은 빌드 · 같은 시드
  ├─ 캡처(before): 대표 시나리오 시트 + 전수 자동 지표          ← scripts/ambient-qa/* (PLAN-005)
  ├─ Agent A · B · C  **동시에** 검토(서로 결과를 보지 않는다)   ← Agent tool 세 번을 한 메시지에
  ├─ 통합 판단(메인 세션): 합치기 → 중복 제거 → 등급 정렬 → **입구 묶음 ≤ 4**로 선택(P0는 전부, §3.3)
  ├─ 수정(선택된 것만, 잘 되는 부분 불변)
  ├─ 게이트: typecheck · lint · vitest · build exit 0
  ├─ 캡처(after): **같은 시드·같은 시나리오** → before/after 시트 + diff
  └─ ROUND-NN.md 기록 → 다음 라운드
```

- 금지: A가 고치고 B가 고치고 C가 고치는 직렬 구조 · **귀속 불가능한 수정**(§3.3의 예산을 넘거나 대상 시나리오를 미리 안 적은 것) · before 캡처 없이 수정 · P3 손대기 · 에이전트가 코드를 고치는 것(에이전트는 **보고만** 한다).
- 한 라운드 = 하나의 커밋 묶음(수정 커밋 + 기록 커밋). 라운드 사이에 소유자 확인이 들어갈 수 있다(특히 P1의 방향 선택).

## 2. 출력 형식(고정 — 파서가 읽는다)

각 발견은 아래 블록 **그대로**. 여러 발견은 블록을 반복. 블록 밖 서술은 마지막 "요약" 3줄만.

```
[Issue] <한 문장 — 무엇이 어떻게 이상한가>
[Biome / Season / TimeOfDay / Weather / Seed / Camera] <biome> / <season> / <band> / <weather> / <seed> / <camera 또는 default>
[Category] <IMMERSION_BREAK_RULES 코드, 예: A-1 · S-5>
[Severity: P0 / P1 / P2 / P3] <하나>
[Why it breaks immersion] <규칙 문서의 어느 조항에 어긋나는지 + 관찰 근거(시트 파일·좌표·크롭)>
[Suggested Fix] <파일·함수 수준의 방향 — 구현은 메인 세션이 한다>
[Acceptance Criteria] <after 캡처에서 무엇이 어떻게 보이면 닫히는가 — 측정 가능하게(지표·L 단차·좌표 조건)>
[Confidence] <높음 / 중간 / 낮음 + 이유>
```

요약(블록 뒤, 3줄): `P0 n · P1 n · P2 n · P3 n` / 가장 넓게 걸린 문제 하나 / 이번 라운드에 안 고쳐도 되는 것 하나.

## 3. 통합 판단(triage) — 메인 세션이 한다

1. 세 보고를 한 표로 합친다(코드·바이옴·좌표 기준 중복 제거 — 같은 원인이면 한 줄, 보고자 열에 A/B/C 병기).
2. 정렬: P0 > P1 > P2 > P3 → 같은 등급이면 **걸린 조합 수**(몇 바이옴·몇 계절에서 보이나) → 신뢰도 → 수정 비용(작을수록 먼저).
3. **수정 예산 = 건수가 아니라 귀속 가능성**(2026-09-05 개정, 소유자: "라운드 한 번에 토큰을 이만큼 쓰는데 3건은 적다").
   옛 규칙은 "상위 2~3건"이었다 — 진짜 이유는 미학이 아니라 **귀속**이다(after에서 픽셀이 변했을 때 어느 수정이 범인인지 알아야 한다).
   결정성 하네스(같은 URL = 같은 픽셀, 시나리오별 해시·diff)가 그 귀속을 대신 해주므로 상한을 이렇게 바꾼다:
   - **P0는 전부** 고친다(예산 밖). 몰입 파괴는 미루지 않는다.
   - 나머지는 **입구 묶음** 단위로 센다 — 같은 파일·같은 함수·같은 엔진 입구(예: `time.ts` 프로파일, `bakeHorizon`, 입자층)를
     건드리는 항목은 **한 묶음 = 한 건**. 한 라운드에 **묶음 ≤ 4**(권장 총 건수 6~10). 대수술 묶음은 그 자체로 한 라운드를 채운다.
   - 각 건은 수정 전에 **대상 시나리오 목록**을 ROUND-NN.md에 적는다. after에서 *변한 시나리오 ≠ 예상 목록*이면 그 건은 귀속 실패 →
     되돌리고 다음 라운드로(다른 건은 살린다).
   - 한 건이라도 게이트(tsc·lint·vitest·build)나 회귀(손대지 않은 시나리오 해시 불변)를 깨면 그 건만 되돌린다.
   나머지는 백로그(QA_PROGRESS)에 등급과 함께 남긴다.
4. 선택 검증: 잠긴 영역(CURRENT_STATE "Locked")·Accepted ADR·오행 팔레트와 충돌하지 않는가. 충돌하면 그 건은 소유자 결정 항목으로 올리고 다음 건을 고른다.
5. 각 건에 **Acceptance Criteria**를 확정(에이전트 것을 다듬는다)하고 ROUND-NN.md에 적은 뒤 수정에 들어간다.

## 3.5 항등 계약 — 세 층(2026-09-06 라운드 6 결정 2)

예전엔 "정적 요소는 라운드 사이에 변하지 않는다"가 한 줄이었다. 하늘(라운드 5)·지평선(라운드 6)처럼
**화면 전체에 걸친 개선**은 16/16을 바꾸므로 그 계약은 지킬 수 없고, 그렇다고 매 라운드 기준선을 갱신하면
회귀 검출이 사라진다(A는 폐기, B·C는 유지를 주장했다). 세 층으로 나눈다:

1. **결정성**(절대) — 같은 `(build, seed, biome, season, band, weather, t)`는 같은 해시다. `ambient:qa:selftest`가 지킨다.
   시간 의존 기능(구름 흐름 등)은 **`t`의 순수 함수**여야 한다 — `performance.now()`·스폰 시각 의존 금지.
2. **정적 항등(면제 목록)** — 그 라운드 표의 "대상 시나리오" **밖**은 점심·맑음 static 해시가 동일해야 한다.
   대상 안은 ROUND-NN.md에 "새 기준선 = 이번 after"를 명시한다. 목록 밖이 2% 이상 바뀌면 회귀다.
3. **동적 계약** — `phaseSync`·`loopSeam`·"밤 움직임 1종"은 해시로 재지 않는다. **시간 시트 diff의 형태**로 계약한다
   (인접 프레임 변화가 단조 · 블록비 < 6× · 1초 변화 하한).

## 5. 결정적 평가 진입점(PLAN-005 P0 — 2026-09-05 구축, `VISUAL_TEST_FIXTURE=1` 프로덕션 서버)

```
/visual-fixture/biome?biome=forest&season=spring&band=dawn&weather=fog&seed=42&t=1500&load=1&camera=showcase
```

| 파라미터 | 뜻 | 기본 |
|---|---|---|
| biome | 시작 바이옴(감상 속성 없이도 머문다 — `pin`) | meadow |
| season | 계절(fixture가 보는 달: 봄 4 · 여름 8 · 가을 10 · 겨울 1) | spring |
| band | 시간대(여섯 띠) | noon |
| weather | 날씨 — **항상 강제**(오늘 날짜의 시드 날씨가 프레임에 끼지 않게) | clear |
| seed | 장면 시드(소품 자리·생물 첫 스폰) | 42 |
| t | 애니메이션 시각(ms). 페이지가 `ready()` → `advance(t)` 뒤 `__vicAmbient.settledT`를 적는다 | 0 |
| load | 여력 고정 0~1 | 1 |
| pointer | `x,y` 포인터 고정(없으면 화면 밖 — 생물 위협 0) | — |
| camera | showcase(내비 오버레이 포함) / plain(캔버스만). 캔버스 픽셀은 같다 | showcase |

같은 URL = 같은 픽셀(캔버스만 캡처, 폰트·OS 무관). `advance(ms)`는 고정 dt(1/60 s) step이라 `advance(1000)` = `advance(250)`×4 = URL `t=1000`.
콘솔: `__vicAmbient.advance(250)` · `.time()` · `.forcePointer({x,y})` · `.forceWorld({…})` · `.pending()` · `.weatherOptions()`. 도구: [`scripts/ambient-qa/README.md`](../../scripts/ambient-qa/README.md).

## 7. 라운드 실행 절차(메인 세션 체크리스트)

1. `docs/ambient/QA_PROGRESS.md` 백로그·지난 라운드 결과 읽기. 잠긴 영역 확인.
2. 로컬 서버(`npm run build && VISUAL_TEST_FIXTURE=1 npx next start -p 3100 -H 127.0.0.1`) → `npm run ambient:qa:selftest`(하네스 자체 점검, 23 PASS) →
   `npm run ambient:qa:capture -- --round NN --phase before` → `ambient:qa:sheet` → `ambient:qa:diff`(같은 인자). 산출 `.scratch-pw/qa/rNN/before/index.md`.
3. Agent tool 세 번을 **한 메시지에** 띄운다(입력: 시트 경로·지표 표·문서 목록). 결과는 `rounds/ROUND-NN-reports/{A,B,C}.md`로 저장.
   **에이전트가 끝날 때까지 3100 서버(before 빌드)를 바꾸지 않는다**(라운드 4: 메인 세션이 검토 중에 수정본을 빌드해 서버를 갈아 끼웠고,
   B·C가 라이브 프로브에서 "밤 해시가 캡처와 다르다"를 감지해 직접 판정을 PNG로 제한해야 했다). 수정본 확인은 에이전트 완료 뒤 — 또는
   다른 포트에 두 번째 서버를 띄운다(`.next`가 하나라 빌드는 어차피 하나 — 확인용 빌드는 에이전트 뒤로 미루는 쪽이 간단하다).
4. 통합 판단(§3) → ROUND-NN.md "선택" 확정.
5. 수정 → 게이트 → `ambient:qa:capture -- --round NN --phase after`(같은 시드) → `ambient:qa:diff -- --round NN --compare before,after` → `compare.md`.
6. ROUND-NN.md 완성, QA_PROGRESS 갱신, CURRENT_STATE 한 줄, 커밋(라운드 단위).
7. 소유자 확인이 필요한 항목(방향 선택·팔레트·P1 이상 대수술)은 "Open Decisions"로 올리고 멈춘다.

## 8. 하지 않는 것

- 전 조합을 같은 깊이로 사람이 본다(불가능·낭비). 전수는 지표, 심화는 16 시나리오.
- 에이전트가 서로 합의한다(각자 보고 → 메인이 판단).
- "예쁘게" 바꾸기 위해 정상 부분을 만진다.
- 소유자 팔레트·카메라·아트 규칙(CLAUDE.md)을 라운드 안에서 뒤집는다 — 필요하면 ADR.
