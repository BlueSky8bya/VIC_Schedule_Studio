# 코덱스에 보낼 프롬프트 — 세계 배경 재구조화 계획(원경/근경 레이어 · 포인터 시차 · 데이브 더 다이버 감성)

소유자 지시(2026-09-10): "계절별 배경들(계곡·민물·산·언덕·초원·숲·갯벌·모래·암석·먼바다·깊은 바다)을 내가 준 레퍼런스 중 데이브 더 다이버의 느낌을 최대한 살려 다시 체계화. 이미지 생성은 코덱스. 레퍼런스를 많이 보고 원경과 근경을 제대로 나눠 여러 배경 레이어를 두고, 마우스를 움직이면 원경일수록 흐릿한 색감으로 조금씩, 근경일수록 짙은 색감으로 더 많이 움직이게. 계절·날씨·시간대 등 기존 것은 모두 살리되 디자인 감성을 전체적으로 다시 구조화."

아래 본문을 그대로 코덱스에 붙인다. 1단계는 **계획서만** 받는다. 승인 뒤 2단계(P0 구현) 프롬프트는 계획서의 단계표를 그대로 가리키면 된다.

## 역할과 범위

너는 이 저장소 안에서 실행되는 계획자다. **이번 대화의 산출물은 계획서 한 장이다.** 코드·이미지·대량 문서 수정은 소유자가 계획을 승인한 뒤 별도 지시로 한다. 규칙과 충돌하는 요구는 조용히 우회하지 말고 "소유자 결정 질문"으로 올려라.

## 목표(소유자 말 → 설계 언어)

열한 바이옴 × 네 계절의 배경을 **깊이 레이어 여러 장**으로 재구조화한다. 포인터가 움직이면 레이어가 깊이에 따라 다르게 밀린다: 원경은 조금·옅고·흐리게, 근경은 많이·짙고·선명하게. 데이브 더 다이버의 감성(깊이 그라데이션, 실루엣 원경, 빛줄기, 색 온도, 옆모습 한 덩어리 생물)을 살린다. 기존 상태 축 — 계절(보고 있는 달), 시간대 여섯 띠, 날씨, 안개, 생물·스폰 감독, 달의 흔적, 하늘 사건, 열한 화면 카메라 이동, 도감, 감상/시청자 모드 — 는 전부 그대로 동작한다. 배경 이미지는 코덱스가 아트 파이프라인으로 생성한다.

## 하드 제약(계획이 이걸 어기면 반려)

- **카메라는 바뀌지 않는다.** 육지·해안은 3/4 부감, 깊은 바다만 측면(AMB-04·06, ADR-0017 ⑮, VISUAL_DIRECTION §6). 데이브의 측면 시점을 육지에 옮기는 안은 내지 말고, 데이브 감성 중 3/4에서도 살아남는 것(깊이 그라데이션·실루엣·안개·색 온도·빛줄기)과 바다·심해에서만 쓸 것을 표로 구분해라. 정말 카메라를 바꾸고 싶으면 결정 질문으로.
- **팔레트·어법 유지.** 오행 팔레트(선명한 빨강·주황·노랑 금지), 픽셀아트 한 어법, ART-13(6~10색·같은 계열 어두운 외곽선·AA 없음). 레이어 이미지도 이 계약 안이다.
- **시간대·날씨는 이미지에 굽지 않는다.** 이미지는 `바이옴 × 계절 × 레이어`만. 시간대·날씨는 엔진 패스(`world/light.ts` 여섯 채널, `particles.ts`, `fog.ts`)를 **레이어 깊이 계수**로 적용한다. 장수를 정확히 계산해 제시하라(예: 11 × 4 × 3 = 132). 시간대·날씨까지 이미지로 만들자는 안은 금지.
- **성능 규칙.** AMB-09(한 번 굽고 매 프레임 drawImage)·AMB-10(소프트 효과는 저해상). 흐림은 **미리 구운 저해상 레이어**로만 — 런타임 `filter: blur`·전역 CSS filter·매 프레임 재굽기 금지(과거 프레임 끊김 원인). 무한 애니는 transform/opacity 성격만. gfx 등급 2/1/0마다 레이어 수·시차 폭·흐림 단계를 다르게 정하고 표로 내라. `reduced`·생동감 OFF·감상 OFF는 시차 0의 정지 프레임(AMB-13).
- **결정성.** 같은 빌드·시드·크기·`pointer` 고정값이면 같은 프레임(AMB-25·29). fixture의 `pointer` 파라미터로 시차 상태를 고정할 수 있어야 한다. 스무딩(spring/lerp)은 `advance`로 수렴 가능해야 한다.
- **카메라 팬과 레이어가 싸우지 않는다.** 620ms 팬 중 시차 동작, 지평선 높이 전 바이옴 동일(BIOME_GRAMMAR 공통 층 구성), 산 다섯 층(MOUNTAIN_DEPTH_RULES)과 새 레이어의 합치를 명시.
- **생물·서 있는 것과의 관계.** 생물·나무·소품은 어느 레이어 사이에 y-sort로 그려지는지, 근경 레이어가 생물을 가릴 수 있는지, `splitHaze`/`drawAbove` 순서에 어떻게 끼는지, 공중 보행(IMMERSION_BREAK) 회귀가 없는지.
- **아트는 파이프라인으로만.** `request → 원본 → normalize → 소유자 검토 → promote`. 배경 레이어는 manifest에 **새 범주**(예: `backdrop`)의 자리로 추가하고 `art-src/폴더명.json`·카탈로그·`분류어휘.json`(subjects/env — `style:pick`이 데이브·동숲의 `mood` 장면을 붙이게)까지 계획에 포함. **현재 manifest는 1024 정사각 투명 PNG를 가정한다(`SOURCE_EDGE`, `targetEdge`, `dotGrid`).** 가로로 긴 레이어는 이 가정을 깨므로, 규격 예외를 어디에 어떻게 넣을지(정규화·검사 계약 ART-06/13 포함) 계획에 명시. 이미지가 없는 자리는 지금의 절차적 장면이 대체물로 남는 **점진 이행**이어야 한다.
- **참고 자산 복제·트레이스 금지**(ART-11·14, ADR-0021). 공통화풍참고 폴더의 파일 바이트·이름·위치는 건드리지 않는다.
- **동결 자산.** `art-src/*/작업회차/` 기존 회차, `public/ambient/art/` 합격본은 덮지 않는다.
- **문서 절차.** 계획서는 `docs/agent/plans/PLAN-20260910-015-world-depth-layers.md`(기존 PLAN 머리 형식: Status Proposed · Task Risk · Created). `docs/agent/plans/ACTIVE_PLAN.md`에 행 추가. 대체되는 조항(BIOME_GRAMMAR 공통 층 표, ADR-0017의 관련 절, SYSTEM_MAP)을 지목하되 개정은 구현 단계에서. ADR 초안은 계획서 부록으로만.
- **git.** 이번 단계는 계획서·ACTIVE_PLAN 두 파일만 바뀐다. `git add -A` 금지, 경로를 명시해 커밋. 푸시는 소유자가 시킬 때만.

## 계획서에 반드시 담을 것

1. **데이브 감성 표.** 실제로 열어 본 캡처 파일명(경로)과 함께: 가져오는 것(깊이 그라데이션 색, 실루엣 원경, 빛줄기, 색 온도, 정면 여백), 안 가져오는 것(측면 시점의 육지 적용, 잔도트 밀도, 게임 UI·캐릭터), 육지 3/4에서의 번역 방법, 바다·심해에서의 직접 적용 범위.
2. **레이어 모델.** 레이어 수와 이름(예: 하늘 / 원경 실루엣 / 중경 지면 / 근경 프레임), 각 레이어의 v 범위·시차 계수·안개 α·채도 계수·흐림 단계(사전 굽기 해상도 비율)·캔버스 크기(화면보다 얼마나 크게 굽나 = 최대 이동 px 여유), 바이옴별 예외(깊은 바다 측면 = 수직 깊이 레이어, 먼바다 = 수평선 중심, 산 = 다섯 층과 합치). BIOME_GRAMMAR 공통 층 표와 1:1 대응표.
3. **포인터 → 오프셋 함수.** 정규화 포인터(−1~1) → 레이어별 오프셋(px) 식, 최대 이동, 스무딩(시간 상수·spring 여부), 포인터 없음(모바일·창 밖)일 때 동작(정지 / 아주 느린 자율 드리프트 — 결정 질문), 카메라 팬 중 감쇠, 스크롤·줌(AMB-11) 보정.
4. **상태 축 유지 매트릭스.** 행 = 계절·시간대·날씨·안개·생물·흔적·하늘 사건·카메라 팬·감상 모드·시청자 모드·gfx 0/1/2·reduced, 열 = 어느 레이어/패스가 어떻게 반응하는지, 지금 코드의 어느 함수가 담당하는지(파일:함수).
5. **아트 계약.** 새 자리 목록(id·바이옴·계절·레이어)·정확한 파일명·총 장수, 장당 크기·격자·색 수·투명 여부, 레이어 간 이음과 겹침 규칙(원경 하단이 중경 뒤로 사라지는 폭 등), 계절 간 같은 실루엣 유지 규칙(ART-08 계절 짝), 대체물, `request` 한 번의 예시(초원 봄 3레이어)와 그때 `style:pick`이 붙일 mood 장면.
6. **성능 예산.** 레이어당 메모리·그리기 비용, 프레임 목표, gfx 등급별 표, 측정 방법(`scripts/ambient-qa/`, perf 실측 스크립트).
7. **검증.** 결정적 fixture 시나리오(바이옴 × 계절 × 포인터 3점 이상), 에이전트 A/B/C 라운드 항목(VISUAL_QA_PROTOCOL 형식), 전후 시트, 회귀 목록(공중 보행·안개 순서·구름 개수 정규화 같은 과거 사고).
8. **단계.** P0 엔진 레이어·시차(지금의 절차적 장면을 레이어로 분리, 이미지 없음) → P1 초원 1바이옴 파일럿(4계절 × N레이어, 소유자 화풍 승인) → P2 나머지 10바이옴 → P3 다듬기. 단계마다 커밋 단위, 게이트(`npx tsc --noEmit` · `npm run lint` · `npm run test` · `npm run build` · `npm run harness:verify` · `npm run art:catalog -- --all --check` · `npm run style:check` · 비주얼 라운드), 되돌리기 지점.
9. **소유자 결정 질문.** 번호 붙여 기본안과 함께: 레이어 수, 시차 세기(px), 모바일·포인터 없음 동작, 육지 카메라 유지 확인, 흐림 단계 수, 이미지 총 장수와 크기, 파일럿 바이옴(초원 기본), 시청자 화면에도 시차를 켤지, 배경 효과 설정(`gfx`)과의 연동.
