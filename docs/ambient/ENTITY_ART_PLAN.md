## 1. 결론 — **CONDITIONAL GO**

### 1.1 왜 지금인가 — 실측 근거

**① 배경 시스템은 새 에셋을 공정하게 판정할 만큼 안정됐다.**
카메라·축척·접지·레이어·간격·안개·조명이 15라운드에 걸쳐 **수용 기준으로** 닫혔고, 회귀는 자동으로 잡힌다.

| 계약 | 지금 값 |
|---|---|
| 결정성(같은 URL = 같은 프레임) | 5/5 조합 × 2시각 동일 |
| 공중 보행 `airWalk` | 0(다람쥐 8시드, 최소 v .260) |
| 겹침 `overlapRatio` | 0.00%(노출 12~13 장면) |
| 풀이 소품을 뚫음 | ≤ 0.41% |
| 물가 바위 꼭대기 잘림 | 0/23 |
| 안개 밀도장 단조 | 6/7 |
| 밤 지면 하한 | 15/15 |
| selftest | ALL PASSED(23/23) |

즉 새 PNG를 넣었을 때 "이상해 보이는 것"이 **에셋 탓인지 엔진 탓인지 구분할 수 있다.** 이것이 착수 가능 판단의 핵심 조건이고, 지금 충족된다.

**② 남은 최대 병목이 정확히 엔티티 층이다.** 라운드 13~15에서 세 검사관이 P1으로 올렸으나 **코드로 못 닫은 것**들의 목록:

- A #3(r15): 암석해안 뭍이 "사구 판" — 지면 L 폭 **10.8**(초원 16.4·숲 37.1), 8×8 타일 SD **0.30**(초원 1.20). 흑백에서 모래해안과 구분 불가 = **R-2**.
- B #3(r15): 언덕 세 겹이 명도 계단일 뿐 — 경계 12개 중 9개 ΔL < 8.
- A(r15 부록 C): "갈대 성냥개비·새싹 껌딱지 대체물 — **아트 배달이 답이지 코드 수정이 아니다**."
- A(r14 #3): 눈송이 5×5 한 크기 24개, 빗줄기 한 크기 — 입자 픽셀 규격.

이들은 **절차적 도형을 더 그려서는 못 고친다.** 소유자가 매니페스트를 만든 이유가 그것이다("나무·초목을 기본 도형 몇 개 붙여 만들면 어떻게 하냐 — 겨울 나무 = 말미잘, 봄 초목 = 껌딱지").
VISUAL_DIRECTION §2의 우선순위("몰입 파괴 제거 > 새것 추가")와도 맞다 — 여기서 **몰입 파괴가 곧 대체물 자체**다.

**③ 파이프라인은 이미 끝에서 끝까지 증명됐다.** 참나무 4장이 배달돼 있고, 그것만 화면에서 "동물의 숲 같은 코지"로 읽힌다(s01 숲 캡처). 자리 매니페스트 → PNG 드롭 → `ArtSet` 알파 트림 → 자리 상자 맞춤 → 앵커 → 바탕 1회 재굽기가 실제로 돈다. **새 파일을 떨어뜨리는 것 말고 할 일이 없다.**

**④ 지금 화면의 실제 상태 — 숫자.**

| 항목 | 값 |
|---|---|
| 선언된 아트 자리 | **69**(전부 phase 1 = 식물·지형·소품) |
| 실제 배달된 아트 | **4**(`tree-oak-{spring,summer,autumn,winter}`) |
| 코드 대체물이 있는 자리 | 33 |
| 이모지·SVG로 때우는 자리 | 6 |
| **아무것도 안 그려지는 자리** | **26** |
| 생물(phase 2) 자리 | **0**(매니페스트에 없음 — `species.ts`에 8종 live + 20종 후보만) |

`scatterProps`는 아트도 대체물도 없으면 **그 개체를 건너뛴다**. 그래서 26자리는 선언만 되어 있고 화면에 존재하지 않는다. 그 목록이 곧 검사관들이 지적한 정체성 결손과 겹친다:

> 시스택 · 큰 바위 · 자갈밭 · 조수 웅덩이 · 갯벌 해조 뭉치 · 모래해안 통보리사초 · 물웅덩이 · 부들 · 사초 · 억새 · 고사리 · 이끼 · 가시덤불 · 산딸기 · 야생화 3종 · 자작나무 4계절 · 눈 이랑 · 고드름 · 솔방울 · 깃털 · 통나무 다리

**⑤ 반복감의 원인이 수치로 잡힌다.** 화면에서 가장 많이 반복되는 서 있는 물체의 변형 수:

| 물체 | 한 화면 개수 | 변형 수 |
|---|---|---|
| 소나무 `tree-pine` | 산 40~46 · 숲 15~22 | **1** |
| 마른 풀 `grass-dry` | 언덕 200~260 | 3 |
| 바위 `rock` | 육지 8~16 | 4 |
| 갈대 `reed` | 민물 4~6 무리 | 4 |

산 캡처(s10)에서 침엽수 40여 그루가 **한 장의 스프라이트를 배율만 바꿔** 세운 것이다. 소유자가 피하고 싶다고 한 "같은 이미지가 반복되어 procedural generation 티가 나는 것"이 지금 가장 크게 보이는 곳이 여기다.

### 1.2 조건 — 생성 전에 닫아야 하는 셋

이 셋을 먼저 닫지 않으면 **파일럿을 다시 만들어야 한다.**

**C1. 화풍 잠금(Style Bible)을 참나무 4장에서 *측정해서* 뽑는다.**
지금 화풍의 유일한 물증이 그 4장이다. 말로 "픽셀아트"라고만 두면 2차 배치가 반드시 어긋난다. §7에 측정값을 박아 뒀다.

**C2. 파일럿은 흩어진 단품이 아니라 *한 장면의 한 가족*을 통째로 바꾼다.**
지금 숲 화면에는 **두 화풍이 나란히** 있다 — 청키 픽셀 참나무 옆에 매끈한 벡터 삼각형 소나무. 파일럿이 또 흩어지면 그 경계가 하나 더 생긴다. 그래서 **소나무가 1순위**다(숲·산·계곡 세 바이옴에서 참나무 바로 옆에 선다).

**C3. 자리 계약을 참나무가 아닌 형태로 한 번 검증한다.**
`ArtSet`은 알파 경계로 잘라 자리 상자에 맞춘다. 참나무는 정사각에 가까워 왜곡이 안 보였다. **가로로 긴 것(통나무 70×26)과 세로로 긴 것(소나무 92×168)** 각 1장으로 트림·맞춤·앵커가 뭉개지지 않는지 먼저 확인한다. `npm run art:normalize`도 이때 한 번 돌린다.

> 조건이 아닌 것: **바람·비의 미완성**. 라운드 16 이월이지만 에셋 제작을 막지 않는다. 정지 판독성은 정지 프레임으로 판정하고, 흔들림은 엔진이 스프라이트에 거는 것이라 에셋 형태와 독립이다. 다만 **눈 쌓임(snow cap)은 엔진에 없다** — 겨울 변형을 "눈 얹힌 그림"으로 그릴지 "엔진이 얹을지"는 §10 결정 사항.

## 2. Asset Gap Matrix — 11개 바이옴

캡처(`.scratch-pw/qa/r15/after/`) + 매니페스트 실측 기준. 우선순위는 **화면 점유 × 정체성 기여 × 현재 결손 정도**.

### 숲 forest (`s01`, `s02`)
- **Current Weakness** — 참나무(아트)와 소나무(벡터 삼각형)가 나란히 서서 **화풍 경계가 한 화면에 있다**. 바닥은 거의 균일한 초록 그라데이션 + 미세한 점, 하층 식생 0 → "잔디밭 위 과수원". 그루터기·통나무는 갈색 덩어리, 바위는 회색 삼각형.
- **Missing Asset Type** — 침엽수(3계절) · 관목(4계절) · 고사리 · 이끼 · 낙엽 더미 · 그루터기 · 통나무
- **Why Needed** — BIOME_GRAMMAR §2가 요구하는 "닫힌 수관 + 빈터 + 그루터기 4~6·통나무 3~5·관목 6~10"에서 **중간층이 전부 비어 있다**. 화풍 경계 해소가 가장 급하다.
- **Priority: P0**
- **Recommended Variants** — 소나무 3계절 × 2형 · 관목 계절당 2 · 고사리 3 · 이끼 2

- **Priority: P0**(침엽수 변형) / **P1**(큰 바위)

## 3. 엔티티 범주 검토 — 만들 것과 만들지 말 것

### 만든다(자리가 이미 있음)
활엽수(자작나무 4계절) · **침엽수 3계절** · 어린 나무 · **관목 4계절** · 덤불(가시덤불·산딸기) · 긴 풀(억새·통보리사초) · 짧은 풀(풀포기 변형 증량) · **야생화 3종** · 갈대·부들·사초 · 연잎·연꽃 · 해조 뭉치 · **작은/중간/큰 바위** · **시스택** · 자갈밭 · 나뭇가지 · 통나무·그루터기 · 조개·불가사리 · 조수 웅덩이 · 이끼·고사리 · 솔방울·깃털

### 만들지 않는다 — 근거 있음
- **동물·물고기·곤충 전부.** 소유자 상시 규칙: *동물은 손으로 그리지 않는다 — Noto Emoji 에셋만*(CLAUDE.md, `NOTICE.txt`, IBR **F-2**). 그리고 VISUAL_DIRECTION §2가 "새 동물·식물은 배경 문법이 정리된 뒤에"로 순번을 정해 뒀다.
  다만 **오리가 화풍에서 혼자 튀는 것은 사실이고**(민물 캡처에서 유일한 이모지 광택), 이 규칙을 바꿀지는 §10의 소유자 결정 사항으로 올린다. 파일럿에는 넣지 않는다 — 화풍 잠금 실험에 변수를 하나 더 넣으면 QA 판정이 흐려진다.
- **깊은 바다 생물.** 측면 시점 + 실루엣이 설계다.
- **화면에서 16px 미만인 것**(조약돌 12×9, 클로버 14×12). PNG로 얻는 것이 없다.

## 5. Entity Style Bible — 참나무 4장에서 **측정한** 기준

> 말이 아니라 수치다. 생성물은 이 표를 통과해야 배치한다.

### 5.1 측정된 기준선(`public/ambient/art/tree-oak-*.png`)

| 항목 | 측정값 | 규격으로 고정 |
|---|---|---|
| 파일 크기 | 460~468 × 512 | **1024 정사각 생성 → `art:normalize`가 자리의 4배로 축소** |
| 알파 여백 | 0%(이미 꽉 참) | 생성 시 ≥ 6%, 정규화가 트림 |
| 대표색 수(불투명 0.5% 이상) | 34 · 38 · 34 · **59**(봄) | **≤ 40**(봄 59는 예외 — 새 에셋은 40 상한) |
| 총 색 수 | 40~46 · 100(봄) | ≤ 48 |
| 가장 어두운 대표색 | rgb(32 32 24) · (24 40 32) · (48 24 32) · (40 32 32) | **순검정 금지**, 같은 색상의 어두운 명도 |
| 가장 밝은 대표색 | rgb(184 144 88) · (192 208 136) · (88 168 64) · (248 248 248) | 겨울만 흰색 허용 |
| 가로 연속 길이 최빈 | **2px** > 3px > 4px > 5px | **도트 2~5px**(512 기준) = 논리 64~96px 확대 |
| 불투명 픽셀 비율 | 60~62%(잎), 35%(겨울 나목) | 실루엣이 상자를 채울 것 |

### 5.2 형태 언어
- **덩어리 2~3개로 읽힌다.** 128px로 줄여 실루엣만 남겼을 때 무엇인지 알아야 한다. 잎 낱개·잔가지·질감 금지.
- **곡선 우위.** 각진 형태·전폭 직선·하드에지 그라데이션 금지(VD §3). 기하학적 정원·정타원 금지(F-1).
- **안티에일리어싱 없음.** 픽셀 경계는 계단으로. 대체물 옆에서 매끈한 벡터로 보이면 **F-2**.
- **윤곽선**: 같은 색상의 훨씬 어두운 명도로 1도트. 순검정 금지.
- **명암 3~5단**(VD §3). 밝은 면은 **왼쪽 위**, 그늘은 **오른쪽 아래** — 참나무가 그렇게 되어 있고 엔진의 그림자 방향과 맞다.
- **하이라이트**는 면 하나에 한 번. 반짝임·림라이트 금지.
- **텍스처 없음.** 나뭇결·잎맥·돌결은 도트 2~3개의 색면 차이로만.

### 5.3 색
- 채도 낮게. **선명한 빨강·주황·노랑 금지**(오행 규칙). 가을 = 갈색·황토·와인.
- 밝은 땅(눈·모래) 위에 서는 것의 줄기는 **회갈색**(적갈 금지 — 눈밭에서 가장 튀었던 것).
- 계절 변형은 **같은 실루엣·같은 줄기, 색만 교체**. 겨울만 형태가 바뀐다(나목).
- 한 물체가 채도·명도로 혼자 튀면 **F-3**.

### 5.4 카메라·축척
- **서 있는 것 = `stand`**: 높은 앵글 3/4 정면(동물의 숲 카메라). 앵커 = 지면 접촉점. **발밑 그림자는 그리지 않는다 — 엔진이 그린다.**
- **누운 것 = `flat`**: 위에서 본 시점. 엔진이 `GROUND_SQUASH .7`로 눌러 그린다 → **원본은 눌리지 않은 상태로** 그린다.
- **물속·하늘 = `shadow`**: 실루엣.
- 크기는 자리 상자(`px`)가 정한다. 원본에 스케일 개념을 넣지 않는다.
- 최대:최소 비 ≤ 12(TILE 64) — 자리 상자가 이미 그 안이다.

### 5.5 전경/중경/원경
별도 variant를 만들지 않는다. 엔진이 `depthScale`(.60~1.00)과 `drawDepthHaze`로 처리한다. **원본은 항상 근경 품질 한 벌.**

## 6. 엔티티는 파일 한 장이 아니다 — 통합 계약

새 에셋이 라운드 1~15가 닫은 것을 다시 열지 않게 하는 규칙.

| 축 | 누가 책임지나 | 에셋이 지켜야 할 것 |
|---|---|---|
| 시각 간격 | 엔진 `claimSpot(x,y,r,stand,hy)` | 자리 상자 `px`가 실루엣과 맞을 것(hy = 실제 높이) |
| 접지 | 엔진(앵커 = 발밑 가운데) | 밑변에 **떠 있는 픽셀 금지**, 그림자 그리지 말 것 |
| 수면선 | 엔진 `drawSubmerged` | **마른 상태 한 벌만** 그린다. 물색 사본·젖은 띠·앞 반원은 엔진 |
| 젖음 | 엔진(라운드 15 물가 40px 젖음 패스) | 밑동이 어두워질 여지를 남길 것(밑변 순백 금지) |
| 잠김 | 엔진(y 오프셋 8k~18k) | 밑변 알파가 급격히 끊기지 않게 |
| 눈 쌓임 | **아직 엔진에 없음** | §10 결정 대기 — 당분간 겨울 변형에 그려 넣는다 |
| 그리기 순서 | 엔진 y-sort(발 y) | 큰 소품은 **바탕에 굽지 않는다**(나무 뒤로 못 감) |
| 가림 | 엔진 y-sort | 반투명 영역 금지(가장자리 α는 0 또는 255에 가깝게) |
| 바람 | 엔진 sway(라운드 16 예정) | 상단 60%가 기울어도 깨지지 않는 형태 |
| 계절 | 자리 분리(`-spring`…) | 같은 실루엣 유지 |
| 스폰 밀도·군집 | 엔진 `scatterProps` + 문법 | 변형 간 **면적비 ≥ 1.4** |

**바위는 PNG 한 장으로 끝난다** — land / water-edge / submerged / wet 네 표현이 전부 엔진 파생이다(라운드 13~15에서 그렇게 만들었다). 에셋을 4벌 만들면 오히려 그 계약을 깬다.

## 8. 파일럿 후 QA 절차 — 라운드 16-A(아트)

기존 프로토콜을 그대로 쓰되 **비교 축이 코드가 아니라 에셋**이다.

1. **before** = 지금 빌드(`1ae7c15`) 캡처가 이미 있다(`.scratch-pw/qa/r15/after/`). 이것을 `r16a/before`로 복사해 쓴다 — 재캡처 불필요.
2. 파일럿 12장을 `public/ambient/art/`에 떨어뜨린다. **코드 변경 0**(드롭인이 설계다).
3. `npm run art:normalize` → 게이트(tsc·lint·vitest·build).
4. **after** 캡처 — 같은 시드 42, 같은 16 시나리오, 같은 띠·날씨·t. 변수는 파일 존재 여부 하나뿐.
5. 검사관 3종 **동시** 투입, 읽기 전용. 이번 라운드의 질문을 명시:
   1. 새 이미지가 배경보다 **지나치게 선명하지 않은가**(대비·채도가 주변 지면보다 튀는가 — F-3)
   2. **스티커처럼 붙은 느낌**은 없는가(접지·그림자·안개 감쇠를 받는가)
   3. 색·명암 단계·선 굵기가 **기존 배경과 맞는가**(F-2)
   4. 화면 **정보량**이 너무 많아지지 않았는가(R-1 벽지)
   5. **반복감이 실제로 줄었는가**(같은 스프라이트 반복 횟수 측정)
   6. 엔티티 간 **spacing**이 자연스러운가(`overlapRatio` 유지)
   7. **layer/occlusion**이 자연스러운가(y-sort 위반 0)
   8. 계절·시간대·날씨에서도 자연스러운가(6띠 × 5날씨 시트)
   9. **기존 대체물보다 실제로 개선됐는가**(개선 안 된 자리는 되돌린다)
6. **되돌림 기준**: 자리 단위. 한 자리가 위 9개 중 하나라도 P1 이상으로 걸리면 **그 PNG만 뺀다**(대체물로 자동 복귀 — 파이프라인이 그렇게 설계돼 있다). 전체 롤백이 필요 없다는 것이 이 파이프라인의 장점.
7. 회귀 고정 묶음: 결정성 해시 · `airWalk` 0 · `overlapRatio` ≤ 8% · 다람쥐 8/8 · 깊은 바다 봉인 · selftest.

**추가 자동 지표 2개**(신설 권고):
- `spriteRepeat` — 한 화면에서 같은 자리 ID가 그려진 횟수 ÷ 변형 수. 소나무는 지금 40, 목표 ≤ 12.
- `assetContrast` — 에셋 픽셀의 평균 채도·명도 vs 반경 60px 주변 지면. |Δ채도| ≤ 12, |ΔL| ≤ 14.

## 9. 전략 결정 — **Strategy C+**(하이브리드, C를 확장)

| 전략 | 판정 |
|---|---|
| A. 절차적 유지 + 종류만 추가 | **기각.** 소유자가 이미 거부한 방향("도형 몇 개 붙여 만들면 어떻게 하냐"). 새 절차적 식물 추가는 문서에서 금지돼 있다. |
| B. 중요 엔티티부터 전면 이미지 교체 | **과도.** 69자리를 다 만들면 유지보수·용량·검증량이 급증하고, 12px 조약돌처럼 PNG로 얻는 게 없는 것까지 포함된다. |
| C. 자연물 절차적 유지 + 동물·곤충·특징 식생만 이미지 | **부분 기각.** 동물은 Noto 규칙이 있어 애초에 이미지 대상이 아니고, **정작 문제인 것이 자연물**(소나무·바위·시스택)이다. C는 방향이 반대다. |
| **C+ (권고)** | **서 있고 · 크고 · 반복되고 · 정체성을 지는 것만 이미지.** 나머지는 절차적 유지. |

**C+의 경계선**

| 이미지로 만든다 | 절차적로 남긴다 |
|---|---|
| 화면 16px 이상, `stand` 뷰 | 16px 미만(조약돌·클로버·나뭇가지) |
| 한 화면 5개 이상 반복 | 지면 텍스처(흙 얼룩·풀 패치·눈 이랑 바탕) |
| 바이옴 정체성을 지는 것(시스택·억새·통보리사초) | 자국·흔적(발자국·두더지 흙더미·건열) |
| 계절 변형이 형태를 바꾸는 것 | 물 효과 전부(고리·거품·항적·수면선) |
| | 입자(비·눈·부스러기·안개 뭉치) |
| | 물고기 그림자(실루엣이 설계) |
| | 동물·곤충(Noto 규칙) |

**근거**: 성능 — 에셋은 한 번 굽고 `drawImage` 한 번이라 절차적보다 **싸다**. 유지보수 — 자리 단위로 넣고 뺄 수 있어 롤백이 자리 하나 단위다. 계절·날씨 — 색 틴트·젖음·눈은 엔진이 얹으므로 에셋 수가 계절 수만큼 늘지 않는다. QA — 파일 존재 여부가 유일한 변수라 A/B가 깨끗하다.

## 10. 대량 제작 전에 소유자가 결정할 것

1. **눈 쌓임을 누가 그리나.** 엔진에 snow-cap이 없다. ⓐ 겨울 변형 PNG에 그려 넣기(파일 수 ×1.33, 지금 방식) ⓑ 엔진이 상단 18%에 얹기(파일 절약, 구현 필요). 파일럿은 ⓐ로 진행하되 결정이 필요하다.
2. **동물 규칙을 유지하나.** "동물은 Noto 에셋만"이 지금 규칙이다. 민물의 오리는 화풍에서 혼자 튄다(이모지 광택·비율). 바꾼다면 ADR이 필요하고 파일럿 2로 분리한다. **바꾸지 않는 쪽을 권고한다** — 지금 병목이 아니고, 손그림 동물은 불쾌한 골짜기 위험이 가장 큰 범주다.
3. **자작나무를 넣나.** 자리 4개가 선언만 돼 있다. 참나무·소나무 두 종으로 충분하다는 판단이면 자리를 지우는 게 낫다(선언만 된 자리는 계획을 흐린다).
4. **변형 수의 상한.** 반복감 해소의 직접 지표다. 소나무 2형이면 충분한지, 3형까지 갈지. 파일 수가 여기서 결정된다.
5. **파일럿 승인 방식.** ⓐ 12장을 한 번에 보고 판정 ⓑ 소나무 3장 먼저 보고 화풍만 승인한 뒤 나머지 진행. **ⓑ를 권고한다** — 화풍이 어긋나면 12장을 다시 만든다.
6. **26개 빈 자리 중 안 만들 것.** 고드름·깃털·솔방울·통나무 다리는 정체성 기여가 낮다. 지금 쳐내면 계획이 가벼워진다.
