## 수정

### ① `art/props.ts` — 실루엣 높이 규칙 · `behindStand`

- `propField` 항목에 `hy`(발 → 꼭대기 px). `claimSpot(x, y, r, stand, hy?)`: 서 있는 것끼리 같은 열(|dx| < .8·(r + o.r))에서 **뒤(y 작은) 것의 발이
  앞 것의 몸통 사각(발 위 .9·hy ~ 발 + 4) 안**이면 거부 — 옛 검사는 수관 반지름만 봐서 dy 17·dx 5인 두 바위, 30px 간격의 소나무 4그루가 통과했다("토템").
- `behindStand(x, y)`: (x, y)가 서 있는 소품의 몸통 뒤인가 — 풀포기·억새는 자리를 잡지 않고 이것만 묻는다. 앞(발 + 4 아래)에 서는 포기는 허용(발치를 가린다).
- `scatterProps`: `artSlot(id).view === "stand"`면 자동으로 `stand` + `hy = px[1]·k` — 바위·관목·그루터기·통나무가 stand = false로 등록돼 세로 검사를 빠져나갔다.

### ③ 레이어 재배치(B (2) 판정 반영)

**B (2) 판정: 풀 층은 옮기지 않는다 — `behindStand` 스킵만.** 관통 획은 전부 소품 발보다 위에서 끝나는 "뒤 뿌리"(s10 25/25 · s09 4/4 ·
s15 5/6)이고, 밑변까지 닿는 "앞 뿌리"(s16 1716px · s15 54px)는 소품 발을 가리는 **정상 가림**이라 풀 층이 위에 있어야만 생긴다 — 풀을 통째로 뒤로
보내면 "받침대 위 관목"이 된다. `standing[]` y-sort는 이번 라운드 필수 아님(16장에서 매 프레임 나무가 앞의 구운 소품을 덮는 사례 검증 못 함; 완전 재배치의
위험 = 매 프레임 30~60 drawProp + 안개 이중 적용 + 캐시 무효). 대신 값싼 닫기 하나: **`scatterProps`가 후보를 모아 y로 정렬한 뒤 점유·그리기** —
옛 리스트 순서(rock → shrub)로는 뒤에 놓인 관목이 앞 바위를 덮을 수 있었다(A-3). 후보 생성(rng 소비)은 정렬 전에 끝나므로 결정성은 그대로.

### ④ 라운드 11 후속 · 회귀(규칙 6) — 안개 밀도장의 소비자·배선 셋(C #1·#2)
