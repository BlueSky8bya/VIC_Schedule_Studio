# Current ambient art workflow rules

Updated: 2026-09-09. Scope: original pixel artwork, references, normalization and owner review. [README](README.md) routes other ambient tasks.

Entity entry points: [art catalogue](../../art-src/목록.md). Commands, migration receipts, batch inputs and promotion checks: [ART_PIPELINE](ART_PIPELINE.md).
An entity's generated prompt collects its full plan; the exact run request defines the delivery. This file owns acceptance intent, not duplicated filenames, inventories or current status.

- ART-01: **아트 자리·파일 정본** — Slot ids, filenames, category, camera, seasons, dimensions, dot grid, palette limits and variant requirements come from `components/shared/ambient/art/manifest.ts`; species slots derive from `world/codex.ts`. Read current generated briefs. Never copy a master prompt, variant count or species inventory into a separately maintained rule document.
- ART-02: **동물의 숲 카메라·발밑 그림자** — Standing plants/props use the high 3/4 camera and ground-contact anchor. Flat objects use top view; water shadows and deep-sea creatures follow their slot camera. The engine adds contact shadows. Do not paint an extra stage/ground or incompatible camera into the sprite.
- ART-03: **픽셀아트·오행 팔레트** — Confirmed style is simple, chunky original pixel art. At on-screen size, the main mass must remain readable. Use slot-specific logical grid/palette rather than a single global resolution. No anti-aliasing, pure-black outline, painterly detail or strongly saturated warm accents. Outlines use darker related hue; trunks on snow/sand stay grey-brown. Evidence: manifest style guide and accepted oak/pine art.
- ART-04: **합격본·반려본 그림 참고** — References have distinct roles: approved style, subject/ecology, and rejected defect examples. Clearly label them; never present rejected art as a target. A rejection crop needs the violated rule and wanted correction, not only “bad.” Local files can be read by the coding agent; whether the image model sees one depends on actual tool/reference attachment. Do not claim it cannot read the workspace or that a path alone guarantees visual reference use.
- ART-05: **생성 원본 보존** — Preserve original delivered bytes before normalization/replacement. Approved public images must not be overwritten or restored over a new delivery. Authorized legacy migration records old/new paths and hashes while keeping frozen runs unchanged. A preserved legacy source or same-name public counterpart alone does not prove original lineage or approval. Keep rejected images and reasons. Evidence: [source rules](../../art-src/AGENTS.md), pipeline and [pine handoff](HANDOFF-20260908-pine.md).
- ART-06: **도트 정규화·정수배 축소** — Normalization preserves discrete pixels through integer scaling and nearest sampling; use the manifest-derived target/grid and current normalization command. Do not resurrect arbitrary fractional shrink dimensions or lanczos smoothing from old briefs. Render sampling is part of the visual result and must be checked at actual screen size.
- ART-07: **아트 대체 그림** — A missing image uses the registered fallback. New procedural plants/props are not finished artwork; add/use a slot and the shared drawProp fallback path. The art board distinguishes delivered, missing and fallback status rather than calling all populated code “delivered.”
- ART-08: **변형 다양성·계절 짝** — Variants must look distinct in silhouette/mass/structure at screen size, not only palette. Seasons of one variant preserve its identity, position and proportions. Treat a season family as one review batch. Numeric similarity, snow and palette checks detect defects but do not establish owner acceptance.
- ART-09: **검토 시트·반려 이유** — Review a flat, labelled contact sheet beside approved references before promotion. Retain per-file acceptance/rejection reasons and the exact brief/reference inputs. Source/staging layout must not force manual renaming away from final manifest filenames.
- ART-10: **개발자 아트 보드** — The developer-only art board is a review/generation entry; server authorization is required. Public viewers must not gain private workflow metadata or mutation access through a client-only role check.
- ART-11: **외부 영감·도감 참고** — 엔티티 `레퍼런스/`는 해당 대상의 형태·구조·생태만 참고하고 이미지/sidecar 출처를 함께 둔다. 받는 라이선스는 **자유 라이선스**(CC0·퍼블릭 도메인·CC-BY·CC-BY-SA·OGA-BY)까지이며 NC·ND·GPL·출처 불명은 받지 않는다(소유자 결정 2026-09-11, 이전의 CC0 전용 조항 대체). 사이드카에 출처·작성자·라이선스가 없거나 자유 라이선스가 아니면 `request`가 실패한다. 픽셀아트는 OpenGameArt, 실물 사진은 위키미디어 커먼즈(640px JPEG로 축소 보관)에서 `ref:fetch-all`이 모은다. `공통화풍참고/<게임>/`은 전체 분위기·색감·구도·카메라와 **같은 부류를 단순화한 어법**만 살피며 특정 대상 형태의 근거나 합격 화풍으로 쓰지 않는다. 우리 합격 시트가 화풍 정본이다. 게임 자산·고유 디자인·도감 문구를 복제하거나 트레이스하지 말고 외부 참고를 public 자산으로 내보내지 않는다. 게임별 관찰은 각 폴더의 `공통화풍원칙.md`([동물의 숲](<../../art-src/공통화풍참고/모여봐요 동물의 숲/공통화풍원칙.md>), [데이브 더 다이버](<../../art-src/공통화풍참고/데이브 더 다이버/공통화풍원칙.md>))에 기록한다. 2026-09-10 개정(ADR-0021): "자동 첨부하지 않는다"는 조항은 ART-14로 대체됐다.
- ART-14: **화풍 참고 색인·자동 첨부** — `공통화풍참고/<게임>/색인.json`이 그림마다 역할을 정한다: `mood`(장면 분위기)·`depiction`(같은 부류의 단순화 어법)·`form`(3D 렌더의 비율만)·`none`(첨부 금지). 출처 게임의 캡처만 첨부 후보이고 스톡·워터마크·다른 게임·사진·출처 불명은 `none`이다. `request`는 색인에서 결정적으로 골라 `고정입력/화풍참고/`에 사본과 사유를 남기며, 색인에 없거나 바이트가 바뀐 그림은 붙지 않는다. 프롬프트는 이 사본을 복제·트레이스 금지와 함께 역할별로 적는다. 화풍 참고는 승인 근거가 아니며 도트 굵기·색 단수·외곽선은 ART-13이 정한다. 분류는 대조 시트를 본 에이전트가 작업지를 채우고 `style:apply`·`style:check`로 닫는다. 명령과 상한: [ART_PIPELINE](ART_PIPELINE.md), 결정: ADR-0021.
- ART-12: **생성·공개 승인** — Generation and promotion follow the user's current authorization. Do not derive permission to create images, overwrite accepted outputs or publish from a historical handoff. Select current work from CURRENT_STATE and its run request; folder storage rules live in [art-src/AGENTS](../../art-src/AGENTS.md).

Original rules/rejection history is preserved in dated evidence; it is not a second generated-prompt source. General biome art acceptance still uses [VISUAL_DIRECTION](VISUAL_DIRECTION.md) and [IMMERSION_BREAK_RULES](IMMERSION_BREAK_RULES.md).

- ART-13: **픽셀아트 검수 조건** — 소유자가 확정한 색 어법은 물체당 6–10색, 같은 계열의 어두운 외곽선, 안티앨리어싱 없음이다. 원본·정리본을 해당 슬롯의 실제 표시 크기(`ArtSlot.px`)로 합격본과 나란히 비교한다. 생성 원본은 현재 계약의 1024×1024 투명 PNG, 논리 격자는 `dotGrid`/`dotBlock`, 저장 변과 정수배율은 `targetEdge`/`sourceRatio`로 확인한다. 숫자 정본: `components/shared/ambient/art/manifest.ts:ART_STYLE_SPEC`, `dotGrid`, `dotBlock`, `targetEdge`, `sourceRatio`. 기계 검사 통과만으로 6–10색 어법이나 소유자 화풍 승인을 대신하지 않는다. 이 검수 조건을 완화하려면 소유자 판단이 필요하다.

## 아트 측정 계약의 적용 범위

ART-13은 모든 그림을 옛 64–96 논리 px나 2–3덩이/128px 하나로 맞추라는 지시가 아니다. 현재 슬롯에는 128칸 참나무처럼 명시된 예외와 서로 다른 화면 크기가 있으므로, 실제 요청의 슬롯별 격자·brief가 우선한다. 6–10색은 화풍 기준이고 `scripts/ambient-art-check.mjs:checkArt`의 넓은 기계 실패 한계와 구별한다. 옛 4× 화면 크기 맞춤 축소와 public 제자리 정규화·탈색은 현행 전달 절차가 아니다(ART-05/06). 숫자 변경 또는 재생성 뒤에는 원본 격자, 정수배 정리본, 실제 화면 크기 세 단계를 모두 확인하며 검토하지 않은 단계를 PASS라 적지 않는다.
