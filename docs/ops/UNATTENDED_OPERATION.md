# 개발자 없이 굴러가는 운영 (2026-11-23)

개발자가 사이트를 거의 돌보지 못하게 되어, 관리자(방송인)가 쓰기만 해도 몇 해 동안 굴러가도록 2026-11-22~23에 전수 점검하고 고친 결과다. 고장 났을 때 누가 다시 열어 봐도 여기서 시작하면 된다.

## 1. 손대지 않아도 스스로 도는 것

| 무엇 | 어떻게 | 언제까지 |
|---|---|---|
| 방송 감지·다시보기·팬 타임라인 수집 | Workers Cron 매분 → `/api/cron/broadcast-poll` | 기한 없음 |
| 연간 인사이트 보관, 제보 삭제, 고장 점검 | Workers Cron 매시 7분 → `/api/cron/insights-archive` | 기한 없음(보관은 2100년까지) |
| 다시보기 채팅 수집 | DB pg_cron 5분마다 → `/api/cron/vod-chat` | 도메인이 살아 있는 동안 |
| 검색 연관어·화제 | DB pg_cron 매일 03:20 KST(+재시도 2회) | 기한 없음 |
| 로그·성능·운영자 기록 정리 | DB pg_cron 매일 03:40~03:50 KST | 기한 없음 |
| 고장 점검(둘째 길) | DB pg_cron 6시간마다 → `/api/cron/health` (`0173`) | 기한 없음 |
| 공휴일·대체공휴일·절기·삼복·정월대보름 | 계산(`lib/calendar/holidays.ts`, 생성 표 2100년까지) | 2100년 |
| 사이트 제보 삭제 | 처리 완료 후 90일, 처리 전이어도 받은 지 180일 | 기한 없음 |

GitHub Actions에는 예약 작업이 없다(수동 실행만) — 60일 무활동 자동 중지와 무관하다.

## 2. 고장 알림 메일

`lib/health/check.ts`가 문제를 찾으면 개발자 계정(`platform_admins`의 메일)으로 한 통 보낸다. 평소엔 보내지 않고, 같은 문제는 일주일에 한 번만 다시 보낸다(`site_alert_state`).

| 메일 제목 | 뜻 | 먼저 볼 곳 |
|---|---|---|
| 방송 감지·다시보기 수집이 멈췄어요 | 매분 예약 작업이 하루 넘게 안 돎 | Cloudflare Worker의 Cron Triggers, 비밀값 `CRON_SECRET`, 최근 배포 실패 여부 |
| 3주째 방송 기록이 없어요 | 긴 휴방이 아니면 숲(SOOP) 응답이 바뀜 | `lib/broadcast/soop.ts`(비공식 주소라 예고 없이 바뀔 수 있다) |
| DB 예약 작업이 실패하고 있어요 | pg_cron 작업이 24시간에 3번 이상 실패 | Supabase → Integrations → Cron |
| 다시보기 채팅 수집 호출이 실패하고 있어요 | DB가 사이트를 부르는 호출이 대부분 실패 | 도메인, Vault의 `vic_cron_token` |
| 검색 연관어 갱신이 멈췄어요 | 밤 작업이 사흘 넘게 못 끝남 | `select public.search_graph_nightly();`의 경고 |
| DB가 거의 찼어요 | 400MB(무료 한도 500MB의 80%) 넘음 | 아래 4절 |

메일은 신고 답장과 같은 Gmail 발송(`lib/reports/gmail.ts`, 비밀값 `GMAIL_*`)을 쓴다. 이 비밀값이 Cloudflare에 없거나 죽으면 알림도 못 간다 — 점검 응답의 `mail` 값이 `not-configured`/`failed`로 나온다. 시험 메일: 크론 인증으로 `/api/cron/health?test=1`.

**이 점검으로 못 잡는 것:** 사이트·도메인이 통째로 내려간 경우(메일을 보내는 것이 이 사이트다). 그건 Cloudflare가 보내는 결제 실패·도메인 만료 메일이 유일한 신호다.

## 3. 사람이 꼭 챙겨야 하는 것 (코드로 못 막는다)

- **Cloudflare 결제**: Workers Paid 월 5달러와 도메인 `victory-broadcast.com` 연 갱신(구입 2026-11-13). 카드가 만료되거나 결제가 실패하면 사이트가 내려간다. 도메인은 자동 갱신을 켜 두고, 카드 만료 전에 바꾼다.
- **계정**: Cloudflare·Supabase·GitHub·구글 클라우드(로그인용 OAuth, Gmail 발송)·문의 메일 계정이 모두 개발자 것이다. 각 서비스의 알림 메일이 가는 주소를 실제로 읽는 주소로 두고, 가능하면 둘째 관리자를 넣어 둔다.
- **구글 OAuth 동의 화면**은 '프로덕션' 상태여야 한다. '테스트' 상태면 Gmail 발송 토큰이 7일마다 죽는다.
- **로컬에서 `cf:deploy` 금지**(`.env.local`이 Worker에 실린다). 배포는 main push → Workers Builds.

## 4. 알려진 한계와 그때 할 일

- **DB 용량(2026-11-23 소유자 결정: 지금은 그대로 둠)**: 180MB에서 시작해 다시보기 채팅 단어·목차로 해마다 50~90MB쯤 는다. 400MB를 넘으면 메일이 오고, 500MB를 넘으면 DB가 읽기 전용이 되어 저장이 전부 막힌다. 그때 고를 것: 오래된 `vod_chat_terms` 삭제(그 다시보기는 채팅 단어 검색에서 빠진다) 또는 Supabase 유료 전환(월 25달러, 8GB). 무료 플랜은 백업이 없다.
- **숲(SOOP) 주소**: 비공식이라 바뀌면 방송 표시·방송 시간·다시보기가 조용히 멈춘다. 사이트 자체(일정 보기·편집)는 그대로 된다.
- **임시공휴일·대통령선거**: 규칙으로 알 수 없어 달력에 안 나온다. 넣으려면 `HOLIDAYS_YEARLY`에 한 줄.
- **다시 빌드할 때**: 오래 지나 push하면 빌드 환경(Node·OpenNext)이 달라져 실패할 수 있다. 실패해도 돌고 있던 판은 그대로 남는다.

## 5. 복구 방법

- **관리자가 떡밥 비밀번호를 잊음**: 설정 → 보안 → 변경 → '비밀번호를 잊었어요' → 구글로 다시 로그인 → 10분 안에 새 비밀번호. (예전처럼 DB를 고칠 필요 없다.)
- **관리자가 구글 계정을 잃음**: 두 곳을 같이 바꿔야 한다 — Cloudflare Worker 비밀값 `OWNER_EMAIL`에 새 메일 추가, 새 계정으로 한 번 로그인, 그 뒤 `db/seeds/0003_transfer_owner.sql`·`0013_sync_co_owners.sql` 적용. 한쪽만 바꾸면 화면은 열리는데 저장이 조용히 실패한다(ADR-0003).
- **신고함**: 개발자만 연다(2026-11-25 소유자 — 11-23에 관리자에게 열었다가 되돌림). 아무도 안 봐도 받은 지 180일 뒤 자동으로 지워진다.
- **운영 판 확인**: `https://victory-broadcast.com/api/soop-live` 응답의 `build`가 배포된 커밋이다.
