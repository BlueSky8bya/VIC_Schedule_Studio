# UX 감사 보고서 적용 계획

원본: `docs/ux-audit-benchmark-report.en.md` (15개 영역, Slack/Notion/Linear/Figma/Canva 벤치마크)

## 정직한 총평

보고서 자체는 잘 쓰였지만, **대규모 멀티테넌트 SaaS 기준으로 보정**돼 있다. 이 앱은
단일 스트리머(빅토리) 일정판을 수십 명 시청자가 보는 구조라, 보고서가 "이미 강점"이라고
인정한 **낙관적 UI(이벤트·스티커·하트 + 롤백)는 사실상 이미 다 구현돼 있다.**

따라서 보고서 15항목을 전부 똑같이 따라가면 **노이즈와 과설계**가 된다. 실제로 체감을
바꾸는 단 하나의 큰 공백은 **라우트 레벨 로딩 스켈레톤 부재**다 (`loading.tsx`가 앱 전체에
하나도 없음 — 확인됨). 핵심 시나리오 = "시청자가 모바일에서 채팅 링크를 눌렀을 때, 인증·
역할·일정이 풀릴 때까지 빈 화면을 응시"한다. 이게 1순위.

## Tier A — 진짜 공백, 고가치·저위험 (강력 추천)

### A1. 라우트 레벨 로딩 스켈레톤 (`loading.tsx`)
보고서 항목 #1(First Paint), #2(Studio Load), #13(Decorate Entry)에 직접 대응.

- 대상 라우트: `app/page.tsx`(루트), `studio`, `studio/calendar/[y]/[m]`, `studio/decorate/[y]/[m]`
- **공개 안전 스켈레톤만 렌더** — 비공개 필드 절대 금지(제목/메모/엠바고/근무 없음).
  KST 월 프레임 + 제목 자리(✨️빅토리 일정표✨️ placeholder) + shimmer 날짜 칸 + 포스터톤 배경.
- **내 추가 아이디어 1:** 공유 컴포넌트 `<CalendarSkeleton variant="poster" | "studio">`
  하나를 만들어 모든 `loading.tsx`가 재사용. 중복 마크업 방지.
- **내 추가 아이디어 2:** 스켈레톤도 실제 화면과 **같은 16:9 고정 스테이지(scale)** 를 써서,
  실제 콘텐츠로 교체될 때 레이아웃 점프가 없게 한다. (포스터/시청자 화면이 이미 고정 캔버스)
- 경계 규칙: 스켈레톤은 actor 해석 전에 그려질 수 있으므로 **익명 안전 크롬만**. 편집 핸들·
  비공개 토글·잠금 UI는 절대 미리 보이지 않게.

### A2. OAuth 여정 폴리시 (항목 #5)
로그인은 첫인상이고, 인앱 브라우저(숲/카톡) 핸드오프가 실제 고통 지점.

- 콜백 처리 중 브랜드 오버레이("VIC 스케줄 스튜디오로 돌아오는 중…").
- `?error=` 쿼리를 **친절한 복구 카드**로 파싱(원시 쿼리스트링 노출 제거).
- 실패해도 비공개 정보(카운트·제목·타이밍) 절대 노출 금지.

## Tier B — 중간 폴리시 (원하면 진행)

### B1. 포스터 편의 내보내기 3단계 피드백 (항목 #9)
공식 내보내기는 Playwright(정본)로 유지. 클립보드 편의 기능만:
"포스터 준비 중 → 이미지 렌더링 → 클립보드 복사" 비차단 오버레이 + 폰트/에셋 미정착 경고.
무거운 html2canvas 작업 중 화면이 얼어붙는 느낌 완화.

### B2. 비공개 레이어 잠금 해제 3단계 핸드셰이크 (항목 #4)
"암호 확인 중 → 비공개 일정 여는 중 → 비공개 레이어 활성" + 검증 성공 후에만 스켈레톤
비공개 칸 표시. 실패 시 카운트/제목 노출 없이 잠금 상태로 복귀. (잠금은 드물어서 폴리시 성격)

### B3. 월 라우트 stale-while-refresh (항목 #3)
스튜디오 내부 월 이동은 이미 클라이언트 슬라이드라 대부분 해결됨. `[y]/[m]` 직접 진입/
새로고침 시에만 직전 그리드를 흐리게 유지. A1 스켈레톤과 겹치므로 A1 이후 판단.

## Tier C — 스킵/보류 (정직한 "안 함" + 이유)

- **항목 #6,#7,#8,#11 — 이벤트/태그/멤버/스티커 "syncing" 마커:** 이미 낙관적+롤백.
  단일 소유자 편집 환경에서 마커는 노이즈만 추가. 실제 실패 가시성 문제가 보고되면 그때.
- **항목 #12 — 하트 카운트 syncing 상태:** 서버 백업 + 낙관적 이미 구현. 한계효용 낮음. 보류.
- **항목 #10 — 스티커 업로드 레인/썸네일:** 소유자가 가끔 몇 개 올리는 수준. 직렬화가
  실제 고통이 아님. 보류.
- **항목 #14 — Presence 상태 표시:** 개발자 전용·비차단 이미 OK. 스킵.
- **항목 #15 — 공개 API 페이로드 분할:** 이미 캐시+병렬. 달력은 어차피 월 전체를 보여줘야
  하므로 분할은 복잡도만 늘림. 스킵.

## 권장 실행 순서

1. **A1**(스켈레톤) — 체감 최대, 위험 최소. 먼저.
2. **A2**(OAuth 폴리시) — 첫인상.
3. 이후 B1 → B2 → B3 를 원하는 만큼.

각 단계: TSC/Lint/Build 통과 + 공개/비공개 경계 점검 → 커밋 → main push → 커밋 해시 보고.
