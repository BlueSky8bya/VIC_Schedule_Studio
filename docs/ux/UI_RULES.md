# Current UI rules

Updated: 2026-09-09. Read only sections affected by the task. Shared security, KST and authorization rules live in [AGENTS](../../AGENTS.md). This file preserves standing UI constraints formerly mixed with history in CLAUDE; historical explanations remain in git and dated reports.

## Materials and meaning

- UI-01: (금생수·오행) Work controls use the existing metal tokens; containers use water/glass tokens. Keep a metal hairline edge, quiet top sheen, slate ink, small work-control radii and larger container radii. Water/glass faces may sit inside metal frames, including 저장. Reason: related surfaces must read as one product. Evidence: [ADR-0016](../agent/decisions/ADR-0016-metal-water-design-language.md), `app/metal-water.css`; current translucent fills use `--glass-*`, not retired `--gs-water-*` names.
- UI-02: (오행·의미색) Owner screens must not introduce strong red/orange/yellow decoration. Preserve the eight semantic colors: 업 도움/support rose, 기간 안내/period cyan, 일정 편집·선택/editing+selection water blue (`--selection-*`, derived from `--studio-action`; was violet until 2026-09-27, [ADR-0029](../agent/decisions/ADR-0029-color-semantics-teaser-selection.md)), 신규/new green, 오늘/today gold, 미정/undecided orange, 떡밥/teaser violet (`--teaser-*`, the only violet state color), 다시보기/VOD forest blue. Existing tag colors and hearts retain their meaning. Never deliberately create stress with clashing 극 colors or awkward placement; warnings belong to real errors/unsaved changes. HCI/accessibility outrank palette preference. Personal-fit source notes remain local; never put them in UI/API or commits.
- UI-03: (방향·저장) North/top chrome uses water, west/left tools use silver, calendar content stays warm; do not introduce hot decorative accents at bottom/right. Placement still follows task flow and thumb/pointer reach. Save is the one water-colored primary action within the editor; cells/cards are selection targets.
- UI-04: (차분한 편집실) Studio calm styling is always on. New studio surfaces use `--studio-*` tokens under `html[data-studio-calm]`; do not restore a calm toggle or remove meaningful motion. Evidence: `app/layout.tsx`, studio calm CSS.
- UI-05: (눈 편한 테마) Eye comfort defaults on and changes UI token palettes, including `--glass-cell/head/panel`; never reintroduce a root CSS filter or tint the ambient canvas. Every new translucent surface takes its RGB base from these tokens, with alpha at the use site. Reason: a root filter affects everything and caused frame jank; literal glass fills made the toggle ineffective. The ≥50% pixel-change and background-invariance acceptance contract is below. Evidence: `app/globals.css`, [ambient engine rules](../ambient/ENGINE_RULES.md).
- UI-06: (모바일 재질) Mobile uses its own cream, 12px/pill radii and meaning-tinted controls. Web metal styles are gated by actual topology classes `.studio-narrow`/`.poster-agenda`, not width alone. Reason: landscape touch devices also enter agenda layout. Evidence: `lib/ui/breakpoints.ts`.

## Layout, typography and chrome

- UI-07: (웹·아젠다) Web and agenda are distinct layouts. Use `MOBILE_QUERY`, `STUDIO_AGENDA_QUERY` and `POSTER_AGENDA_QUERY`; do not confuse the mobile-device threshold with the studio/poster agenda thresholds. Never compress a desktop surface until text is unreadable. Mobile is a compact single column with thumb targets and sheets, with zero horizontal overflow; web uses horizontal space and larger type.
- UI-08: (디자인 통일) Use shared spacing, type, radius, shadow and motion tokens. Keep sibling heights and symmetric padding consistent; enlarge content or redistribute unused space without stretching a cramped box. Native-looking controls and legible text outrank decorative density.
- UI-18: (통일 우선 — 2026-09-17 소유자) 편집실·시청자·미리보기·비로그인은 **한 기능 = 한 구현**이다. 새 화면 요소나 동작이 필요하면 먼저 기존 것을 계승한다: 상태·컨트롤·폭·모션은 `use-side-panel`/`panel-place-control`/`--side-panel-w`/`flipSpring`, 달력 글자는 시청자 포스터 캔버스 px(날짜 20/900 · 제목 14/800 · 세부 12.5/800 · 요일 17/800, `public-poster.css` '달력 글자 기준')를 편집실이 `100vw/1840 ÷ --shell-zoom`으로 환산, 패널 글자는 `--text-title`/`--text-body` 토큰. 화면 하나에만 있는 새 크기·굵기·규칙을 만들지 않는다 — 구조가 강제할 때(포스터 고정 캔버스 vs 편집실 유동 그리드)만 분기하고 그 이유를 주석에 남긴다. 통일 실패는 결함으로 취급한다(ADR-0025).
- UI-09: (편집실 배치) Studio web chrome is one north row: build badge, month navigation, save state, account/role, viewer preview, logout. The decorative product title belongs on the viewer. Tools live in the west rail; do not restore a second full-width action row. Evidence: `components/studio/studio-shell.tsx`, [chrome compaction](chrome-compaction-manual.md).
- UI-10: (계정 카드·저장 상태) Account controls use one rail-width grid; fixed-content cells remain stable and preview uses remaining space. Save-state labels reserve their longest width. A successful save may put its KST time in the role badge while role remains available by its existing cues; do not make the card jump. Viewer preview navigation aligns to the same measured rail. Rail/grid measurements are below.
- UI-11: (패널 자리·세로 압축) The panel control `[⇤ | 패널 | ⇥]` stays bottom-center, outside the moving panel, and is the same component in studio, viewer and viewer preview (ADR-0025). The middle button toggles collapse (state by ink only) and for 1.2s after Ctrl+wheel shows the zoom percentage as information (hover restores the toggle; no click-to-reset); side buttons are a radio (white box) and exist for every desktop viewer. Below 1680px (`PANEL_WIDE_MIN`) the panel auto-collapses and reopens as an overlay over the calendar, never pushing it. Panel width is the shared token `--side-panel-w` (studio divides by `--shell-zoom` so on-screen widths match); the viewer panel is an in-flow sticky column, never an independent scroller; while the studio panel pushes, the calendar scales by `panel.fit` so a month stays in one view. The rail prioritizes usable filter/tools height; the avatar's empty area yields first. Keep the ≥132px filter floor and 620px/470px height contracts below. The bottom floating row moves aside for the editor or falls behind it when space is insufficient. Evidence: `lib/ui/use-side-panel.ts`, chrome compaction manual and `placeEditorPopover`.
- UI-12: (크롬 실측 압축) Chrome compacts from measured overflow: cold labels and decorative chrome fold before calendar/save/month navigation. Never measure detached/zero-size nodes (`isConnected && clientWidth > 0`); rebind observers on remount. Keep accessible names when labels fold. Width/height/remount checks are below. Evidence: `chromeTier`/`data-pchrome` and the manual.
- UI-13: (투명 상단바) Background-enabled topbars remain transparent and non-sticky; empty chrome containers use pointer-events none with actual controls auto. Never give `html` a background that blocks body-background propagation and covers negative-z ambient layers. Reason: invisible chrome must not eat background interactions or cover the calendar. Evidence: `app/globals.css` html-background restriction.
- UI-14: (아바타 자리·상태 라디오) Viewer chrome uses 36px control cells, 44px outer/central cards, 13.5px `--text-body` and shared ink. State radios always show all states: ambient `켜기/흐리게/끄기` (the avatar `끔/왼쪽/오른쪽` radio was replaced by the panel pill, UI-11). Any target state is one click away and width is stable; never glue a cycling next-action button to a state radio. Size and transition checks are below.
- UI-15: (짧은 이름·툴팁) One short label per control on every platform. No long/short label pairs. A tooltip adds only missing information: hidden label → name only while folded, using `data-tip`; visible but ambiguous action → short result, about 20 characters or fewer and no parenthetical aside; self-explanatory visible label → none. Do not use a native title to repeat a visible label. Keep aria-label as the name. Evidence: `data-tip` chrome rules.
- UI-16: (칸 안 표식) One useful icon per control and one icon vocabulary per group. Chrome uses lucide strokes; emoji remain on playful surfaces without neighboring stroke icons. If folding would leave two icons, keep the leading identity icon and express popup semantics with aria-haspopup. In cells, icons are inlaid in host ink at one stroke weight, without drop shadow/white ring; saturated color is for data and selected states. Desktop calendar icon sizes are below.
- UI-17: (스크롤바 숨김) Scrollbars are visually hidden globally, while wheel/touch/keyboard scrolling remains. Do not override with thin/auto on a new scroller. Evidence: global scrollbar rule in `app/globals.css`.
- UI-38: (애플식 체계 — 2026-10-06 소유자 승인) Press feedback uses only `--press-scale` (0.95, controls) or `--press-scale-lg` (0.985, cards/rows/panels); the heart's 0.82 squish is the one deliberate exception. Radii use the token steps `--r-xs 6 / sm 8 / md 12 / card 14 / lg 16 / xl 20 / pill` (2–3px only for thin structural bars). Elevation uses only `--elev-1` resting card, `--elev-2` raised chip/button, `--elev-3` popover/menu/sheet, `--elev-4` modal; inset rings, colored glows and zero-blur rings are separate. Font weights outside calendar text follow 400/600/700 (no 800/900); calendar text (cards, dates, weekdays, bands, tier marks, teasers) keeps its poster-legibility weights.
- UI-39: (설정 창) Settings use a left tab sidebar when the list's own box is ≥600px wide (container query `rhh`; window size fixed while switching tabs, arrow keys move between tabs) and fall back to stacked groups in narrower boxes (phones, studio mobile popover). Motion follows Apple: one sliding highlight in the sidebar, a sliding thumb in segments, a stretching switch knob while pressed, and a short rise-in for the chosen pane (all spring tokens, off under reduce-motion). Within a group they are laid out like Apple Settings: section title → white rounded card of rows → optional one-line footer only where a choice needs explaining. Each row = colored icon tile + short name + control; two-to-three-state choices use the always-visible `.rhh-seg` segment, not a select. Tile tone states the group's nature (water 화면·움직임, leaf 배경, metal 편집·개발, rose 시청자 화면), not a semantic state. Web-only rows/groups carry `.rhh-web`. New preferences go into this one list (UI-21).
- UI-40: (효과음) Every sound goes through `lib/ui/sfx.ts` `playSfx(name)` (synthesized, no files), paired with the matching haptic moment. Locks: master switch (default **on** since 2026-10-06 owner decision; only devices that chose off stay silent — mind broadcast leakage), per-category switch (축하 celebrate · 누름·이동 ui · 하트·기대 tap · 편집 edit · 알림 alert; every `hapticTick` also plays a deferred `tick` that yields to any specific sound in the same gesture), quiet while the tab is hidden (default on), volume 0–100 (default 60, squared curve). New sounds pick an existing category; never play sound outside a user action except reveals, which the hidden-tab lock covers. SOOP replay audio belongs to the player and is not controlled here. Sound character (2026-10-06 v3, sources: WWDC19 'Designing Audio-Haptic Experiences', WWDC21 'Practice audio haptic design', Brewster earcon guidelines, Gaver SonicFinder, Zwicker annoyance, Plomp–Levelt roughness, Material sound, Kaaresoja latency): functions differ by note count and rhythm, not pitch alone; rising = positive, falling = undo/close; consonant intervals only; error = same low note twice; master lowpass 4.2 kHz; ±3% pitch and ±1.5 dB jitter per play; frequent sounds 40–120 ms. `hapticTick` sounds are picked from the element just touched (switch on/off, tab/radio, open/close, slider/drag detent, plain tap) in `tickFor()`, so call sites stay unchanged; modal/sheet open and close sound from one state effect each. One action = one sound (2026-10-06): a pointer/key press and its results form one gesture; within it only a stronger sound may follow (1 tick-derived < 2 ui screen sounds < 3 results); tick-derived sounds wait 45 ms and yield to a specific sound; on double-click surfaces (studio pills, bands, day cells) the first click's sound waits 220 ms and a second click hands the slot to the double-click's open sound; second-beat haptics (server confirm) are silent; detent and celebrate sounds are exempt. Verified by `window.__sfxTrace`. Silent-control fallback (2026-10-10): any trusted click on a pressable element (button, link, role=button/tab/switch/…, checkbox/radio, label) also plays the deferred `tick`, so controls whose handler makes no sound still get the `tickFor()` sound and controls that already sound stay one sound; opt out with `data-sfx="off"`. Studio day cells pick `cell` (tiny bubble); entering/leaving viewer preview plays `peek`/`peek-back` from one `viewerMode` state effect.
- UI-41: (글꼴·굵기) Font and card text weight are device settings in `lib/ui/font-prefs.ts` (`vic.font`, `vic.calWeight`), applied pre-paint by `app/layout.tsx` as `--app-font` on `<html>` (body font) and `--cal-weight` (added to `--evt-weight`, clamped 100–900). Font files only download when used: Google fonts via `next/font` with `preload: false`, others as `@font-face` in `app/fonts.css` (prefixed `VIC `, real bold files mapped to 600+). The picker never renders every option in its own font up front — a chip switches to its font after hover/focus. Excluded by the owner: 동글, 주아, 개구, 나눔손글씨 펜. Picker grid (2026-10-10): each group holds a multiple of 4 fonts (고딕 8 · 둥근 8 · 명조 손글씨 4) shown in exactly 4 columns, 2 columns when the settings box is ≤420px; tile names never ellipsize (wrap instead, full name in `title`). Settings grids (`.rhh-panes`, `.rhh-group-card`) pin their column to `minmax(0,1fr)`, and the mobile studio settings popover in the 92px agenda rail gets a definite width — `.rhh-tabs` is an inline-size container, so shrink-to-fit popovers would collapse and spill content sideways (page horizontal scroll). Text size, weight and font are fully independent per surface (2026-10-10, `lib/ui/pref-surface.ts`): viewer surface (`/` and the studio's viewer preview) uses `vic.calText`/`vic.calWeight`/`vic.font`, the editor uses the same keys + `.studio`, with no fallback between them. Surface = `/studio` path and not in viewer preview (`<html data-pref-surface>` set by studio-shell, `vic_view` cookie `v=1` pre-paint); switching preview fires `vic:pref-surface` and the settings hook re-applies all three. The pre-split shared font/weight were copied to the editor once (`vic.prefSplit`). The 글자-tab preview must be measured from the live calendar behind the window (cell width, card insets, on-screen title px incl. poster scale), so its line breaks equal the real cards on that surface.
- UI-42: (변경 체감) Every edit the user intends must be felt on the calendar itself, not only in a toast. Copy: source card bumps, a translucent echo lifts off, and marching-ants (`.copy-ants`, mint `--copy-ink`) stay on it until paste/Esc, with a persistent `.clip-chip` and a dashed `.paste-preview` card in the chosen cell. Paste: a card ghost springs from the source to the new slot (`flyPaste`, destination hidden while flying), or pops in if the source is off-screen. Undo/redo of band moves replays `settleSpanSegments`. Date-cell shading (`.selected`) shows only right after clicking that cell (`dateCue`); a plain cell click never adds range shading.
- UI-43: (축하 탭 멜로디) Day-mark taps go through `playCelebrationTap` (lib/ui/sfx): first tap = that day's fanfare, further taps within 2.5 s play one melody note each (birthday = Happy Birthday, others = 떴다 떴다 비행기) with a `popMusicNote`; birthday's first tap is a big fanfare then the song, with `danceBirthdaySong` spawning one dancing note per song note from the same timetable (`BIRTHDAY_SONG`, `SONG_DELAY`). Notes are body-level DOM animated with transform/opacity only; skipped under reduce motion. Streak melodies (`MELODIES`, 13 public-domain tunes incl. 젓가락 행진곡·작은 별·나비야·환희의 송가·엘리제·징글벨) rotate per new streak (Christmas = 징글벨) and show a `.mn-title` chip on the first note. `grand` days (birthday, 주년, D+N00) get the ceremonial `grand` fanfare (birthday keeps its song), extra screen fireworks and the top confetti rain; on the day itself the mark gets `.invite` (shine + bounce + '눌러 보세요!' bubble) until tapped once (`vic.markTapped.<date>`). Since 2026-10-06 every tap is one note (first tap included); only grand days play a whole piece on one tap (birthday song, 주년/D+N00 ceremonial fanfare). Days with a related public-domain song use it (`THEME_SONG`: Christmas 징글벨, Halloween 산왕의 궁전에서, 설날·추석·대보름 아리랑, 신정 석별의 정, 발렌타인 결혼 행진곡, 어린이날 작은 별, 현충일 어메이징 그레이스, 국경일 애국가, 어버이날·대체공휴일 브람스 자장가, 스승의 날 환희의 송가, 빼빼로 젓가락 행진곡, 만우절 엔터테이너, 식목일 비발디 봄, 복날 올드 맥도날드, 한글날 도레미 계단, D+·주년 캐논); solar terms (절기) are unrelated days and play random songs; when a song ends the streak moves to a different random song (never repeating the same one); copyrighted children's songs (까치 설날·어머님 은혜·달달 무슨 달…) are excluded. The birthday theme carries a `gift` image (public/celebrate/victory-birthday.webp) shown as a card after the first tap (✕/outside/Esc to close; shown even with reduced motion). Settings: text controls live in the 글자 tab (preview left, size/weight/font right, widened window) and must fit without scrolling at 1280×720 up to 20px.
- UI-44: (생일 선물·캡슐 뽑기) The viewer surface (`/`, anonymous or logged in) only ever plays the birthday song. Owner too (for now, owner decision 2026-10-06) — only the developer, with the developer toggle `calendars.birthday_gift_preview` on, gets `birthdayGift`/`gachaAnyDay` in the studio viewer preview, so the birthday mark's first tap opens the capsule machine (`components/poster/gacha-machine.tsx`) on any day; toggle off = song only. - UI-37: (상태 선택 강조) Use shared `--seg-on-*`/`--seg-off-op` for state segments. Selected state is tint plus inset hairline, not another bordered box inside a segmented card.

## Motion and ambient controls

- UI-27: (생동감 있는 동작·햅틱) Use immediate pressed feedback, shared transitions/springs, meaningful enter/exit and `hapticTick` on toggles/selectors/confirms; an action with press and server-confirm stages has two ticks. Chart hover values stay centered and clamped to their available bounds. Honor the in-app `html[data-reduce-motion]` state. The “생동감 있는 동작” switch defaults on; storage `vic.reduceMotion` keeps its inverse meaning. Do not independently seed/gate motion from the OS media query.
- UI-28: (생동감 있는 동작·배경 존재) “생동감 있는 동작” controls movement, not existence. When motion is off, ambient stays as a baked still frame if enabled. Its sole visibility preference is the ambient mode. Transparency selectors containing `:not([data-gfx="soft"])` must not also carry `:not([data-reduce-motion])` unless the block actually starts an animation; otherwise opaque UI hides the still canvas. No duplicate off option in the gfx selector. Evidence: `scene-engine.ts stillFrame` (dt=0 initialization and bounded late-asset retries) and `StudioSettingsList`.
- UI-29: (좌우 전환·튐) An element that crosses sides needs side-keyed animation names so CSS restarts the transition. Delayed both-filled animations must have identical direction-free held values; otherwise repeated toggles snap. Repeated-toggle measurement is below. Evidence: rail/avatar keyframes.
- UI-30: (계절 진입·편집 집중) Season entry animation uses backwards fill; both can pin opacity and defeat dim/showcase rules. Editor-open/drag focus dim affects only background opacity and work rate, never text or a blur filter. Ambient runtime rules are in ENGINE_RULES.
- UI-31: (미디어 일시정지) Heavy VOD/insights/studio modals pause ambient through `lib/ui/ambient-pause.ts`; settings are exempt for live inspection. Do not keep a full-screen animation behind blur/iframe media. Use events/ResizeObserver for poster follow/measure logic, not always-running rAF.
- UI-32: (오늘·업 도움·기간 안내) Today is marked on the full date label with the accepted gold tile and fading ends. Keep date-header height fixed, digits readable and selection ring above support/period bands. The 12px fade, 1.3em digits, 21px/18px badge and 8 > 7 > 6 layering contracts are below. Do not restore hard pills, elliptical radial glows or corner hairlines. Evidence: `--z-cal-select-ring`, `.d-num`, `.studio-day-head`.
- UI-33: (시청자 캡처·내보내기 은퇴) Public poster capture surfaces contain content, not editing/login/unlock controls. In-app PNG export and stickers are retired; do not recreate them or preserve constraints solely for removed sticker coordinates. Preserve current desktop geometry and explicit visual contracts when changing layout.

## Analytics UI

- UI-34: (이용 기록·장소) An activity area is a place, never a device or generic grouping. Use `AREA_ORDER`/`lib/activity/labels.ts` and registered `data-act` identifiers. Do not infer event ids from user-facing text or titles. Reason: it leaks content or merges unrelated actions.
- UI-35: (공개 인사이트) Public insights remain aggregate. Internal diagnostics use existing role/data boundaries; unknown roles stay unknown in records while authorization remains closed. Display partial/current periods as partial rather than comparing them to completed periods as equal.
