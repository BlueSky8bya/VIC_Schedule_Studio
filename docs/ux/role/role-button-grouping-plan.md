# 역할별 스튜디오 버튼 그룹핑 계획

목표: 평평하게 나열된 상단/액션바 버튼을 **성격이 비슷한 것끼리 묶어** 각 역할이 "내 작업
공간"처럼 느끼게 한다(시청자는 이미 완성형이라 제외 — owner/developer/manager/worker만).

원본 영감: `docs/role-based-ui-ux-audit-report.*.md`의 functional-zone 아이디어를, 이 앱 규모
(소유자 1·개발자 1·신뢰멤버 소수)에 맞게 **가볍게** 적용한다(전면 재설계 X, 회귀 위험 최소).

## 1. 현재 버튼 인벤토리 (코드 기준)

상단바 `studio-role-tools` ([studio-shell.tsx:2348](components/studio/studio-shell.tsx#L2348)):
- 역할 배지(+"?" 팝오버: 역할·이메일·권한) — 전원
- 비공개 일정 보기 / 비공개 표시 중 (private toggle) — viewer 외 전원
- 시청자 화면 미리보기 (viewerMode) — 전원
- 계정변경 / 로그인 — 인증

액션바 `studio-actionbar-tools` ([studio-shell.tsx:2390](components/studio/studio-shell.tsx#L2390)):
- 태그 편집 — owner/dev (`canEdit`)
- 멤버 관리 — owner/dev (`canEdit`)
- 🛠 접속자 현황 — dev only
- 달력 꾸미기 — owner/dev/manager/worker (`canDecorate`); manager/worker는 primary
- (dev) "🛠 개발자 세션입니다…" 안내 띠 (좌측)

## 2. 그룹(zone) 정의

버튼을 4개 성격으로 묶는다:

| 그룹 | 버튼 | 성격 |
|---|---|---|
| **A. 정체성/세션** | 역할 배지(?), 계정변경 | "나는 누구 / 계정" |
| **B. 보기 모드** | 비공개 일정 보기, 시청자 화면 미리보기 | "지금 무엇을 보는가" (view state 토글) |
| **C. 관리** | 태그 편집, 멤버 관리, (dev) 접속자 현황 | owner/dev 운영·관리 도구 |
| **D. 만들기** | 달력 꾸미기 | 포스터 제작 — 1차 창작 행동 |

배치 원칙:
- **상단바 = A + B** (정체성 왼쪽, 보기 모드 묶음 오른쪽, 계정변경 맨 끝).
- **액션바 = C(묶음) + D(단독·강조)**. C는 옅은 컨테이너로 한 덩어리, D(꾸미기)는 분리해 우측 강조.

## 3. 역할별 노출 매트릭스

| | A 정체성 | B 보기모드 | C 관리 | D 꾸미기 |
|---|---|---|---|---|
| 소유자 | 배지·계정변경 | 비공개·미리보기 | 태그·멤버 | 달력 꾸미기 |
| 개발자 | 배지·계정변경 | 비공개·미리보기 | 태그·멤버·**접속자현황** + 세션띠 | 달력 꾸미기 |
| 매니저 | 배지·계정변경 | 비공개·미리보기 | — (없음→숨김) | **달력 꾸미기(primary)** |
| 작업자 | 배지·계정변경 | 비공개·미리보기 | — (없음→숨김) | **달력 꾸미기(primary)** |

→ 매니저/작업자는 C가 비어 자동으로 깔끔해짐(상단 정체성+보기모드, 액션 꾸미기 하나).

## 4. 시각 처리 — 방안

### 방안 1 (추천) — 묶음 + 구분선, 한 줄 유지
- 상단바: B(비공개·미리보기)를 `<div class="studio-mode-group">`로 묶어 살짝 붙이고, 정체성/계정과는
  넓은 간격(또는 옅은 세로 구분선)으로 분리.
- 액션바: C(태그·멤버·접속자)를 옅은 배경·라운드의 `studio-manage-group` 한 덩어리로, D(꾸미기)는
  `margin-left:auto`로 우측에 분리 강조.
- 장점: JSX는 래퍼 div만 추가, 나머지는 CSS. **회귀 위험 최소.** 직관적으로 "묶였다"가 보임.

### 방안 2 — 그룹 라벨
각 묶음 앞에 작은 라벨("보기", "관리"). 더 명시적이지만 chrome이 늘어 owner 일상 사용엔 다소 무거움.

### 방안 3 — "관리 ▾" 오버플로 메뉴
C(태그·멤버·접속자)를 드롭다운 하나로 접고 D(꾸미기)만 노출 → 최대 정리. 단 드롭다운 상호작용
(열기/바깥클릭) 추가. owner/dev 액션바가 더 붐비게 느껴질 때의 후속 카드로 둔다.

**추천: 방안 1**을 기본으로, owner/dev가 여전히 붐비면 방안 3을 옵션으로.

## 5. 적용 후 스케치 (방안 1)

소유자:
```
[관리자 ?]        [👁 비공개 일정 보기 · 👁 시청자 미리보기]        [계정변경]
─ 관리: [태그 편집][멤버 관리] ──────────────────────  [✎ 달력 꾸미기]
```
매니저 / 작업자:
```
[매니저·작업자 ?]  [👁 비공개 일정 보기 · 👁 시청자 미리보기]      [계정변경]
──────────────────────────────────────────────  [✦ 달력 꾸미기]
```
개발자:
```
[개발자 ?]        [👁 비공개 · 👁 미리보기]                       [계정변경]
🛠 개발자 세션…   관리: [태그][멤버][🛠 접속자현황]        [✎ 달력 꾸미기]
```

## 6. 구현 접근 (방안 1)

- JSX: `studio-role-tools` 안에서 비공개·미리보기를 `studio-mode-group`으로 래핑.
  `studio-actionbar-tools` 안에서 태그·멤버·접속자를 `studio-manage-group`으로 래핑,
  꾸미기는 그 밖에 둬 `margin-left:auto`로 분리.
- 빈 그룹 처리: `studio-manage-group`은 안에 버튼이 하나도 없으면(매니저/작업자) 렌더하지 않음
  (`{(canEdit || isDeveloper) && (<div class="studio-manage-group">…)}`).
- CSS: 그룹 컨테이너에 옅은 배경/라운드 또는 세로 구분선(`border-left`)·간격. 기존 버튼 스타일 유지.
- 모바일(`m-rolebar`/모바일 관리 영역): 모바일은 이미 컴팩트(매니저/작업자는 꾸미기 숨김 등).
  같은 그룹 개념을 가볍게 적용하되, 라벨은 생략(모바일은 덜어내기 원칙). 데스크톱 우선 적용 후 점검.
- 접근성: 그룹에 `role="group"` + `aria-label`("보기 모드", "관리").

## 7. 범위·위험

- 위험: 낮음~중. `studio-role-tools`/`studio-actionbar-tools`는 flex라 래퍼 div 추가가 안전.
  topbar는 3열 그리드(좌제목 | 월 | role-tools)라 role-tools 내부만 손대면 영향 격리.
- 비범위: 시청자(완성형), 일정 편집 폼/달력 그리드, 포스터 표면 버튼(export/테마)은 이번 그룹핑 대상 아님.
- 경계 규칙 불변: 버튼 노출은 기존 `canEdit`/`canDecorate`/role 게이팅 그대로(서버 권한 불변).

## 8. 권장 순서

1. 방안 1을 데스크톱에 적용(상단 B 묶음 + 액션 C 묶음/꾸미기 분리) → 빌드·확인.
2. owner/dev가 붐비면 방안 3(관리 ▾ 메뉴)로 C를 접는다.
3. 모바일에 같은 그룹 개념을 컴팩트하게 반영.
