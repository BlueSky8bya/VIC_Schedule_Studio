# 편집실 크롬 압축 매뉴얼 — 창 비율이 망가졌을 때 (2026-09-04)

관리자 요청: "사용자가 억지로 창 비율을 망가뜨릴 때도(거의 없지만) 대응할 수 있게 규칙을 마련해 달라 —
관리자? 버튼은 ?만, 보여주기·로그아웃은 아이콘만, 저장됨 hh:mm은 저장됨만, 더 부족하면 동그라미만,
태그 필터는 '태그 필터' 글자까진 보이고 부족한 높이는 (빈) 아바타 자리에서 긁어온다."
같은 날 "편집 팝오버와 아바타 좌/우 알약이 겹치면 잘 안 보인다"도 여기서 다룬다.

적용 범위: 편집실 **웹 크롬(≥1000px 폭)**. 모바일(≤999px)은 제 크롬이 따로 있다(`STUDIO_AGENDA_QUERY`).

## 원칙

1. **뜨거운 것은 마지막까지, 차가운 것부터 접는다.** 달력·저장 상태·달 이동은 끝까지 남고, 라벨 → 버전 배지 →
   별(✨) → 아바타 자리 순으로 접힌다(30일 사용 데이터: 칸 361·저장 176 vs 관리 도구 0~2).
2. **접혀도 뜻은 남는다.** 라벨을 숨기는 요소는 전부 `aria-label`/`title`을 갖는다. 색이 상태를 대신한다
   (저장 점 = 초록/호박/빨강, 배지 배경 = 역할).
3. **임계 폭을 외우지 않는다.** 가로 단계는 JS가 "헤더 한 줄이 넘치는가"를 실측해 정한다 — 제목 길이·역할·
   브라우저 줌·글꼴이 달라도 맞다. 세로는 뷰포트 높이 미디어 + rail flex 예산.
4. **겹치면 비켜 선다, 못 비키면 물러선다.** 떠 있는 것(하단 알약)은 팝오버 옆으로 이동, 자리가 없으면 팝오버
   아래로 내려가 거의 투명해진다(클릭이 팝오버에 닿아야 한다).

## 가로 — 헤더 한 줄 (`.studio-shell[data-chrome]`, studio-shell.tsx `chromeTier`)

측정: `topbar.scrollWidth > clientWidth` 또는 제목·달·계정 세 칸이 서로 겹치면 "넘침". 단계를 0부터 올려
넘치지 않는 첫 단계에서 멈춘다(리사이즈·역할 변경·웹폰트 로드 때만, 동기 레이아웃 ≤4회). 계정 모서리의
버튼은 전부 `white-space: nowrap` — 한 글자씩 꺾여("보여/주기") 숨는 대신 넘침으로 드러나야 JS가 안다.

| 단계 | 접히는 것 | 남는 것 |
|---|---|---|
| 0 | — | 전부(≥ ~1140px 실측, 제목 "빅토리 일정표" 기준) |
| 1 | 미리보기 긴 라벨 → "보여주기"/"미리보기", 간격 8 | (CSS ≤1560px 미디어와 같은 모습 — JS는 보통 0→2로 건너뛴다) |
| 2 | 배지 라벨(관리자/개발자) → **"?"만**(배경색 = 역할) · 보여주기·로그아웃·역할 미리보기 → **아이콘만**(눈·나가기·눈) · 저장 시각 숨김 · 제목 20px | 저장 "저장됨" 글자, 버전 배지, 별 |
| 3 | 저장 상태 → **점만**(24px 원, 테두리·점 색이 상태) · 버전 배지 숨김 · 별 숨김 · 제목 17px · 달 라벨 22px · ‹ › 34px | 제목 글자, 달 이동, 저장 점, ?, 아이콘 둘 |

CSS: `components/studio/studio-calm-layer.css` ⑤. 실측(1600→1000 스윕, owner·developer): 넘침·겹침·두 줄 0,
전이 1140→1120px에서 0→2.

## 세로 — 서쪽 rail 예산 (studio-shell.css `.avatar-rail-filter` / `.avatar-slot`, calm-layer ⑤ 미디어)

rail = [태그 필터 | 도구 카드 | 아바타 자리] flex-column, 높이 = 창 − 상단바 − 8.

- **항상**: 필터 `flex: 1 1 132px; min-height: 132px`(제목 "태그 필터" + 칩 두 줄), 아바타 자리
  `flex: 0 4 58%; min-height: 0`. 합이 rail 안이면 예전과 픽셀 동일(아바타 58%, 필터가 나머지). 모자라면 빈
  아바타 자리가 4배 빠르게 먼저 줄고 필터는 132 아래로 안 내려간다. 도구 카드는 안 줄어든다.
- **≤620px 창**(1366×768 노트북 ≈650은 해당 없음): 도구 타일 **아이콘만**(한 줄 4개, ≤1300의 2×2도 한 줄로),
  rail 간격 6, 상단바 위아래 여백 10, 아바타 자리 기준 58→45%.
- **≤470px 창**: 아바타 자리 `display:none`(필터가 rail 전부), 상단바 여백 6, 달력 아래 알약 여백 72→56.
- 비 scene(좌측 그리드 칸 `.studio-left-panel`)은 sticky + `max-height: calc(100vh - 88px)` 스크롤이 이미 있고,
  도구 타일 아이콘만 규칙은 같이 받는다.

실측(1147 폭, 900→380 높이 스윕): "태그 필터" 제목 항상 카드 안, 필터 ≥132, rail 넘침 0; 620에서 타일 46px·
4열, 460에서 아바타 자리 0.

## 팝오버 ↔ 하단 알약 (studio-shell.tsx rAF 틱 dodge, studio-shell.css `.bottom-float-row`)

편집 팝오버가 열려 있는 동안 매 프레임: 알약 행의 **자연 위치**(화면 정중앙)와 팝오버 rect가 12px 여유 안에서
겹치면 → 팝오버 **옆**(가까운 쪽, workspace 안 8px 여백)으로 `--bfr-shift`만큼 이동(스프링 transition). 양옆
다 자리가 없으면 `data-dodge="fade"`: 행이 팝오버 **아래**(z 11 < 12)로 내려가고 알약은 opacity .14 — 팝오버가
읽히고 눌린다; 삐져나온 부분에 포인터가 오면 그 알약만 되살아난다. 팝오버가 닫히면 원위치.
(이동 중인 실제 rect로 재면 스스로를 쫓아 흔들린다 — 반드시 자연 위치 기준.)

## 새 요소를 헤더·rail에 넣을 때

- 헤더 계정 모서리에 넣는 버튼은 아이콘 + `<span class="lbl">라벨</span>` + `aria-label` + `title`, `nowrap`.
  ⑤에 2단계 숨김 한 줄을 추가한다. 긴/짧은 라벨이 있으면 `.lbl-long`/`.lbl-short`.
- rail에 카드를 더하면 예산부터: 필터 132 최소 + 도구 + 새 카드 + 아바타. 새 카드는 `flex: 0 0 auto`가 아니라
  줄어들 수 있게 하거나 ≤620 미디어에서 접는 규칙을 같이 넣는다.
- 새 플로팅 요소는 `.bottom-float-row` 안에 넣는다(회피 규칙을 공짜로 받는다). 따로 fixed로 띄우면 같은
  dodge를 다시 써야 한다.
