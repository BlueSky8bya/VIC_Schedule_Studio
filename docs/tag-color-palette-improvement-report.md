# VIC 태그 색상 팔레트 개선 보고서

작성일: 2026-06-04 KST  
범위: 코드 read-only 확인, DB SELECT 조회, 색상 개선 방향 제안  
비범위: 코드 수정, DB 업데이트, 마이그레이션 실행

## 1. 결론

현재 방향은 맞다. **콘텐츠 태그는 연한 채움색 + 패턴**, **방식 태그는 진한 단색**, **휴뱅은 회색 고정** 구조가 달력 UX에 적합하다.

다만 지금 상태 그대로 태그가 늘거나 전체 달력을 한 번에 보면 다음 문제가 생긴다.

- 색상만으로 19개 상위 태그를 기억해야 해서 인지 부담 큼.
- 콘텐츠 색 일부가 서로 가까움: 게임/소통뱅/별별랭킹, VRChat/월드컵, 기타/시네티.
- 일부 칩 텍스트 대비가 낮음: 게임, 소통뱅, 별별랭킹, 토크쇼 등.
- 방식 태그가 콘텐츠 색과 같은 시각 채널을 쓰면 "무슨 방송인가"보다 "어떤 방식인가"가 더 먼저 보일 수 있음.

개선 핵심:

1. **콘텐츠 태그만 달력 메인 채움색 담당.**
2. **방식 태그는 채움색이 아니라 링/점/보조 배지로 표시.**
3. **고빈도 콘텐츠 태그부터 hue 거리 크게 배치.**
4. **같은 색상군 재사용 시 패턴 필수.**
5. **모든 태그 텍스트 대비 4.5:1 이상 목표.**

- 낮은 빈도 태그는 색만으로 구분하기보다 레전드/필터/패턴 보조가 더 중요.

## 3. HCI/접근성 근거

### 3.1 색만 쓰면 안 됨

W3C WCAG 1.4.1은 색이 정보를 구분하는 유일한 수단이면 안 된다고 설명한다. 색을 쓰더라도 텍스트, 모양, 패턴 같은 보조 단서가 필요하다.

VIC 적용:

- 태그 이름 유지.
- 콘텐츠 패턴 유지.
- 방식 태그는 링/점/배지 같은 비색상 단서 추가.
- 필터 on/off는 색 변화만 말고 체크/선택 상태도 표시.

출처: https://www.w3.org/WAI/WCAG22/Understanding/use-of-color

### 3.2 범주 수가 늘수록 색 판별 어려움

CHI 2023 연구는 색상으로 구분하는 범주 수가 늘수록 사용자 판단이 어려워지고, 팔레트 판별력이 결과에 큰 영향을 준다고 보고한다.

VIC 적용:

- 콘텐츠 12개 이상을 모두 "색만"으로 구분하려 하면 실패 가능성 큼.
- 상위 빈도 태그는 강하게 구분.
- 하위 빈도 태그는 색 + 패턴 + 레전드 의존 허용.

출처: https://arxiv.org/abs/2303.15583

### 3.3 색 생성보다 "배정"이 중요

Palettailor 연구는 색을 잘 만드는 것뿐 아니라 데이터 특성에 맞게 어떤 범주에 어떤 색을 배정하는지가 중요하다고 본다.

VIC 적용:

- 사용량 많은 태그를 먼저 배치.
- 자주 동시에 나타나는 조합은 서로 멀리 배치.
- 방식 태그는 콘텐츠와 같은 채널을 쓰지 않게 분리.

출처: https://arxiv.org/abs/2009.02969

### 3.4 캘린더 벤치마크

Google Calendar 이벤트 색상은 named color 11개 수준으로 제한된다. 범주형 일정 UI는 색을 무한 확장하기보다 적당한 수의 안정된 색상 집합과 이름/레이블 체계를 함께 쓴다.

VIC 적용:

- 콘텐츠 상위색은 12개 내외로 유지.
- 휴뱅은 회색 시스템 색.
- 방식 태그는 별도 시각 채널.

출처: https://developers.google.com/apps-script/reference/calendar/event-color

ColorBrewer도 범주형 팔레트에서 색맹 안전성과 출력 환경을 고려한다.

출처: https://colorbrewer2.org/

## 4. 개선 목표

### 목표 A. 달력 전체 조망

사용자가 한 달을 봤을 때 즉시 알아야 하는 것:

1. 방송 있음/없음
2. 주요 콘텐츠 종류
3. 같은 콘텐츠가 며칠 이어지는 흐름
4. 방식 태그가 붙었는지

색상 우선순위:

| 우선순위 | 정보 | 시각 채널 |
|---:|---|---|
| 1 | 휴뱅 | 회색 채움 |
| 2 | 콘텐츠 | 연한 채움색 + 패턴 |
| 3 | 콘텐츠 2개 조합 | 2색 그라데이션 |
| 4 | 방식 | 링/점/작은 배지 |
| 5 | 추가 태그 | +N, 상세/툴팁/필터 |

### 목표 B. 읽기 가능성

- 칩 안 텍스트 대비 4.5:1 이상.
- 흰 배경 위 연한 색 스와치도 테두리로 식별 가능.
- 패턴은 8~11% 농도 유지. 글자와 경쟁 금지.

### 목표 C. 귀엽고 깨끗한 viewer

- viewer mode는 색이 밝고 부드럽게.
- studio mode는 실용적, 조작 상태 명확.
- private-layer mode와 색상 체계 섞지 않음.

## 5. 추천 팔레트 v1

### 5.1 콘텐츠 태그

원칙:

- bg는 현재 감성 유지.
- text만 더 어둡게 조정해 대비 확보.
- 패턴은 기존 gen 패턴 유지.
- 휴뱅은 회색 고정.

| 태그 | bg | text | border | 패턴 | 의도 |
|---|---|---|---|---|---|
| 휴뱅 | `#e9ecef` | `#495057` | `#ced4da` | none | 방송 없음, 낮은 채도 |
| 게임 | `#b2f2bb` | `#1b5e20` | `#69db7c` | diag | 최고 빈도, 밝은 초록 유지 |
| VRChat | `#d0bfff` | `#3b1f8f` | `#9775fa` | dots | 게임과 분리되는 보라 |
| 서버 | `#fcc2d7` | `#7a1239` | `#f783ac` | grid | 분홍, 서버 독립감 |
| 풀트뱅 | `#99e9f2` | `#055160` | `#3bc9db` | cross | 청록, 장기 흐름 식별 |
| 월드컵 | `#eebefa` | `#5f1470` | `#da77f2` | dash | 보라군이지만 패턴으로 VRChat 분리 |
| 기타 | `#a5d8ff` | `#0b4a7c` | `#4dabf7` | diag | 파랑, 낮은 빈도 |

| 시네티 | `#bac8ff` | `#263899` | `#748ffc` | dots | 남보라, 기타와 패턴 다름 |

예상 효과:

- 현재 감성 유지.
- 텍스트 대비 개선.
- 고빈도 콘텐츠 색상 우선 구분.
- 비슷한 색상군은 패턴으로 보조 구분.

### 5.2 방식 태그

원칙:

- 진한 배경 + 흰 글자.
- 달력 메인 채움색으로 쓰지 않음.
- 이벤트 칩 위에 작은 링/점/상단 바/우측 배지로 표시.

| 태그 | bg | text | border | 추천 표시 |
|---|---|---|---|---|
| 합방 | `#8e24aa` | `#ffffff` | `#6a1b9a` | 보라 링 |
| 대회 | `#c2410c` | `#ffffff` | `#9a3412` | 주황 링/트로피 아이콘 가능 |
| 연습 | `#1565c0` | `#ffffff` | `#0d47a1` | 파랑 점 |
| 시참 | `#c62828` | `#ffffff` | `#8e1b1b` | 빨강 점/사람 아이콘 가능 |
| 짧뱅 | `#00796b` | `#ffffff` | `#005f56` | 민트 작은 배지 |
| 모캡 | `#5e35b1` | `#ffffff` | `#4527a0` | 보라 작은 배지 |
| 구플뱅 | `#c2185b` | `#ffffff` | `#8c1641` | 분홍 작은 배지 |

주의:

- 합방/모캡 둘 다 보라계. 둘 다 방식이라 괜찮지만 같은 이벤트 안 동시 표시 가능성 있으면 아이콘/약어 필요.
- 대회 주황은 타스뱅송과 hue 가까움. 그래서 대회는 채움색이 아니라 링/배지로만 써야 함.

## 6. UI 표시 방식 개선안

### 6.1 달력 이벤트 칩

현재:

- 콘텐츠 색이 칩 배경.
- 콘텐츠 2개면 그라데이션.
- 방식도 extra color로 나타남.

개선:

- 메인 배경: 콘텐츠만.
- 방식: 칩 바깥/안쪽 링.
- 방식 여러 개: 최대 2개 점 + `+N`.

권장 구조:

| 이벤트 태그 | 표시 |
|---|---|
| 게임 | 연초록 채움 + 게임 패턴 |
| 게임 + VRChat | 2색 그라데이션 |
| 게임 + 합방 | 연초록 채움 + 보라 링 |
| 게임 + 합방 + 대회 | 연초록 채움 + 보라/주황 점 |
| 휴뱅 | 회색 채움, 콘텐츠색 무시 |
| 휴뱅 + 방식 | 회색 채움 + 방식 링만 |

### 6.2 색상 필터/레전드

개선:

- 그룹 순서: 휴뱅 / 콘텐츠 / 방식.
- 콘텐츠는 스와치 크게, 방식은 작은 점/링으로 다르게.
- 필터 on 상태는 색만 말고 체크/두꺼운 테두리/pressed 상태 병행.
- 비슷한 색끼리 인접 배치 금지. 게임 옆에 소통뱅/별별랭킹 두지 않기.

추천 정렬:

1. 휴뱅
2. 게임
3. VRChat
4. 서버
5. 풀트뱅
6. 타스뱅송
7. 시네티
8. CK
9. 월드컵
10. 기타
11. 소통뱅
12. 토크쇼
13. 별별랭킹
14. 방식 그룹: 합방, 대회, 연습, 시참, 짧뱅, 모캡, 구플뱅

이유:

- 고빈도 먼저.
- 가까운 hue 분산.
- 낮은 빈도/기타성 태그 후반.
- 방식은 별도 그룹.

### 6.3 모바일

모바일은 색 면적 작음. 패턴이 흐려질 수 있음.

권장:

- 이벤트 제목 앞 3~4px 세로 막대는 콘텐츠색.
- 방식은 제목 오른쪽 작은 점.
- 레전드는 2열 wrap, 방식 그룹 별도 줄.
- 선택된 필터는 체크 아이콘 또는 `aria-pressed` 시각 상태.

### 6.4 포스터/export

포스터는 캡처/압축/공유에서 색 손실 가능.

권장:

- 패턴 대비 약간 유지하되 11% 넘기지 않기.
- 텍스트는 반드시 어두운 색.
- 방식 링은 2px 이상. 1px은 export 후 흐림 가능.
- 휴뱅 회색은 너무 옅지 않게 border 유지.

## 7. 구현 단계 제안

### PR1. 팔레트 텍스트 대비 보정

범위:

- 기존 bg/border 최대한 유지.
- text_color만 위 추천값으로 교체.
- 방식 bg를 더 어둡게 조정.

리스크:

- 낮음.
- 시각 감성 유지하면서 읽기성 개선.

검증:

- 모든 태그 text/bg contrast >= 4.5.
- viewer/studio 레전드 텍스트 읽힘.
- poster export 텍스트 흐림 없음.

### PR2. 방식 태그 시각 채널 분리

범위:

- 콘텐츠는 칩 배경.
- modifier는 칩 링/점/배지.
- 필터 레전드도 방식은 점/링 형태.

리스크:

- 중간.
- 기존 extra color 표시 방식과 렌더 영향 있음.

검증:

- `게임+합방`이 보라 채움으로 보이지 않음.
- `게임+VRChat+합방`에서 콘텐츠 2색 + 방식 보조 표시.
- 휴뱅 우선순위 유지.

### PR3. 빈도 기반 자동 배치 규칙 정리

범위:

- `recolor-tags.mjs` 같은 재색칠 스크립트는 사용량 내림차순 유지.
- hue 충돌 검사.
- content/modifier 팔레트 별도 관리.

리스크:

- 중간.
- DB 업데이트 스크립트라 적용 전 preview 필요.

검증:

- dry-run 모드 추가 권장.
- 적용 전/후 태그별 색상 표 출력.
- KST 일정 데이터 자체 변경 없음.

### PR4. 시각 QA

범위:

- viewer month
- studio month
- mobile agenda
- poster export
- colorblind simulation 가능하면 추가

검증 기준:

- 전체 달력에서 게임/VRChat/서버/풀트뱅 즉시 구분.
- 방식 태그가 콘텐츠보다 먼저 튀지 않음.
- 필터 on/off 상태 색 없이도 구분.
- 작은 화면에서 태그명 잘림/겹침 없음.

## 8. QA 체크리스트

- [ ] 모든 태그 칩 text/bg contrast >= 4.5.
- [ ] 휴뱅은 항상 회색 우선.
- [ ] 콘텐츠 없는 modifier-only 이벤트가 있다면 기본 배경 + 방식 배지로 표시.
- [ ] 콘텐츠 1개 + 방식 N개: 콘텐츠 채움 유지.
- [ ] 콘텐츠 2개 + 방식 N개: 콘텐츠 2색 유지, 방식 보조 표시.
- [ ] 콘텐츠 3개 이상: 대표 2색 + `+N`, 나머지는 상세/툴팁.
- [ ] 필터 선택 상태가 색만으로 전달되지 않음.
- [ ] 포스터 export 후 링/패턴 깨짐 없음.
- [ ] mobile 360px 폭에서 레전드 wrap 정상.
- [ ] viewer public API에 private data 노출 없음.

## 9. 최종 추천

가장 좋은 개선 순서:

1. **텍스트 대비 보정 먼저.** 가장 작고 효과 큼.
2. **방식 태그를 링/점으로 분리.** 달력 전체 조망 품질 가장 크게 개선.
3. **레전드 그룹/정렬 개선.** 사용자가 색 의미를 학습하기 쉬워짐.
4. **자동 재색칠은 dry-run 만든 뒤 적용.** DB 색상 대량 변경은 preview 필요.

최종 형태:

> 콘텐츠는 달력의 "무엇".  
> 방식은 달력의 "어떻게".  
> 휴뱅은 달력의 "없음".  
> 이 세 가지를 서로 다른 시각 채널로 나눠야 전체 달력이 조화롭고 구분 가능해짐.
