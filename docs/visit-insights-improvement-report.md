## 1. 현재 상태 (세션 이벤트 모델로 교체 완료)

옛 모델(`visit_log` 일1회 + `presence_ping` 분 단위 버킷)을 **`visit_session` 한 테이블**로 통합했다.

- **한 줄 = 화면이 보이는 한 번의 방문.** 재진입하면 또 한 줄(여러 번 기록).
- 컬럼: `started_at`(진입) · `last_seen_at`(25초 하트비트) · `ended_at`(이탈, null이면 last_seen을 종료로).
- **체류 = `coalesce(ended_at, last_seen_at) − started_at` (초 단위).** 분 버킷의 반올림 한계 제거.
- **유령 방문 차단**: `content-ready` 신호(실제 달력 = PublicPoster/StudioShell 마운트) + `visible`일 때만 세션 시작 → 프리렌더·프리패치·백그라운드 로드(안 본 화면)는 0.
- 집계는 RPC 없이 JS에서(스트리머 1명 규모라 행을 받아 계산). 모든 그래프(일일 상세·월별 방문 패널·트렌드)가 같은 소스.
- 개인정보 비저장 유지: `account_hash`(단방향) · 역할 · 기기만.

### 현재 지표 정의
- **방문 수 / 역할별·기기별** = 순방문자(=`(날짜, 계정)` 고유, 계정당 하루 1). 재진입 세션은 합쳐짐.
- **시간대 동접 막대** = 세션 구간 초를 시간대별로 쪼개 `초/(3600×관측일수)` = 하루 평균 동접. `.vt-seg min-height`로 1초 방문도 한 조각.
- **관리자 방문 기록 / 접속 세션** = `role=owner` 세션을 세션별로(여러 줄), 시각·기기·체류(초)·계정(설정 owner 이메일 매칭 시 이메일, 아니면 `#N`).

## 2. 남은 문제점 (왜 더 손봐야 하나)

### P1. "방문 수"에 노이즈가 섞임 — **가장 큼**
프리렌더는 막았지만, **0~1초짜리 순간 진입**(실수 탭·바로 뒤로가기)이 아직 방문 1로 잡힌다.
세션 모델이라 이제 체류 초를 알므로, **최소 체류 미만은 방문에서 빼면** "방문 수"가 즉시 깔끔해진다.

### P2. 운영진 트래픽이 신호를 가림 — **체감상 가장 큼**
지금 그래프는 **개발자(본인) 테스트 트래픽이 지배**한다. 관리자(toryvac)도 운영 목적 접속이 잦다.
"진짜 시청자가 언제·얼마나 오나"가 운영진에 묻혀 안 보인다. → 운영진을 분리/제외해야 신호가 산다.

### P3. 지표가 한 종류뿐이라 의미가 좁음
"방문 수(순방문자)"만 있다. **재방문 여부·체류 시간·이탈**을 모르니 "왔다"는 알아도 "의미 있게 봤나"를 모른다.
세션 모델이라 이 지표들은 이제 추가 비용이 거의 없다.

### P4. 레거시 잔존 + 무한 증가
`visit_log`·`presence_ping` 테이블과 `presence_hourly/peak/active_days/owner_sessions` RPC가 **미사용으로 남아 있다**.
`visit_session`은 보존 정책 없이 계속 쌓인다(규모는 작지만 방치 시 누적).

## 3. 권장안 (이 프로젝트 기준)

스트리머 1명 · 운영진 소수 · 시청자 규모 작음 · KST · 개인정보 비저장 — 이 맥락에 맞춰 우선순위화.

### 지금 하기 (작고 안전, 효과 큼)

**R1. 방문에 '최소 체류' 컷 (P1)**
- 규칙: 세션 체류 `< 3초`는 **방문 수·역할별·기기별 reach 카운트에서 제외**. (동접 막대·세션 목록엔 그대로 남겨 "있긴 있었다"는 보존.)
- 구현: `reachSlot`에서 `sEnd−sStart >= 3000ms`인 세션만 카운트. 한 함수만 수정 → 모든 그래프에 일괄 반영.
- 근거: 프리렌더 차단(visible 게이트) 위에 한 겹 더 — 실수 진입까지 걸러 "방문 수"가 사람 기준으로 정직해진다.

**R2. 운영진 분리 (P2)**
- 방식 A(추천): 방문 패널·일일 상세 헤드라인을 **"시청자 방문"** 기준으로, 운영진(owner·developer·manager·worker)은 별도 작은 줄로. 그래프는 "운영진 제외" 토글 1개.
- 방식 B(가벼움): 헤드라인 숫자만 시청자(viewer) 기준으로 바꾸고, 역할별 분해는 그대로(운영진도 색으로 보임).
- 구현: 집계에 `role === "viewer"` 필터 분기 + 토글 상태. 데이터는 그대로(역할이 행에 있으니 분기만).
- 근거: 본인·관리자 테스트가 시청자 신호를 가리는 게 지금 가장 거슬리는 지점.

**R3. 방문 횟수(세션 수) 같이 표기 (P3 일부)**
- 헤드라인 "N 방문(순방문자)" 옆에 "· 세션 M회"(재진입 포함). 둘 다 보이면 "여러 번 기록"의 의미가 안 헷갈린다.
- 구현: reach.total(이미 있음) + 세션 배열 length. 표시만 추가.

### 곧 추가하면 좋음 (세션 모델이라 저비용)

**R4. 평균/총 체류 시간** — 일·월 평균 체류(초/분), 총 체류. `fmtDur` 재사용.
**R5. 이탈(바운스)률** — 체류 `< 10초` 세션 비율. "와서 바로 나간 비율".
**R6. 새 방문자 vs 재방문자** — `account_hash`가 날짜 넘어 유지되니, 그 달 처음 온 계정/다시 온 계정 분리. (account_hash 인덱스 1개 추가 권장.)
**R7. 월 최고 동시 접속** — 헤드라인에 "최고 N명 동접"(이미 peak 계산 있음, 월 최댓값만 노출).

### 큰 개편 때 묶기 (지금 급하지 않음)

**R8. 레거시 정리 (P4)** — `visit_log`·`presence_ping` 테이블 + 4개 RPC를 drop하는 마이그레이션. 충분히 안정화 확인 후.
**R9. 보존 정책** — `visit_session` 6개월 경과 행 정리(수동 SQL 또는 cron). 규모상 급하진 않으나 정해두면 깔끔.
**R10. 동접 인원 dedup** — 한 사람 2탭이면 동접 2로 잡힘. "동접 인원(계정 dedup)" vs "동접 세션" 구분 옵션. 규모상 후순위.

## 4. 추천 실행 순서

1. **R1(최소 체류 컷)** — 1개 함수 수정, 즉시 방문 수 정화.
2. **R2(운영진 분리)** — 토글 1개 + 집계 분기. 진짜 신호 확보.
3. **R3(세션 수 병기)** — 표시만. 의미 명확화.
4. (선택) R4·R5·R7 — 헤드라인 KPI 보강.
5. 나중 큰 개편에서 R8·R9.

> R1~R3은 데이터 모델 변경 없음(집계/표시만) → 마이그레이션 불필요, 위험 낮음.
> R6은 인덱스 1개 추가 권장(작은 마이그레이션).

## 5. 리스크 / 주의

- **최소 체류 컷 값(3초)**: 너무 크면 짧지만 진짜인 방문이 빠진다. 3초 권장, 추후 조정 가능. 동접/세션 목록엔 남기므로 데이터 손실 아님(표시 기준만).
- **운영진 제외**: 기본값을 "제외"로 할지 "포함+토글"로 할지는 취향. 운영 점검용이면 토글로 둘 다 보게.
- **과거 데이터**: 세션 모델 전환(오늘)부터 누적. 지난달 그래프는 빈 게 정상.
- **개인정보 경계**: 계정 식별은 설정된 owner 이메일 매칭 한정 — 일반 시청자는 익명 유지(R2/R6도 이 원칙 유지).
