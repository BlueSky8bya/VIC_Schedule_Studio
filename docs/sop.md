# VIC Schedule Studio SOP

## 1. 프로젝트 정체성

프로젝트명: VIC Schedule Studio  
저장소명: vic-schedule-studio  
한글명: VIC 스케줄 스튜디오  
줄임말: VIC Studio

VIC Schedule Studio는 빅토리님을 위한 스트리머 중심 일정 스튜디오다.

이 앱은 일반 캘린더가 아니다. 공개 방송 일정을 계획하고, 비공개 작업/엠바고 일정을 안전하게 관리하고, 월간 캘린더를 포스터처럼 꾸미고, 시청자에게 보여줄 일정 이미지를 내보내기 위한 방송 운영 도구다.

## 2. 프로젝트 목적: 몰입

이 프로젝트의 핵심 목적은 **몰입**이다.

여기서 몰입은 다음을 뜻한다.

- **체감성능**: 클릭, 저장, 이동, 업로드, 잠금 해제, 내보내기 같은 모든 행동이 즉시 반응하는 것처럼 느껴져야 한다. 로딩, 전환, 낙관적 반영, 실패 복구 상태가 분명해야 한다.
- **유저-시스템 유대**: 앱은 차가운 관리자 패널이 아니라, 사용자의 역할과 상황을 이해하는 따뜻하고 믿을 수 있는 도구처럼 느껴져야 한다.
- **재미를 위한 움직임**: 애니메이션은 일정 관리와 포스터 꾸미기를 귀엽고 생동감 있게 만들어야 한다. 단, 가독성, 접근성, 작업 효율을 해치면 안 된다.
- **역할별 몰입**: 소유자, 매니저, 작업자, 개발자, 시청자는 각자 자기 역할에 맞는 화면과 도구를 받고 있다고 느껴야 한다.

핵심 약속:

> 시청자는 공개 일정 데이터만 받아야 한다. 비공개, 엠바고, 작업용, 소유자 전용, 운영용, 관리자용 데이터는 공개 UI나 공개 API 응답에 절대 섞이면 안 된다.

## 3. 절대 규칙

1. 모든 시간 기준은 KST / Asia/Seoul이다.
2. 공개 데이터와 비공개 데이터는 서버에서 분리한다. CSS로 숨기는 방식은 금지한다.
3. 일반 일정의 전체 생성/수정/삭제 권한은 소유자에게 있다. 개발자는 시스템 유지보수 목적의 상위 권한을 가지지만, 소유자 전용 일정은 소유자 전용으로 유지한다.
4. 개발자는 시스템 유지보수자다. 스트리머 소유자와 다르다.
5. 매니저는 방송 운영 보조 역할이다.
6. 작업자는 창작/제작 협업 역할이다.
7. 시청자는 공개 포스터와 공개 일정만 본다.
8. 비공개 레이어 접근은 Google 로그인과 유효한 비밀번호 잠금 해제 세션이 모두 필요하다.
9. 비공개 레이어 잠금 해제는 사용자 세션별이며 전역으로 풀리면 안 된다.
10. 공개 API 응답에는 엠바고, 작업용, 소유자 전용, 비공개 메모, 운영 정보, 관리자 경고가 포함되면 안 된다.
11. 시청자 화면은 귀엽고 깨끗하며 포스터 중심이어야 한다.
12. 스튜디오 화면은 실무적이고 반복 작업에 편해야 한다.
13. 비공개 레이어 표시 중에는 강한 경고가 필요하다.
14. 포스터/export 화면에는 관리자 UI가 포함되면 안 된다.
15. 방송 태그 색상은 날짜별 대표색 최대 2개로 제한한다.

## 4. 역할 정의

### 4.1 시청자

시청자는 공개 일정을 보는 사용자다.

- Google 로그인 후 소유자/신뢰 멤버가 아니면 시청자로 처리한다.
- 루트(`/`)에서 공개 포스터/캘린더를 본다.
- 공개 일정, 공개 태그, 공개 스티커, 공개 업 도움 링크를 볼 수 있다.
- 월 이동, 필터, 좋아요/저장 같은 공개 상호작용을 사용할 수 있다.
- 비공개 레이어 토글을 볼 수 없다.
- 엠바고/작업용/소유자 전용 일정을 볼 수 없다.
- 어떤 편집도 할 수 없다.

### 4.2 작업자

작업자는 빅토리님과 함께 제작물을 만드는 창작 협업자다. 예: 버츄얼 의상, 그림, 이미지, 스티커, 포스터 자료 작업자.

- Google OAuth로 로그인해야 한다.
- `trusted_members`에 등록되어 있어야 한다.
- 한 계정이 매니저와 작업자 역할을 동시에 가질 수도 있다. 이 경우 화면의 기본 역할은 매니저로 보되, 작업자 성격의 안내도 함께 보여줄 수 있다.
- 비공개 레이어 토글을 볼 수 있다.
- 비밀번호 잠금 해제 후 엠바고/작업용 일정을 볼 수 있다.
- 소유자 전용 일정은 볼 수 없다.
- 일반 일정, 태그 자체, 멤버, 비밀번호, 업 도움 기간/링크는 수정할 수 없다.
- 작업용 일정 확인, 이미지 자료 업로드, 스티커, 포스터 꾸미기 흐름이 중심이다.
- 소유자 계정을 빌려 쓰는 사람이 아니라 자기 계정으로 제한된 제작 업무만 수행하는 사람이어야 한다.

### 4.3 매니저

매니저는 방송 운영 보조 역할이다. 예: 방송 매니저, 채팅 매니저, 커뮤니티 흐름을 돕는 사람.

- Google OAuth로 로그인해야 한다.
- `trusted_members`에 등록되어 있어야 한다.
- 한 계정이 매니저와 작업자 역할을 동시에 가질 수도 있다. 매니저 권한이 있으면 방송 운영 역할이 우선 적용된다.
- 비공개 레이어 토글을 볼 수 있다.
- 비밀번호 잠금 해제 후 엠바고/작업용 일정을 볼 수 있다.
- 소유자 전용 일정은 볼 수 없다.
- 일반 일정, 태그 생성/삭제/색상, 멤버, 비밀번호는 수정할 수 없다.
- 업 도움 일정의 기간/링크 수정은 매니저에게만 열 수 있다.
- 일정별 태그 할당은 매니저에게 열 수 있다. 단, 태그 자체의 생성/삭제/이름/색상 변경은 소유자/개발자 전용이다.
- 시청자 화면 점검, 업 도움 링크 확인, 공지 초안 확인, 방송 관련 링크 점검이 어울린다.
- 포스터 꾸미기 도구는 사용할 수 있지만, 제작 자료 관리의 주 책임은 작업자 화면에서 더 잘 드러나야 한다.

### 4.4 소유자

소유자는 스트리머 본인, 즉 빅토리님이다. (역할 키는 `owner`지만, 화면에 보이는 라벨은 "관리자"다.)

- Google OAuth로 로그인해야 한다.
- `OWNER_EMAIL`에 등록된 Google 계정은 소유자다.
- 여러 Google 계정을 쉼표로 등록할 수 있다.
- 첫 계정은 기본 소유자이며, 추가 계정은 공동 소유자로 동기화될 수 있다.
- 모든 소유자 계정은 동일한 권한을 가진다.
- 일반 일정, 공개/엠바고/작업용/소유자 전용 일정을 만들고 수정하고 삭제할 수 있다.
- 태그, 색상, 신뢰 멤버, 비공개 비밀번호, 포스터 테마, 스티커, 업 도움 관련 설정을 관리할 수 있다.

### 4.5 개발자

개발자는 플랫폼/시스템 유지보수자다. 스트리머 소유자와 구분된다.

- Google OAuth로 로그인해야 한다.
- `platform_admins` 테이블로 판별한다.
- 소유자보다 먼저 개발자 여부를 확인한다.
- 디버깅과 유지보수를 위해 넓은 관리 권한을 가진다.
- 단, 소유자 전용 일정은 읽거나 만들 수 없다.
- 공개 API 응답은 개발자에게도 동일하게 공개 데이터만 포함해야 한다.
- 엠바고/작업용 정보 읽기에는 여전히 유효한 잠금 해제 세션이 필요하다.
- 개발자 세션은 화면에서 분명히 드러나야 한다(현재: 스튜디오 상단 개발자 세션 안내 + 접속자 현황 패널).
- 개발자 전용 역할 미리보기(관리자/매니저/작업자/시청자 화면 점검)를 제공한다. 클라이언트 한정이며 라우트/쿠키를 건드리지 않고(새로고침 시 해제), 미리보기 중 변경은 막히는 보기 전용이다. 화면 점검용이지 권한 상승 기능이 아니다.

## 5. 공개 범위

일정 공개 범위는 다음 중 하나다.

- `public`: 모두에게 공개.
- `embargo`: 공개 전 일정. 잠금 해제한 소유자/매니저/작업자/개발자만 볼 수 있다.
- `work`: 작업용 일정. 잠금 해제한 소유자/매니저/작업자/개발자만 볼 수 있다.
- `owner_private`: 소유자 전용 일정. 소유자만 볼 수 있다.

공개 화면의 날짜 색상 계산은 공개 일정만 사용한다. 엠바고/작업용/소유자 전용 일정의 태그 색상이 공개 캘린더에 영향을 주면 안 된다.

## 6. 앱 모드

### 6.1 시청자 모드

시청자가 보는 공개 화면이다.

보여줄 것:

- 공개 일정
- 공개 방송 태그
- 공개 업 도움 카드/링크
- 공개 스티커
- 공개 범례
- 월 이동, 필터, 좋아요/저장

숨길 것:

- 편집 컨트롤
- 비공개 레이어 토글
- 운영 정보
- 엠바고/작업용/소유자 전용 일정
- 비공개 메모
- 저장 상태
- 관리자 경고

### 6.2 라이브 안전 스튜디오 모드

소유자, 개발자, 신뢰 멤버가 역할에 맞는 작업을 하는 스튜디오 화면이다. 방송 중 소유자가 시청자와 함께 일정을 계획할 때도 이 모드를 사용한다.

보여줄 것:

- 공개 일정
- 소유자/개발자에게 일정 편집
- 소유자/개발자에게 태그 관리
- 매니저에게 업 도움 기간/링크 수정과 일정별 태그 할당
- 작업자에게 작업용 일정 확인과 제작 자료/꾸미기 흐름
- 역할에 맞는 스티커/포스터 꾸미기 컨트롤
- 포스터 미리보기
- 비공개 레이어 토글

숨길 것:

- 잠금 해제 전 엠바고/작업용/소유자 전용 일정
- 신뢰 멤버에게 일반 일정 생성/삭제/전체 편집
- 작업자에게 업 도움 기간/링크 수정
- 매니저와 작업자에게 태그 생성/삭제/색상 변경

### 6.3 비공개 레이어 모드

소유자/신뢰 멤버가 비밀번호로 잠금 해제한 뒤 보는 모드다.

보여줄 수 있는 것:

- 공개 일정
- 엠바고 일정
- 작업용 일정
- 소유자에게만 소유자 전용 일정
- 허용된 비공개 메모
- 충돌/주의 경고

필수 경고 문구(현재 코드의 실제 노출 문구와 일치):

`⚠ 비공개 일정 표시 중입니다. 방송 화면 공유에 주의하세요.`

### 6.4 포스터 모드

이미지 export를 위한 화면이다.

보여줄 것:

- 캘린더
- 공개 일정
- 공개 태그 색상
- 업 도움 카드
- 스티커
- 범례

숨길 것:

- 스튜디오 패널
- 편집 컨트롤
- 운영 경고
- 비공개 레이어 경고
- 저장 상태
- 관리자 버튼

## 7. 방송 태그

규칙:

- 태그 이름과 색상은 소유자가 관리한다.
- 개발자는 시스템 유지보수 목적에서 태그 관리가 가능하지만, 공개/비공개 데이터 경계를 깨면 안 된다.
- 일정 하나에 붙일 수 있는 태그는 최대 2개다.
- 날짜 칸에 드러나는 태그 색상도 최대 2개다.
- 태그가 이미 2개 붙어 있으면 추가 태그를 더 붙일 수 없다.
- 매니저는 일정별 태그 할당을 도울 수 있다. 단, 새 태그를 만들거나 태그 이름/색상을 바꾸는 일은 소유자/개발자 전용이다.
- 작업자는 태그를 읽고 참고할 수 있지만, 태그 할당이나 태그 관리는 하지 않는다.
- 비공개 일정의 태그 색상이 공개 화면에 새면 안 된다.

## 8. 데이터 경계

공개 데이터와 비공개 데이터는 query/DTO 단계에서 분리해야 한다.

공개 DTO에 절대 포함하면 안 되는 것:

- private_title
- private_memo
- editor_note
- embargo events
- work events
- owner_private events
- owner email
- trusted member list
- passcode info
- operational updated_at
- link validation result
- admin warnings

비공개 레이어 DTO에 엠바고/작업용 데이터를 포함할 수 있는 조건:

1. 사용자가 인증되어 있다.
2. 사용자가 소유자 또는 활성 신뢰 멤버다.
3. 사용자가 비공개 레이어 접근 권한을 가진다.
4. 사용자가 유효한 잠금 해제 세션을 가진다.
5. 잠금 해제 세션의 비밀번호 버전이 현재 설정과 일치한다.

소유자 DTO는 소유자 검증 후 편집 가능한 전체 데이터를 포함할 수 있다.

## 9. 체감성능과 애니메이션 원칙

체감성능과 몰입은 나중에 넣는 장식이 아니라 제품 목적이다.

### 9.1 체감성능

- 빈 화면 대기를 만들지 않는다.
- 인증/역할/데이터를 기다리는 라우트는 공개 안전 셸을 먼저 보여준다.
- 로딩 셸에는 비공개 데이터, 편집 버튼, 잠금 해제 버튼이 들어가면 안 된다.
- 사용자 행동은 가능한 한 즉시 화면에 반영하고, 서버 결과와 나중에 맞춘다.
- 낙관적 UI는 체감일 뿐이며, 서버가 권한과 저장의 최종 권위다.
- OAuth, 비공개 잠금 해제, 포스터 export, 라우트 이동처럼 여러 단계가 있는 일은 현재 단계를 말로 보여준다.
- 실패는 사람이 이해할 수 있는 문장과 복구 방법으로 보여준다.
- 비공개 잠금 해제 실패에서는 개수, 제목, 시간 같은 힌트도 드러내지 않는다.

### 9.2 애니메이션

- 움직임은 사용자가 만든 상태 변화를 설명해야 한다.
- 의미 없는 장식 애니메이션은 줄인다.
- 월 이동은 방향감 있게 움직여 사용자가 위치를 잃지 않게 한다.
- 포스터는 16:9 캔버스처럼 안정적으로 유지되어야 한다.
- 애니메이션은 빠르고 가벼워야 한다.
- `prefers-reduced-motion`을 존중한다.
- 시청자/포스터 화면은 귀엽고 생동감 있게, 스튜디오는 실무적으로 유지한다.

### 9.3 모바일

- 모바일은 줄이는 것이 아니라 덜어내는 것이 핵심이다.
- 긴 설명, 보조 문구, 부가 컨트롤은 모바일에서 숨길 수 있다.
- 작은 화면에서는 한 줄로 핵심만 전달한다.
- 프로젝트 기준 모바일 breakpoint는 `640px` 이하로 본다.

## 10. 개발 하네스

중요한 작업은 planner, builder, evaluator 루프를 따른다.

### 10.1 Planner

구현 전에 확인할 것:

- 영향을 받는 route/component
- 역할과 권한 영향
- 공개/비공개 데이터 경계
- KST 가정
- 시청자/소유자/매니저/작업자/개발자별 기대 동작

### 10.2 Builder

구현 중 지킬 것:

- 기존 앱 패턴을 따른다.
- 서버 권한 검사를 유지한다.
- client-only 권한 숨김을 유일한 보호 장치로 쓰지 않는다.
- 명시 요청 없이 매니저/작업자를 일반 일정 편집 가능하게 만들지 않는다.
- 권한이 없는 사람에게 꺼진 소유자 편집 화면을 보여주기보다, 역할에 맞는 화면을 제공한다.

### 10.3 Evaluator

완료 전에 확인할 것:

- 비공개 데이터 누출 없음
- 소유자 전용 콘텐츠는 소유자 전용 유지
- 매니저와 작업자 동작이 분리됨
- 시청자 화면은 깨끗함
- 비공개 레이어 경고가 명확함
- 포스터/export 결과에 관리자 UI가 없음
- 체감성능과 애니메이션 상태가 의미 있음
- 테스트 또는 수동 검증 내용을 기록함

## 11. 완료 기준

작업 완료 전 확인:

1. TypeScript 통과.
2. lint 통과.
3. 공개/비공개 데이터 경계 확인.
4. 공개 API에 비공개 필드 없음.
5. 소유자 전용 write route가 비소유자를 거부함.
6. 매니저/작업자가 일반 일정을 편집할 수 없음.
7. 작업자는 업 도움 기간/링크를 수정할 수 없음.
8. 매니저의 일정별 태그 할당은 허용 범위 안에서만 동작함.
9. 작업자는 태그 할당이나 태그 자체 관리를 할 수 없음.
10. 비공개 레이어 데이터에는 유효한 잠금 해제 세션이 필요함.
11. KST 날짜 로직 유지.
12. 태그 색상이 비공개 정보를 누출하지 않음.
13. 포스터 모드에 관리자 UI 없음.
14. 관련 문서 업데이트.
15. 새 async 흐름은 현재 단계를 보여주고 친절하게 실패함.
16. 새 애니메이션은 실제 상태 변화를 설명하고 reduced-motion 대안을 가짐.

## 13. 현재 구현 기준 메모

이 SOP는 제품 방향과 현재 권한 구조의 기준 문서다. 구현 세부는 계속 변할 수 있지만, 현재 프로젝트는 다음 흐름을 기준으로 한다.

- 역할 판별은 서버에서 한다.
- 개발자는 소유자보다 먼저 판별된다.
- `OWNER_EMAIL`은 여러 계정을 쉼표로 받을 수 있다.
- 신뢰 멤버는 매니저/작업자 플래그를 동시에 가질 수 있다.
- 매니저 플래그가 있으면 화면의 기본 역할은 매니저로 본다.
- 소유자/개발자는 일반 일정과 태그 자체를 관리할 수 있다.
- 매니저는 일반 일정 본문을 수정하지 않고, 업 도움 기간/링크와 일정별 태그 할당만 도울 수 있다.
- 작업자는 제작 자료와 꾸미기 중심이며, 업 도움 기간/링크와 태그 할당은 수정하지 않는다.
- 스티커/포스터 꾸미기는 소유자, 개발자, 매니저, 작업자가 모두 사용할 수 있다.
- 포스터 테마 변경은 소유자/개발자 중심으로 유지한다.
