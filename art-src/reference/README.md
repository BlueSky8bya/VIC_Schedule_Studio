# 취향 레퍼런스 서고 — 엔티티 범주별 참고 그림

생성 의뢰에 **첨부하는** 그림 중 "발상" 쪽이 여기 산다. 계획서 [PLAN-20260909-011](../../docs/agent/plans/PLAN-20260909-011-reference-library.md).

## 왜 그림인가

3차 소나무 납품이 **수치 여덟을 전부 통과하고 반려**됐다. 틀린 둘은 **말로만 적혀 있던 것**이었다.
교훈은 지표를 늘리는 것이 아니라 — **말은 새고 그림은 안 샌다.** 그래서 소유자의 취향도 문장이 아니라 그림으로 전달한다.

특히 **도감 129종(물고기·곤충·동물)은 합격본이 0장**이라, 화풍을 붙잡을 우리 그림이 그 범주에 아예 없다.

## 폴더

`manifest.ts`의 `ArtCategory`와 **같은 아홉**이다. 새 분류를 만들지 않는다 — 갈라진 두 목록은
이 저장소에서 이미 사고를 냈다(`species.ts` ↔ `codex.ts`).

`tree` 나무 · `plant` 풀·꽃 · `ground` 지형 · `water` 물 · `prop` 소품 · `sky` 하늘·천체 ·
`fish` 물고기 · `bug` 곤충 · `animal` 동물

## 쓰는 법

```bash
npm run ref:fetch -- animal --limit 20        # 한 범주 더 받기
npm run ref:fetch -- fish --query "koi carp"  # 질의를 직접 주기
npm run ref:fetch -- --all --limit 14         # 아홉 범주 한 번에
# ── 소유자가 폴더를 열어 마음에 안 드는 것을 지운다 ──
npm run ref:notice                            # 출처 목록 다시 굽기
```

`ref:notice`는 **살아남은 사이드카에서만** 굽는다. 그림을 지우면 그 줄도 사라지고, 짝 잃은 사이드카도 같이 지운다.
`npm run ref:check`는 어긋나면 실패한다.

## 받을 때 거르는 것 (태그를 믿지 않고 **잰다**)

OpenGameArt가 "2D Art"라고 말해도 절반이 벡터 만화체다. 그래서 네 게이트를 통과한 것만 남는다:

| 게이트 | 기준 | 왜 |
|---|---|---|
| 라이선스 | **CC0만**. 검색 필터와 별개로 개별 페이지에서 다시 확인 | 저장소에 남의 저작물을 남기지 않는다 |
| 홍보 배너 | 이름에 preview·banner·logo… 가 있으면 버린다 | 로고와 라이선스 문구가 박혀 있어 그것까지 배운다(케니 팩 실측) |
| 색 수 | ≤ 128색 · 반투명 ≤ 6% | 우리 합격본은 6~8색·반투명 0%, 받은 벡터는 254~13,447색이었다 |
| **논리 해상도** | 긴 변 ÷ 도트 격자 ≤ 160칸 | 색 게이트만으로는 **매끈한 플랫 벡터가 통과한다**(300px 만화 물고기가 색 40·런 8이었다) |

떨어진 것은 이유와 함께 화면에 찍는다 — 조용히 버리면 수확이 적을 때 원인이 게이트인지 소스인지 알 수 없다.

## 규칙

- **발상만 얻는다.** 그리는 어법(도트 굵기·색 단수·외곽선)은 우리 합격본이 정본이다.
- ⚠ **베끼거나 트레이스하지 않는다.** 남의 그림을 옮겨 그린 것은 이 프로젝트에 못 쓴다(ADR-0019).
- 소유자가 직접 넣은 그림은 사이드카(`<파일>.json`)를 손으로 적어야 한다 — 출처를 잃은 그림은 쓸 수 없다.
