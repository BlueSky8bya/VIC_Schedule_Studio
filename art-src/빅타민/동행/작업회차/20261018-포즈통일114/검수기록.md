현재 사용자 요청에 따라 한 담당자가 built-in imagegen 한 번으로 생성하고 한 회차로 확인했다. 별도 아트 검수자·자동 재생성·수정 생성은 사용하지 않았다. 제작자의 관찰이며 독립 전문 검수나 새 사용자 시각 승인을 의미하지 않는다.

## 남은 한계

- 요청한3072×3840보다 작은1122×1402로 반환됐다. 각 실제 주체 폭은 대략100픽셀이며,192셀 기술적 확대는 새로운 세부 묘사를 만들지 않는다. 기본92픽셀 표시용 contact와184픽셀 확대 contact를 구분해 보존했다. 고DPI/큰 확대의 원본 해상도 완전 충족으로 보고하지 않는다.
- 정상 눈 크기는 기존 선택099를 참고했지만, 모든 각도의 동일한 해부학적 지름을 수치 인증한 것은 아니다. 원근·표정·구름으로 눈/귀의 보이는 모양은 달라진다.
- 하품 clean10의 O입 강조는 이번 단일 생성에서 미충족이다. 전체 구름 원화를90° 회전하는 후보는 확대해 보니 O입으로 보인 점이 눈이어서 채택하지 않았다. 추가 생성이나 입 편집으로 보완하지 않았다.
- raw 주변에 황색/적색 프린지와 투명 영역 노이즈가 존재한다. 원본을 보존하고 주체와 가까운 표시를 함께 담는 사각 whole-key crop만 수행했다. 연결된 주체의 고불투명 픽셀 수가 유지됨을 검사했다. 선·얼굴·alpha를 색칠하거나 노이즈를 새로운 선으로 메우지 않았다.
- 최초공개 응원16개는 이번 생성 범위에서 제외해 원래 바이트/소비/제외9·10을 보존했다.92픽셀 contact16개를 직접 확인했으며 귀·체형·일반 눈의 명백한 누락은 보이지 않았지만 새 세계 원화보다 선이 얇고 종이 면이 평평하다. 응원단까지 완전 통일했다고 보고하지 않는다.

## 첨부 작은 갈색 안경 포즈의 출처

기존520셀의 실제 배포 픽셀을 첨부 이미지와 비교하니 회복 마지막4슬롯364–367, `recovery:key3`, 왼쪽 facing이 가장 가까웠다. 기존 동결 메타데이터·실제 공유 painter로 갈색 `sunglasses`를 착용한 결과에서도 삼각형 몸통, 귀, 안경 배치가 맞았다.113 비교표에는 회복 첫 키만 있어 마지막 회복 키가 보이지 않았던 것이다. 이번 새 원화는 이 마지막 회복 구간까지 교체한다. 원본 스크린샷의 정확한 시각/프레임을 알 수 없으므로 네 슬롯 중 하나의 byte-identical 캡처라고 주장하지 않는다.

## 보존과 확인

- 보호된 이전 native/33패킷은 변경하지 않고 새 `unified-114-v1` 형제 파일을 추가했다. 생성 raw·실제 요청 args·원문·crop·파생·관찰을 분리했다.
- 실제 도구 입력4·5는 G: 원본 경로였다. 작업공간에 생성 전 복사하지 않았으며, 생성 때 SHA와 같은 바이트를 사후 보존한 사실을 `레퍼런스보존.json`에 기록했다. 도구 args는 고치지 않았다.
- 실제 사용자 원문/수신 시각·claim·preflight는 현재 요청만 격리한 비공개 provenance에 보존했다. 공개 기록에는 session/log 식별자와 이전 전체 대화를 넣지 않았다.
- 관련8단위파일43검사 통과:114 native/crop,520슬롯/41행,33개 실제 패킷 SHA·alpha, 빈8셀 alpha,32개 입 좌표, 기존098/101/104 역사 원화/파생 증거, selector 연결. 이 숫자는 시각 승인이나 실제 방송PC 검증이 아니다.
- 실행: `node scripts/prepare-companion-unified-poses.mjs`와 `node scripts/prepare-companion-mouth-114.mjs --apply`. 추가 생성은 실행하지 않는다.
