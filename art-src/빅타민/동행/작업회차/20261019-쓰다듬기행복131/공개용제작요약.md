# 131 쓰다듬기 행복 표정 — 공개 제작 요약

요청 범위는 쓰다듬을 때 보이는 row9의 눈·입을 명확히 행복한 표정으로 바꾸는 것이었다. builtin imagegen을 실제 **1회** 호출했고, 그 단일 원본에서 런타임 패킷을 파생했다. 추가 생성, 얼굴 합성, 눈 덧그리기, 선택적 알파 노이즈 삭제는 하지 않았다.

생성자의 전체 열람과 기계 검증을 기록했으며, 전문 미술 검수나 사용자 시각 승인을 뜻하지 않는다. **owner/user artwork approval: NONE.** 실제 표시 크기 비교를 거쳐 런타임 적용을 결정한 것과 그림의 사용자 승인은 구분한다.

## 표정 참고의 범위

실제로 열람한 [Sanrio 공식 폼폼푸린 소개·갤러리](https://www.sanrio.co.jp/characters/pompompurin/)에서 편안하게 닫힌 눈과 행복한 입의 명료함을 참고했다. 열람한 공식 그림은 [포옹 장면](https://www.sanrio.co.jp/wp-content/uploads/2022/06/gallery-pompompurin5-1.png), [목욕 장면](https://www.sanrio.co.jp/wp-content/uploads/2022/06/gallery-pompompurin1.png)이다. 적용 원리는 짝을 이룬 부드러운 웃는 눈의 곡선과 작은 열린 U자 미소다. 타 캐릭터의 몸, 귀, 모자, 색 구성이나 그림을 복제·트레이스하지 않았고, 이 참고 이미지는 생성 입력이나 런타임 자산으로 사용하지 않았다.

프로젝트 캐릭터의 기존 원본과 당시 row9 패킷은 형태 권한으로 따로 사용했다. 외부 표정 참고는 캐릭터 원본 권한이나 사용자 승인 근거가 아니다.

## 파생 방법과 알려진 한계

생성 원본의 `(left=0, top=91, width=2172, height=543)` 정수 영역을 취하고, 같은 비율 `1536/2172`의 Lanczos3 축소로 1536×384를 만들었다. 원본은 별도로 그대로 보존한다. 바깥 crop 영역에는 알파 1/255 픽셀 26개가 있었고 알파 32 이상 픽셀은 없었다. 축소에 따른 재표본화와 알파 양자화는 있으며, 별도 마스크 정리나 특정 픽셀 지우기는 없다.

런타임 WebP는 lossless다. 정규화 결과의 **모든 알파와 알파가 있는 픽셀의 RGB**가 디코드 후 같음을 검사한다. 알파 0인 RGB 204,849채널은 WebP 인코딩에서 정규화됐다. 보이지 않는 RGB까지 완전히 같다고 주장하지 않는다.

중심·발 기준은 가장 큰 알파 200 이상 연결 성분으로 등록한다. 메타데이터 clip은 알파 8 이상 실루엣과 논리 2px 여백으로 측정한다. 낮은 알파 잔점을 이미지에서 삭제하지 않으면서, 잔점이 물리적 몸 경계를 과장하지 않게 한 등록 기준이다.

생성기가 보호 대상 몸·귀·외곽선도 다시 그렸으므로 **기존 외형의 픽셀 단위 보존은 성립하지 않는다.** 원시 생성본을 셀 192 좌표로 환산한 진단에서 알파 200 이상 주 연결 성분 면적은 기존보다 4.80–6.67%, 아래 몸 영역은 1.88–3.57%, 몸 폭은 0.41–2.81% 커졌다. 귀 높이의 정의된 대리 지표는 3.85–7.69% 증가했다. 갈색 경계 픽셀 연속 길이의 중앙값은 3→4.243px였으나, 이는 안티앨리어싱·기울기에 영향을 받는 대리 지표이지 정확한 붓 두께 인증이 아니다. 눈의 전체 가로 범위도 약 2px 작아졌다. 이 편차를 숨기거나 외형 보존 PASS로 바꾸지 않았다.

몸 외곽의 빨강·노랑 잔점 대리 지표 7,746픽셀 중 7,502개는 알파 1, 나머지 244개는 알파 2–7 범위이며 최대 알파는 6이었다. 이 정의에서 알파 8 이상 잔점은 없었다. 생성자의 이러한 계측·관찰은 실제 화면에서의 만족이나 전문 미술 판정을 대신하지 않는다.

## 변경과 보존

- 새 패킷은 `/companion/hd/vitamin-action-09-happiness-131-v1.webp`다. 기존 파일을 덮어쓰지 않았다.
- row9의 전역 프레임 **144–159**, 해당 16개 입·액세서리 기준점을 새 그림에 맞춰 등록했다.
- 나머지 **504프레임과 활성 32패킷**은 변경 전과 같다. 이전 33패킷 파일도 해시 그대로 보존했다. 기존 기본 099 자산도 교체하지 않았다.
- 새 닫힌 눈의 21픽셀 성분이 있는 프레임 9:5에만 정확한 패킷 SHA를 묶은 액세서리 측정 예외를 추가했다. 전역 검출 기준을 완화하지 않았다.

저장소 루트에서 기존 의존성을 설치한 환경으로 실행한다. 아래 명령은 보존 원본에서의 **기계적 파생과 등록**을 확인하며 imagegen을 다시 호출하지 않는다. 생성 자체의 결정적 재현을 주장하지 않는다.

```sh
node scripts/prepare-companion-petting-happiness-131.mjs --check
node scripts/prepare-companion-accessory-anchors.mjs --check
npx vitest run tests/unit/companion-petting-happiness-131.test.ts tests/unit/viewer-companion-mouth.test.ts tests/unit/viewer-companion-sprite-quality.test.ts
```

파생 파일을 다시 쓸 필요가 있을 때는 첫 명령의 `--check`를 빼고, 그 뒤 기존 액세서리 등록 스크립트를 실행한다. 등록 스크립트는 쓰기 전에 세 메타데이터와 입 기준점의 현재 소유 상태를 검증하며, 다른 회차의 변경이 있으면 덮어쓰지 않는다. 각 명령의 성공은 기계 검사 결과이며 전체 제품 빌드·실제 렌더 검증·사용자 시각 승인과 별개다.

## 로컬 근거 분리

실제 사용자 원문 전체 캡처, 해당 요청 문단의 원문, 실제 생성 계약·인수·회차 예산 증빙, 외부 레지스트리 영수증 및 공식 참고 이미지 다운로드는 로컬 근거로 보존했다. 이 공개 색인에 전체 대화, 세션 식별자, 개인 경로 또는 비공개 자료를 옮기지 않았다. 로컬 보존은 공개 커밋 포함이나 사용자 시각 승인을 뜻하지 않으며, 원문·기존 기록을 삭제하거나 고쳐서 경계를 맞추지 않았다.
